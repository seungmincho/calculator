# 26차 계약 — 내용이 보존되는 CSV·Base64 변환

2026-11-17 KST. [코드 조사](../../handoff/2026-11-17-data-conversion-candidates.md)에 따른 기존 도구 개선이다. 25차 검증이 우선이며26차는 부모에 연결하지 않은 순수 로직을 준비 중이다. 새 경로·서버·패키지는 추가하지 않는다.

## A. CSV 여러 줄 셀·문자열 보존·결과 일치

`/json-csv-converter/`에서 CSV 레코드 파싱을 순수 모듈 한 곳으로 모은다. 쉼표/실제 탭/파이프/세미콜론과 큰따옴표를 지원하며, 따옴표 안 CRLF/LF/CR·구분자·`""` 및 셀 앞뒤 공백을 보존한다. 파일 앞 BOM은 읽기에서 한 번만 제거한다. 마지막 레코드 구분자가 빈 행을 하나 더 만들지 않게 하고, 실제 빈 레코드와 빈 셀은 조용히 삭제하지 않는다. 닫히지 않은 따옴표/닫힌 따옴표 뒤 비구분자/열 수 불일치는 위치와 함께 오류로 알린다.

- CSV→JSON은 기본 문자열 보존으로 `00123`, 큰 정수, 공백, 빈 셀을 유지한다. 숫자 변환은 명시 옵션이며 유한한 안전 숫자만 허용하는 규칙과 변환되지 않는 식별자 예를 안내한다. 모든 JS 숫자의 임의 정밀도를 보장하지 않는다. 헤더의 빈 이름/중복은 오류로 알리고 이름을 멋대로 바꾸거나 같은 키를 덮어쓰지 않는다. 헤더 없음은 안정적인 column 키를 사용한다. `__proto__`/`constructor`/`hasOwnProperty`도 일반 데이터 키로 처리한다.
- JSON→CSV의 단일 객체/객체 배열·평탄화/중첩 유지·배열 join/separate를 유지한다. 중첩 유지의 객체/배열은 JSON 문자열로 표기한다. 평탄화 키 충돌은 오류로 알린다. 입력 배열에 객체가 아닌 항목은 명시적으로 거부한다. 모든 행의 키 합집합을 열로 사용하고, 헤더 유무와 무관하게 표/통계/반출이 같은 확정 결과를 사용한다.
- 입력은 UTF-8 크기 2MiB, 최대10,000 데이터 행·200열·200,000셀, JSON 깊이20, 출력8MiB를 초기 상한으로 잡는다. 한도 초과는 원문 보존과 명확한 오류로 처리하며 잘라서 성공 표시하지 않는다. 대형 경계의 실제 UI 응답성을 측정하고 필요할 때만 Worker로 분리한다. 현재 100MB/성능 안내는 실제 범위로 수정한다.
- EUC-KR/UTF-8 선택은 파일 읽기에 실제 적용하고 라벨을 파일 읽기 인코딩으로 바꾼다. 출력은 UTF-8이며 필요하면 명시 BOM 옵션만 제공한다. EUC-KR 출력을 구현했다고 표시하지 않는다. 붙여넣기 문자열은 이 설정으로 재인코딩하지 않는다.
- 파일 읽기는 새 선택/직접 편집/탭·인코딩 변경/언마운트 이후 이전 응답을 무효화한다. 오류/취소가 현재 원문을 지우지 않게 한다. 입력/옵션을 바꾸면 기존 확정 결과에 변경됨을 표시하거나 비활성화해 다른 형식으로 잘못 반출하지 않게 한다. 클릭 당시 결과의 문자열·형식·통계·파일명이 한 묶음이다.
- 결과 복사는 실제 성공만 표시하고 실패 시 수동 선택/재시도를 제공한다. 늦은 복사 응답은 현재 결과를 덮지 않는다. 데이터는 메모리에만 두며 원문/결과를 URL·저장소·로그에 추가하지 않는다. 수정 UI는 디자인 토큰·16px 입력·44px 조작·모바일1열을 적용한다.

검증: RFC 예제와 다국어/공백/여러 줄/빈칸/인용부호/헤더 없는 표, 식별자와 숫자 옵션, 중첩·키 충돌·특수 키·한도, 실제 UTF-8/EUC-KR 파일, 읽기 경합, 미리보기·통계·전체 다운로드 바이트 일치, 실패 복사·KO/EN·320px. 브라우저/Node의 독립 파싱으로 실제 파일을 다시 읽는다.

### 독립 읽기 검토 후 확정한 세부

team의 코드 검토로 모호했던 정책을 다음과 같이 고정한다. 새 기능 범위나 Worker를 추가하는 요청은 아니다.

- 숫자 옵션의 문법은 `^-?(?:0|[1-9]\d*)(?:\.\d+)?(?:[eE][+-]?\d+)?$`다. `00123`, `+3`, `.5`, `1.`, 앞뒤 공백이 있는 값은 문자열이다. `1e3`은1000, `-2.5`는-2.5로 변환할 수 있다. 결과가 유한하고 절댓값이 MAX_SAFE_INTEGER 이하이며, 정수 결과면 safe integer여야 한다. 음의0으로 변환되는 값은 문자열로 둔다. 소수는 JS Number의 정밀도 한계가 있음을 옵션 옆에서 설명하고 기본 문자열 보존을 권장한다.
- 빈 문자열 입력은 오류다. 헤더 없음에서 `""`는 빈 셀1개, 개행1개도 빈 레코드1개다. `a\n`은1행, `a\n\n`은 두 번째 빈 레코드를 포함한2행이다. 두 열 헤더 뒤 빈 레코드는 열 수 불일치 오류다. 헤더만 있고 마지막 개행이 있거나 없는 입력은 데이터0행의 `[]`이며 헤더 정보는 유지한다. 헤더의 원문 공백은 보존하되 `trim()` 결과가 빈 이름은 거부한다. 중복은 보존된 이름의 정확한 대소문자 구분으로 판정한다.
- 파일은 원래 바이트 크기와 디코딩 후 UTF-8 크기를 둘 다2MiB로 검사한다. 잘못된 인코딩 바이트를 대체문자로 조용히 받아들이지 않도록 fatal decoder를 사용하고 이전 입력을 유지한다. BOM은 디코더/후처리에서 중복 제거하지 않는다. 직접 붙여넣은 원문의 공백은 읽기와 별개로 보존한다. TSV select는 문자 두 개 `\\t`가 아니라 실제 탭값을 사용한다.
- 표는 확정 rows/cells를 직접 사용한다. no-header 첫행/나중행 새키/빈셀을 잃지 않는다. 모바일의 긴 셀도 선택·펼침 등으로 전체 내용을 확인할 수 있게 하며 hover title만을 유일한 확인 방법으로 삼지 않는다.
- 배열 join의 원소가 객체/배열이면 JSON 문자열을 사용하고 null은 빈 문자열, 빈 배열은 빈 셀로 둔다. separate의 빈 배열/중첩 빈 객체는 원래 키의 `[]`/`{}` 문자열 셀로 남긴다. 루트 빈 객체/빈 객체 배열처럼 열이 전혀 없는 JSON은 오류다. join/flatten 결과를 원본 JSON의 완전한 가역 변환이라고 설명하지 않는다.
- BOM 옵션은 CSV 출력에만 적용한다. JSON 출력은 옵션이 남아 있어도 BOM 없이 UTF-8로 만들고 바로 JSON.parse 가능한 내용을 제공한다. UI도 CSV 출력일 때만 ‘CSV 파일에 BOM 추가’로 표시한다. [RFC 8259 §8.1](https://www.rfc-editor.org/info/rfc8259/)의 JSON 상호운용성 원칙을 확인한 뒤 정한 도구 정책이다. 붙여넣은 원문이나 셀 안의 U+FEFF를 임의 제거하는 정책과는 구분한다.
- 평탄화 중 긴 공통 경로가 많은 열로 복제될 수 있으므로 확정 표를 만들기 전 중간 key/value UTF-8 합계도8MiB로 제한한다. 행별 map을 무제한 만든 뒤 마지막 직렬화에서만 거부하지 않는다. 헤더 출력 해제 상태에서도 미리보기용 키는 만들어지므로 이 한도는 유지한다. 원문은 보존하고 잘라서 성공 처리하지 않는다. 실제 경계 응답성은 부모 연결 뒤 확인한다.
- JSON→CSV에서도 파싱된 정수가 안전한 정수 범위 밖이면 반올림된 값을 성공 결과로 내보내지 않고 오류로 알린다. 큰 식별자는 JSON에서 따옴표로 감싼 문자열로 넣도록 안내한다. 문자열로 된 큰 정수는 그대로 보존한다. 유한 소수는 일반 JavaScript Number 정밀도를 사용하며 임의 정밀도 JSON 변환을 약속하지 않는다. 별도 JSON 파서를 새로 만드는 범위는 아니다.

## B. Base64URL·텍스트/파일 변환 정리

`/base64-converter/`의 표준 Base64 기본값과 기존 UTF-8 텍스트/파일 입력을 보존하면서 Base64URL 선택을 추가한다. 파일→바이트 인코딩과 텍스트→UTF-8 인코딩을 구분한다. 파일 업로드 뒤 변환을 다시 눌러도 data URL 문자열을 중복 인코딩하지 않는다. 디코딩 모드의 .txt/.base64 업로드는 텍스트 내용을 읽는다.

- UTF-8은 TextEncoder/TextDecoder를 사용하고 잘못된 UTF-8은 텍스트 성공으로 표시하지 않는다. 바이트 결과를 받았으면 파일 다운로드가 가능하며 텍스트 미리보기가 불가능함을 설명한다. 입력이 공백뿐인 텍스트도 의도한 바이트로 인코딩하고 빈 입력은 명시 초기 상태로 구분한다.
- 표준/Base64URL 알파벳을 분리하고 URL용 패딩 포함/생략 정책을 표시한다. 디코딩의 ASCII 공백 허용 여부·패딩 생략 허용 범위를 문서화하고 혼합 알파벳/중간 패딩/불가능한 길이/비정규 마지막 비트를 거부한다. data URL은 `;base64,` wrapper를 별도로 파싱하며 payload의 규칙과 MIME 표시를 혼동하지 않는다.
- 텍스트·파일·디코딩 바이트 결과를 번역 안내 문자열과 분리한 명시적 상태로 둔다. 파일의 raw Base64/data URL 복사 대상을 명확히 구분한다. 기존 이미지 미리보기는 확인된 PNG/JPEG/GIF/WebP 바이트와 실제 이미지 로드 성공에만 사용한다. SVG/HTML은 실행/inline 표시하지 않고 일반 파일로 다룬다. 상한4MiB 바이트·입력 문자열6MiB를 미리 검사하고 파일명은 안전한 다운로드 이름으로 정리한다.
- 신규 입력/모드/형식/초기화/언마운트는 대기 중 읽기와 복사 세대를 무효화한다. 파일 오류/취소는 현재 입력을 보존한다. 결과 편집 후에는 이전 결과의 기준을 표시하거나 무효화하고, 교환은 변환 가능한 텍스트 결과에만 제공한다. 바이너리 안내 문장이 다음 입력으로 복사되지 않게 한다.
- 미리보기는 네이티브 이미지 decode 전 기존 검증된 raster 헤더 검사로16,777,216픽셀 이하인지 확인한다.4MiB 파일 상한만으로 decode 메모리까지 제한된다고 보지 않는다. 너무 큰 이미지나 헤더를 읽을 수 없는 이미지는 미리보기만 생략하고, 유효한 Base64 변환/원본 바이트 다운로드는 유지한다. 기존 QR 헤더 검사를 동작 변경 없이 재사용할 수 있다.
- Clipboard 성공/실패/수동 선택/재시도, 임시 URL 회수, 이전 이미지 해제, KO/EN·모바일 디자인 토큰을 적용한다. 원문·파일·결과는 URL·기기 기록·외부 요청에 넣지 않는다. 암호화나 무결성 검증 기능이라고 설명하지 않는다.

검증: RFC 4648 벡터, 한글/이모지/공백/잘못된 UTF-8, 표준·URL 알파벳/패딩 오류, 실제 바이너리 왕복·data URL·텍스트 파일 읽기·비이미지 MIME/서명, 용량 경계, 파일/복사 경합·교환·locale 보존, 실제 다운로드와 원본 바이트 동일성·320px. 기존 이미지 미리보기와 표준 변환 회귀를 확인한다.

## 분업과 완료

각 제품 담당이 코드/ko·en 조각/도메인 검사와 부모 이벤트 검사를 맡는다. 통합 담당만 canonical 번역·메타·메뉴 날짜·생성물·마스터 상태를 고친다. 독립 검토와 단일 Chrome 실제 파일/모바일 검증 후 모든 TS 작성 중지·Chrome 종료·메모리 확인·전체 타입 검사를 수행한다. 빌드·배포·커밋·푸시는 실행하지 않는다.
