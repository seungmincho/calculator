# 택시·택배 검색 표기 및 모바일 검증

- 생성일: 2026-10-25
- 대상: 로컬 Next.js 개발 서버의 `/taxi-fare/`, `/shipping-calculator/`
- 도구: Playwright Chromium, TypeScript, ESLint, 번역 검사
- 사용자 승인 범위: 기존 두 도구 개선 및 모바일 사용성 점검. 빌드·배포는 수행하지 않는다.

## S01: 검색 표기
두 페이지를 열고 title, description, OG, Twitter, JSON-LD, h1을 읽는다. 택시는 일반 요금 계산을 먼저 설명하고, 택배는 '택배비 계산기' 명칭과 요금 비교 목적이 일관되어야 한다. canonical은 기존 주소를 유지한다.

## S02: 화면 폭·첫 화면 결과
320, 375, 390, 768, 1280px에서 각 페이지를 연다. 페이지 전체 가로 스크롤이 없어야 하고, 모바일 첫 화면에 결과 바로가기가 보여야 한다. 비교 표의 스크롤은 표 안에 한정한다. 모바일 다크 모드와 영어 내비게이션 설정에서도 확인한다. 현재 공통 도구 번역 레지스트리는 한국어 고정이므로 영어 도구 UI 지원 여부는 이 작업의 검증 범위가 아니다.

## S03: 택시 입력·할증·결과 왕복
거리 프리셋을 누르고 탑승 시각과 시외할증을 바꾼다. 예상 금액과 URL이 바뀌어야 한다. 결과 바로가기 → 입력 수정 → 초기화가 가능해야 한다. 입력과 주요 선택 버튼은 모바일에서 최소 44px 높이여야 한다.

## S04: 택배 입력·비교·결과 왕복
상자 프리셋, 무게, 도착지, 택배 종류를 바꾼다. 요금·접수 가능 여부가 갱신되고, 결과 바로가기 → 입력 수정 → 초기화가 가능해야 한다. 무게·크기는 소수점 숫자 키패드를 요청한다.

## S05: 배송 가능한 업체가 없는 경우
무게를 100kg으로 바꾼다. 가능한 업체가 없다는 안내가 표시되어야 하고, 결과 영역과 입력으로 돌아오는 링크가 유지되어야 한다. 긴 불가 사유가 화면 밖으로 넘치지 않아야 한다.

## S06: 공유 URL 복원
각 페이지에서 입력을 바꾸고 생성된 URL을 새로 연다. 입력·선택 상태와 결과가 재현되어야 한다.

## S07: 기존 기능·정적 검사
기존 택시·택배 계산 검사를 실행한다. 타입 검사, 변경 코드 ESLint, 번역 생성본 일치 및 namespace audit를 확인한다. 브라우저 pageerror와 누락된 번역이 없어야 한다.
