# D-day 캘린더 내보내기 구현·검증 메모

2026-11-16. 기존 D-day 화면에서 현재 일정 1개 또는 선택한 저장 일정 최대 100개를 명시적으로 `.ics` 다운로드한다. 계정 연결·외부 캘린더 등록·초대·반복·알람은 추가하지 않는다.

## 확인한 공식 규격

RFC Editor의 RFC 5545 원문을 직접 확인했다. 다음은 요약이며 원문을 복사하지 않았다.

- 줄 구분은 CRLF이며 75바이트를 넘는 내용 줄은 공백으로 이어 접는다. UTF-8 문자 중간을 끊지 않는다. [§3.1 Content Lines](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.1)
- `DATE`는 구분자 없는 네 자리 연도·월·일이다. 하루 일정의 종료는 다음 날을 쓰는 배타적 경계다. [§3.3.4 Date](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.3.4), [§3.6.1 Event](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.6.1)
- 제목의 역슬래시·쉼표·세미콜론·줄바꿈은 TEXT 규칙으로 이스케이프하고 콜론은 그대로 둔다. [§3.3.11 Text](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.3.11)
- 이벤트에는 지속 식별자 UID와 UTC 형식 DTSTAMP가 필요하다. METHOD가 없는 경우 DTSTAMP는 캘린더 정보의 최종 변경 시각을 나타낸다. [§3.8.4.7 UID](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.4.7), [§3.8.7.2 DTSTAMP](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.7.2)

## 구현 결정

- `DTSTART;VALUE=DATE`는 선택 날짜, `DTEND;VALUE=DATE`는 기존 `dday.ts`의 `addDays(date, 1)`로 계산한다. 시간대 변환 없이 종일 날짜 자체를 유지한다.
- 기존 날짜 검증 함수는 `Date.UTC`의 0~99년 처리 때문에 해당 연도를 지원하지 않는다. 이 기능도 같은 검증 함수를 재사용하여 **0100-01-01~9999-12-30**을 지원한다. 9999-12-31은 다음 날을 네 자리 연도로 나타낼 수 없어 전체 파일 생성을 거부한다. 날짜를 임의로 보정하거나 해당 일정만 제외하지 않는다.
- 제목은 최대 2,000자, 제어 문자·깨진 UTF-16은 거부한다. 유효한 줄바꿈은 이스케이프한다. 본문 속 `BEGIN:VEVENT` 같은 문자열은 별도 속성이나 이벤트가 되지 않는다.
- UTF-8 코드포인트 단위로 접으며 다음 물리 행의 선행 공백도 75바이트에 포함한다. 마지막 행도 CRLF로 끝난다.
- 현재 저장 UI는 기존 항목의 제목·날짜를 직접 수정하지 않는다. UID는 구분자 충돌 없는 JSON 형태의 버전·출처·저장 ID·제목·날짜를 SHA-256 해시하여 도메인을 붙인다. 같은 저장 항목의 반복 내보내기는 UID가 같고, 서로 다른 저장 ID는 구분된다. 현재 D-day가 기존 저장 항목과 일치하면 그 ID를 사용한다. 새 저장 ID는 UUID이며 기존 timestamp ID도 보존한다.
- DTSTAMP는 내보내기용 VEVENT 스냅샷을 구성한 UTC 시각이다. 과거 저장 시각이 없는 기존 목록에서 과거 수정 시각을 추정하지 않는다. 캘린더 앱별 재가져오기 중복/갱신 동작은 보장하지 않고 화면에서 확인하도록 안내한다.
- 한 파일의 일부만 성공시키지 않는다. 잘못된 날짜·제목·중복·사라진 선택·100개 초과가 있으면 파일 전체를 만들지 않는다. 다운로드 실패도 성공 표시로 바꾸지 않는다.

## 저장 목록 보호

기존 `dday-saved` 키와 배열 형식은 유지한다. 배열·모든 항목·ID 유일성·제목·날짜·고정 여부를 검증하며 잘못된 항목만 필터링해서 덮어쓰지 않는다. 1,000개를 넘는 기존 목록은 제한을 벗어난 데이터로 보존하고 쓰기를 중단한다. 내보내기 선택 상한은 별도로 100개다.

쓰기는 Web Locks가 있으면 독점 잠금 안에서 관찰한 원문과 비교하고 저장 후 재조회한다. 미지원 환경에서는 원문 비교와 재조회로 오래된 탭 쓰기를 막지만 완전히 동시에 실행되는 쓰기의 원자성까지 보장하지 않는다. 저장 공간·접근 거부·손상·다른 탭 변경은 화면에 알린다. 저장 목록 다시 읽기는 현재 D-day 입력을 바꾸지 않는다.

기념일 저장 값이 JSON `null`인 경우에도 초기화가 중단되지 않도록 해당 값만 기본 객체로 처리했다. 기존 계산 유틸은 변경하지 않았다.
