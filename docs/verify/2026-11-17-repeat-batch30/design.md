# 30차 집중 타이머 — 시간 소유권과 복귀 설계

2026-11-17 KST. root 승인 정책을 반영한 설계 계약이다. 27차 이후 미연결 준비를 마쳤고 CSV·29차 체크포인트 뒤 두 시계/완료 영수증 보완과 부모 연결이 승인됐다. 최종 구현·자체48그룹과 독립13그룹 결과는 implementation.md와 independent-review.md에 기록한다. 통계/목표 API·스키마는 유지하며 canonical 번역, Chrome·전체 타입 검사·빌드는 각 담당자에게 맡긴다.

## 유지할 현재 동작

- 집중 완료만 `completedRounds`, 현재 선택한 할 일의 완료 횟수, 해당 관찰 시점의 브라우저 로컬 날짜 통계를 증가시킨다. 할 일 선택은 시작 시 고정하지 않으며 `activeTaskId`는 계속 방문 중 상태다.
- 휴식 완료·건너뛰기에는 집중 실적을 더하지 않는다. 과거 저장된 통계에서 완료와 건너뛰기를 구별할 수 없으므로 정상 기존 통계는 수정하지 않는다.
- 집중 완료 횟수가 긴 휴식 간격의 배수이면 긴 휴식, 나머지는 짧은 휴식이다. 집중 건너뛰기는 짧은 휴식, 휴식 완료/건너뛰기는 집중이다. 긴 휴식 후 회차는 1, 짧은 휴식 후에는 현재 회차+1이다.
- 현재 단계 리셋은 누적 횟수를 유지한다. 전체 리셋·설정 모달 적용은 집중/1회차/누적0/정지로 돌아가며 할 일·일별 통계는 유지한다. 상단 소리/알림 토글은 타이머를 리셋하지 않는다.
- 정상 완료와 일반 건너뛰기의 소리·화면 강조는 유지하며 건너뛰기 알림은 보내지 않는다. 알림 권한 요청은 기존 명시 버튼에서만 수행한다. 목표 변경·7일 CSV는 타이머를 건드리지 않는다.

## 시계와 단계 전이

`PomodoroClock={wallMs,monotonicMs}`를 주입한다. 같은 방문의 실행 시간은 시작/재개 시 저장한 남은 밀리초와 단조 시각의 차이로 계산한다. tick은 이 값을 표시할 뿐 반올림된 초를 누적 차감하지 않는다. 표시만 `ceil(remainingMs / 1000)`한다. 일시정지는 마지막 tick 이후 소수 밀리초까지 확정하고 재개는 그 남은 값에서 새 기준을 만든다.

정상적으로 두 시계가 함께 진행할 때는 단조 기준을 사용한다. 다만 단조 시계만 믿으면 일부 OS의 절전에서 남은 시간이 되돌아오는 회귀가 생길 수 있다. MDN은 명세상 절전 중 진행 요구와 실제 OS별 구현 차이를 구분하며, Windows 이외 브라우저에서 절전 중 진행이 멈추는 관련 버그를 연결한다. 따라서 절전인지 사용자의 시각 변경인지 추정하지 않고 두 시계의 큰 불일치를 안전 중단으로 처리한다. 아래 추가 보완 계약은 root가 승인했으며 현재 구현과 제어 포트 검사에 반영했다. [MDN: Ticking during sleep](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now#ticking_during_sleep)

각 단계는 `phaseId`, 각 실행/취소는 세대를 가진다. 오래된 interval·복귀·완료 승인 callback은 양쪽을 확인한다. 완료 부수효과는 React state updater/effect에 두지 않는다. 단계 소유자가 한 번 전이한 뒤 독립 이벤트를 발행한다. 다음 단계 자동 시작은 완료 소유권을 승인한 시각을 사용한다. 이전 단계 관찰 시각과 긴 잠금 대기가 끝난 승인 시각을 혼용하지 않으며, 저장 checkpoint와 실행 baseline도 같은 시각이어야 한다. 밀린 여러 단계를 순회하지 않는다.

경계의 명시 의도를 다음과 같이 처리한다.

| 동작 | 아직 소비되지 않은 만료가 있을 때 |
|---|---|
| tick/복귀/일시정지 | 현재 단계 완료 승인 1회만 시도한다. 일시정지로 발견한 완료는 다음 단계를 자동 시작하지 않는다. |
| 건너뛰기/리셋/설정 적용 | 이전 미처리 완료를 취소한다. 건너뛰기는 skip 전이이며 실적0, 리셋은 해당 초기 상태다. |
| 이전 callback/중복 시작 | 현재 세대가 아니면 무시한다. 이미 실행 중인 시작은 아무것도 바꾸지 않는다. |
| 다른 탭 timer 변경 | 완료를 승인하지 않고 남은 시간만 확정해 정지한다. 명시 재조회 전 자동 채택/덮어쓰기하지 않는다. |

완료 승인용 선택적 비동기 포트는 현재 저장 raw를 timer 전용 잠금 안에서 재확인할 수 있게 한다. 대기 중 건너뛰기/리셋/입력 교체/언마운트는 AbortController와 세대로 무효화한다. 잠금 안에서 통계나 할 일 잠금을 다시 요청하지 않는다. timer 승인 종료 후 기존 통계 API와 별도 할 일 저장을 호출한다. 준비 당시 단순 `allow` 응답은 아래 startedAt 영수증 계약으로 보완했다.

### 추가 보완 계약 — CSV·29차 체크포인트 뒤 적용 완료

2026-11-17 KST root의 모바일 절전·완료 잠금 검토에 따라 아래 보완 범위를 승인받았다. CSV·29차 타입 PASS 신호 이후 이 경계를 먼저 보완·검사하고 부모 연결까지 완료했다. 기존28그룹 PASS는 보완 전 준비 상태의 증거이며, 이 후속 결과와 구분한다. 현재 결과는 implementation.md를 따른다.

**1. 진행 중 두 시계 불일치**

- 시작/재개 기준에 `{remainingMs,wallMs,monotonicMs}`를 함께 보관한다. 매 tick/복귀/일시정지에서 각각의 누적 진행량을 비교한다. 기준은 매 tick 이동시키지 않으므로 작은 누적 차이가 계속 숨지 않는다.
- 안전 중단 임계값은 `abs(wallElapsed - monoElapsed) > 2000ms`다. 2초는 정상 샘플 오차와 큰 차이를 나누기 위한 제품 정책이며, 절전을 진단하거나 OS의 정확도를 보장하는 값이 아니다. 단조 시각 자체의 역행/불가능한 값은 임계값과 별도로 중단한다.
- 큰 차이가 있으면 `min(직전 확인한 남은 값, max(0,기준 남은 값 - max(0,wallElapsed)), max(0,기준 남은 값 - max(0,monoElapsed)))`를 택한다. 유효하지 않은 시계의 후보는 제외하며, 마지막 확인 값보다 시간을 늘리지 않는다.
- 보수적 남은 값이 양수이면 일시정지와 시간 기준 변경 안내를 표시한다. 명시 재개가 새 wall/mono 기준을 만든다. 완료/통계/할 일/알림/음향을 실행하지 않는다.
- 0이면 `clockGapExpired` 같은 별도 안내 상태로 정지한다. 절전이나 부재를 사실로 단정하는 문구를 쓰지 않는다. 새 방문 만료와 동일하게 집계0/명시 다음 단계 skip 전이를 적용하고, 일반 시작 버튼으로 이전 단계를 완료시키지 않는다.
- 두 시계가 함께 크게 진행한 정상 늦은 관찰은 기존 현재 단계1회 완료 정책을 유지한다. 두 시계가 모두 멈추거나 같은 크기로 잘못 진행하는 경우까지 판별한다고 주장하지 않는다. 벽시계 rollback으로 남은 시간을 추가하지 않는다.

**2. 완료 승인 이후의 새 단계 기준**

- 승인 포트의 성공값을 단순 문자열에서 `{decision:'allow',startedAt:PomodoroClock}`로 바꾼다. conflict/unconfirmed는 시작 시각이 없는 실패 결과다.
- timer 잠금을 실제로 얻은 뒤 현재 generation/signal/raw를 확인하고, 다음 상태를 쓰기 직전에 시계를 한 번 읽는다. 그 동일 `startedAt.wallMs`를 다음 타이머의 `lastTickTime`으로 저장하고, `startedAt` 전체를 성공 영수증으로 반환한다. 관찰 당시 `proposal.observedAt`은 이전 단계 통계의 로컬 날짜 귀속용이며 다음 단계 시작점으로 사용하지 않는다.
- controller는 영수증의 `startedAt.monotonicMs`를 실행 기준으로 채택하고 Promise가 전달된 현재 시각까지의 경과만큼 남은 값을 계산한다. Promise 수신 시각으로 baseline을 새로 만들거나 전체 시간을 다시 주지 않는다. 저장 직후 새로고침해 복원한 값과 화면 실행 값이 같은 시작점에서 나온다.
- 영수증 전달이 다음 단계 전체 시간보다도 늦으면 이전 단계 완료 이벤트는1회만 유지하고, 미관찰 다음 단계는 무집계 만료 안내로 멈춘다. 반복 완료 루프나 추가 알림을 만들지 않는다. 전달 중 시계 불일치도 위 중단 정책을 사용한다.
- 취소된 세대의 영수증은 기존대로 무시한다. readback 확인 불가에는 성공 영수증을 주지 않는다. 저장 API의 wallMs 인자는 그대로 사용할 수 있어 별도 새 키/새 schema/중첩 잠금이 필요 없다.

**최소 수정 범위와 추가 검사**

CSV·29차 체크포인트 이후 `pomodoroSession.ts` 순수 시계 판정, `lib/pomodoro/session.ts` 기준/승인 영수증, 기존 session 검사와 KO/EN 조각을 먼저 보완했다. 이후 승인된 부모 연결을 진행했으며 통계 schema는 유지했다. 일반 parser/CAS13그룹은 무관하게 반복하지 않았다.

추가 검사는 (a) wall만 진행해 만료, (b) wall만 진행했지만 남음, (c) 벽시계 rollback과 시간 증가0, (d) 임계값 경계/정상 동행, (e) 긴 lock 대기 후 실제 저장 `lastTickTime`과 controller 기준 일치, (f) 영수증 전달 지연이 한 단계를 넘은 경우/취소된 늦은 영수증이다. 기존 ‘live 벽시계는 무조건 무시’ 검사는 새 안전 중단 정책에 맞춰 영향 범위만 변경한다. 실제 OS 절전 검증과 제어 포트 검증은 구분한다.

## 새 방문 복원

저장된 실행 상태의 남은 시간에서 `now.wallMs - lastTickTime`을 빼며 음수 경과는 시간을 추가하지 않고 정지/시계 변경 안내로 처리한다. 저장 시각은 유효한 정수 Date 범위만 허용한다. 같은 방문에서 사용한 단조 시각은 저장하거나 다른 방문에서 재사용하지 않는다.

- 남은 값이 양수인 실행 상태: 기존처럼 자동 복귀한다. 복원 읽기 자체는 저장하지 않는다.
- 만료됐거나 legacy의 정지한 0초 상태: 정지한 `restoredExpired` 상태로 표시한다. 완료 횟수·할 일·통계·소리·알림은 모두 0회다.
- 명시 ‘다음 단계 시작’: 기존 skip 전이를 사용한다. 집중이었다면 짧은 휴식이며 완료 횟수는 증가하지 않는다. 새 단계는 버튼의 의도대로 시작한다. 만료된 이전 단계의 소리·알림은 내지 않는다.
- 같은 방문에서 뒤늦게 만료를 관찰: 현재 단계 하나만 관찰 시점 로컬 날짜에 기록한다. 과거 날짜에 소급 추가하거나 실제 작업 시간을 추정하지 않는다.

## 저장 형식과 원본 보호

기존 키 `pomodoro-settings`, `pomodoro-tasks`, `pomodoro-timer-state`를 유지한다. 새 키나 별도 저장 동의/버전 버튼을 추가하지 않는다. settings는 기존 객체, tasks는 기존 배열 형식을 유지한다. timer는 기존 필드를 포함하는 호환 객체에 `version:1`, `revision`, `phaseId`, `remainingMs`만 더한다. 기존 `timeLeft`는 표시 초(밀리초 올림), `lastTickTime`은 체크포인트의 벽시각이다. 정상 legacy는 새 필드가 없는 기존 객체로 엄격하게 읽는다.

읽기만으로 쓰지 않는다. 최초 정상 체크포인트(start/pause/전환/visibility/pagehide 등)에서는 정상 legacy의 expected raw를 CAS로 확인한 뒤 호환 객체로 쓸 수 있다. 이는 기존 자동 저장 범위이며 별도 동의 흐름을 만들지 않는다. 미래 버전·잘못된 구조·원문 초과·접근 차단은 해당 키의 쓰기만 막고 메모리 내 타이머 사용은 유지한다.

| 검증 | 정책 |
|---|---|
| 설정 | 정확한 8필드. 집중1–120/짧은 휴식1–30/긴 휴식1–60분, 간격2–10, 음량0–100 정수, 3개 boolean. |
| 할 일 | 정확한 5필드, 중복되지 않는 비어 있지 않은 ID, 원문 문자열, boolean, estimate 양의 safe integer, 완료 횟수0 이상 safe integer. 기존 handler가99 초과 estimate를 저장할 수 있어 읽기에서99로 자르거나 거부하지 않는다. |
| 타이머 | 정확한 legacy 또는 version1 필드, 지원 phase, 남은 값0–해당 단계 시간, 양의 회차와 음수가 아닌 safe 누적 값, 유효한 저장 시각, 설정 재검증. 현재 회차를 긴 휴식 간격으로 제한하지 않는다. |
| 원문 한도 | 설정/타이머64KiB, 할 일2MiB UTF-8. 초과 파일은 잘라 읽거나 덮지 않고 용량 오류로 원본을 보존한다. 텍스트는 trim/coerce하지 않는다. |

각 키는 읽은 raw를 보관한다. 쓰기는 해당 키 Web Lock(지원 시) → 현재 raw 비교 → 기존/새 값 엄격 검증 → setItem → readback 순서다. 대기 중 취소·입력 변경은 쓰기 직전에도 확인한다. 같은 키 lock을 중첩 호출하지 않는다. 미지원 환경의 CAS/readback은 완전한 동시쓰기 원자성을 보장하지 않는다.

quota/setItem throw는 저장 실패로, setItem 후 읽기 실패/불일치는 이미 저장됐을 수 있는 ‘확인 불가’로 구분한다. 확인 불가에 이전 원문으로 rollback하지 않는다. 실패 입력은 유지하고 명시 재조회로 실제 상태를 확인한다. 손상된 원문을 버리는 별도 확인 동작만 strict 검사 예외이며, 이 경우에도 확인 시 읽은 raw와 현재 raw가 같아야 한다. 접근 불가로 raw를 읽지 못한 키는 맹목적으로 지우지 않는다.

timer는 매초 쓰지 않는다. 시작/일시정지/재개/전환/리셋/설정 적용과 visibility/pagehide 체크포인트에만 저장한다. 종료 시 비동기 잠금/저장 완료는 브라우저가 보장하지 않으므로 표시를 성공으로 단정하지 않는다. settings/tasks는 사용자 변경 시 저장하며 최초 기본값 렌더로 기존 손상 원문을 덮지 않는다.

`pomodoro-daily-stats`와 목표 키의 API·schema는 그대로다. timer/할 일/통계는 서로 다른 localStorage 키라 전체를 원자 트랜잭션으로 만들 수 없다. 현재 방문의 단계 부수효과 중복 방지와 crash 이후 세 키가 모두 저장됐다는 내구성 보장을 구분한다. 불확실한 완료를 새 방문에서 재실행해 누락을 자동 보충하지 않는다.

## 준비 파일과 연결 경계

- `src/utils/pomodoroSession.ts`: 공유 타입·설정 검증·phase 시간·밀리초 계산·복원·다음 단계 순수 함수.
- `src/utils/pomodoroPersistence.ts`: 세 키 strict parser, 호환 timer 직렬화, CAS/readback/명시 원본 폐기, 취소 가능한 키별 lock.
- `src/lib/pomodoro/session.ts`: 단일 실행 소유자, 주입 시계/interval/복귀 포트, 완료 승인/세대/취소와 이벤트. DOM·저장·소리·알림을 직접 사용하지 않는다.
- `scripts/check-pomodoro-session.ts`, `scripts/check-pomodoro-persistence.ts`: 독립 시계 oracle와 legacy/원문/CAS 경계. 실제 브라우저/OS 성질과 구분한다.
- `translations-pomodoro.json`: `pomodoroTimer.reliability` KO/EN 동일 구조 조각. 부모 연결 때 실제 사용하는 키를 공용 담당에게 전달한다.
- 이후 최소 부모 연결: 기존 계산/차트/목표/알림 UI를 두고 시간 state/완료 effect와 세 키 cast helpers만 대체한다. 별도 storage 안내 UI가 필요하면 작은 자식으로 나눈다.

## 실행 검사 계약

1. 1.4초 반복 tick·여러 번0.5초 미만 pause/resume를 독립 총 실행 밀리초 oracle와 비교. 벽시계 변경/단조 역행도 분리한다.
2. 큰 지연/자동 시작은 현재 단계1회만 완료하고 다음 단계 전체 시간 유지. pause/skip/reset/설정 적용과 대기 중 완료 승인, 이전 callback·언마운트는 부수효과 횟수로 확인한다.
3. 정상 legacy 원문·한글/공백/큰 estimate·빈 tasks 보존, 미래 버전/unknown/null/범위/중복ID/용량 손상 차단, 읽기0쓰기, 정상 checkpoint 호환 저장.
4. CAS 충돌/setItem quota/readback 확인 불가/대기 취소/두 소비자 경합. 원본 폐기 확인 뒤 raw가 바뀌면 거부.
5. 실제 부모 연결 뒤 activeTask/관찰일자/통계1회, skip·복귀 만료0회, 목표/CSV 비간섭, 일반 알림/음향은 fake 포트, KO/EN·320px를 검증한다. 실제 부모 자체/독립 검사는 완료했으며 실제 브라우저와 목표 CSV·320px 확인은 전담 검증 결과를 따른다.
