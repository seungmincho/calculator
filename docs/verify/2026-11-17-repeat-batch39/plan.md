# 39차 실행 계약 — 정규식 처리 중 멈춤 방지

> 완료 상태(2026-11-17): 최종 native8/8과08:08:20 KST 전체2GB 타입 exit0·진단0을 확인했다. 구현·독립·공용 검사와 한계는 [최종 보고서](report.md)에 기록했다. 빌드·배포·커밋·푸시 미실행.

## 사용자가 얻는 변화

정규식이 오래 걸려도 입력과 취소 버튼을 사용할 수 있게 한다. 빈 문자열을 찾는 `^`, `$`, `a*`, lookahead가 끝나지 않는 문제를 고친다. 추출·행 필터·치환, 프리셋, 저장된 이력은 유지한다. 결과가 중단되거나 너무 크면 일부를 완성 결과로 표시하지 않는다.

## 확인한 근거

- `check-regex-baseline.mjs --record`: 실제 `RegexExtractor.tsx`의 `processText` 콜백을 TypeScript 변환 후 VM 100ms 제한으로 실행했다. 일반 추출·캡처 있는 비전역 추출·행 필터·치환 토큰 4개 정상, 전역 빈 일치 4개와 `(a+)+$` 역추적 1개는 제한 시간까지 반환하지 않았다. 브라우저를 직접 멈추게 한 검사는 아니다. 원본 SHA와 결과는 `before-fix.json`에 보존한다. 검사 lint 0.
- 빈 일치를 `exec()`로 반복할 때 `lastIndex`를 직접 진행해야 한다는 [MDN exec 문서](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/exec)와 일치한다. Unicode 모드에서는 서로게이트 쌍을 나누지 않는 진행이 필요하다.
- UI 스레드의 동기 실행 중에는 타이머로 해당 호출을 중단할 수 없다. 별도 Worker를 [terminate](https://developer.mozilla.org/en-US/docs/Web/API/Worker/terminate)하는 경로로 취소/시간 제한을 구현한다.
- 현행 상세 일치마다 `substring(0,index).split('\n')`를 계산해 많은 일치에 불필요한 반복 비용도 있다.

## 구현 계약

1. 입력·패턴·플래그·치환·작업 모드를 불변 요청으로 Worker에 전달한다. 작업당 하나, 입력 수정/모드 변경/새 실행/언마운트 시 이전 Worker 종료. 300ms 자동 실행은 유지하고 실행 중 취소·실패 후 재시도를 제공한다. 취소한 동일 입력을 효과가 즉시 재실행하지 않게 한다. Worker 생성 실패·시간 초과는 번역된 안내, 메인 스레드 정규식 실행으로 후퇴하지 않는다.
2. 5초 작업 제한, 입력 1,000,000 UTF-16 단위, 파일 4MiB(디코딩 후 같은 입력 한도), 패턴 10,000·치환 100,000 UTF-16 단위, 결과 4,000,000 UTF-16 단위, 일치 100,000개를 초기 한도로 검토한다. 한도를 검사 없이 잘라 내지 않는다. 실제 모바일 비용을 보고 조정하되 안내와 검사를 함께 고친다.
3. 전역 빈 일치의 다음 인덱스는 Unicode 모드의 코드포인트 단위, 그 외 UTF-16 단위로 전진한다. 마지막 위치의 빈 일치는 한 번 포함하고 종료한다. `g/i/m/s` UI와 기존 URL로 전달되는 유효 JS 플래그 의미를 유지한다. 잘못된/중복 플래그는 명시 오류.
4. 일반 추출의 `String.match()` 결과 의미를 보존한다. 특히 비전역에서는 첫 전체 일치와 캡처들이 출력에 포함된다. grep은 일치한 행 한 번씩·원래 순서, 치환은 `$&`, `$$`, `$1`/`$nn`, named capture, 앞/뒤 문맥 토큰까지 기존 JS 의미를 유지한다. 최악의 치환 확장으로 거대한 문자열을 먼저 만들지 않게 결과 한도를 점진적으로 확인한다. 별도 치환 구현을 쓴다면 JS 내장 결과와 광범위 비교해야 한다.
5. 행 번호는 미리 만든 줄바꿈 인덱스/단조 커서로 계산한다. 결과 상세는 기존 첫 5개, 큰 출력은 50,000단위 미리보기와 전체 길이를 구분하고 복사·TXT는 성공한 전체 문자열만 사용한다. 전체 결과/일치 수는 worker 결과에서 계산하고 메시지 크기와 React 렌더 비용도 제한한다.
6. 마지막 성공 결과를 보존할 경우 결과의 입력 스냅샷·상태를 명시하고 현재 실패 입력과 합쳐 저장/공유하지 않는다. 입력 변경 즉시 pending 복사/파일 읽기/다운로드 세대를 무효화한다. 복사 실패는 전체 원문 수동 선택/재시도, native/legacy 실제 성공만 성공 안내.
7. 파일 읽기는 최신 선택만 반영하고 오류·취소·같은 파일 재선택을 처리한다. 입력 텍스트가 이미 URL에 자동 반영되는 기존 정책을 갑자기 개인정보 무저장으로 설명하지 않는다. 기존 이중 인코딩 URL을 복원하되 malformed percent에서 죽지 않고, 무관 query/hash/history와 최신 사용자 입력을 보존한다. 지나치게 긴 공유 URL은 명시 안내, 전체 TXT와 혼동하지 않게 한다.
8. 스마트 모드의 중복 제거는 이전 정규식 작업을 취소하고 독립된 성공 결과로 취급한다. 추가 실제 핸들러 검사 `check-regex-smart-baseline.mjs`에서 (a) capitalize의 `$1`.toUpperCase()가 `hello world`를 그대로 두는 문제, (b) 여러 글자 끝 구분자 `##`를 한 글자씩 금지해 `::a#b##`를 못 찾는 문제, (c) 중복 제거 직후 기존 예약 콜백이 결과를 숫자 추출로 덮는 문제를 재현했다. 원본 SHA와 3그룹은 `before-smart-fix.json`에 보존한다. 대문자화는 코드 문자열 평가 없이 명시 변환 종류로 Worker에서 수행하고, 양끝 구분자는 리터럴 문자열로 해석한다. 기존 공백으로 나누는 구분자 입력 형식/전체 일치 추출 의미는 유지한다. 이 3건도 이번 Worker 연결 범위에서 고친다.
9. 기존 계산 이력 스키마 호환. 저장/복원 시 현재 결과 스냅샷 일치와 replacement 복원 확인. 새 원격 저장/실제 사용자 텍스트 업로드 없음. KO/EN fragment는 구현 담당 소유, canonical은 통합 담당 소유.

## 검증 순서

- 순수 엔진: 기존 4회귀 + 빈 일치 4개 종료·정확 인덱스, Unicode/CRLF/끝위치, g/y/캡처/치환 토큰, 큰 일치·출력 한도·임의 작은 입력 JS 내장 비교.
- Worker 어댑터: 생성 실패/error/messageerror/timeout/cancel/한 번 종료/지연 A→B→A 응답 무시. 실제 역추적은 반드시 격리 Worker에서 bounded 검증.
- 부모: 자동 실행 취소 후 재시도, 입력/이력/프리셋·모드 전환, 늦은 파일과 복사, Strict replay, 결과 스냅샷, URL 초기화.
- 독립 검토 후 실제 Chrome Worker·타이머 지연·취소·복사/TXT 전체·320px KO/EN. 전체 타입은 모든 TS 담당 동결 후 통합 담당만 실행. 빌드/배포는 실행하지 않는다.

## 부모 연결 시 숨김 정책

[MDN Page Visibility 문서](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)는 비활성 탭의 setTimeout이 지연될 수 있음을 설명한다. 따라서5초 설정을 모든 기기/백그라운드의 엄격한 벽시계 보장으로 표현하지 않는다. 부모 연결에서는 visibility hidden/pagehide 때 진행 중 Worker를 취소하고 마지막 성공 스냅샷을 보존하며, 보이는 상태로 돌아왔다고 자동 재실행하지 않는 정책을 사용한다. 입력 수정/명시 재시도로 새 작업을 시작할 수 있다. 이 항목은 준비 client 자체의 문서 이벤트 구독 완료를 뜻하지 않는다.
