# 33차 native 검증 준비

실행 완료: 최종6/6 PASS. A→B→A 독립 P2 수정 후 기존 copy1흐름만 재검사했고06:44:02 KST에 Chrome을 종료했다. 아래 계획의 실제 결과·제어 포트 구분은 review-browser.md를 따른다.

1. **기존 계산·가져오기:** 실제 URL로 할인율/최종가/할인금액 세 모드를 방문하고 기본 결과를 확인한다. 중복 할인 단계의 기존 계산 결과를 기본 결과와 별도로 가져와 클릭 당시 원 단위 반올림과 수량1/쿠폰0/배송비0을 확인한다. 기존 입력 변경은 가져온 값을 바꾸지 않고 최대4개·잘못된 최종가에서는 추가를 막는다.
2. **독립 계산 oracle:** BigInt로 상품합계·실제/초과쿠폰·상품결제액·배송비/총액을 계산한다. 총액 최저와 단가 최저가 다른 조건, 공동 최저,0원/배송비/쿠폰초과를 실제 카드에서 비교한다. 빈칸·소수·음수·초과·이름40경계의 원문 보존 및 일부 미완일 때 전체 최저/반출 보류를 확인한다. 표시 반올림과 비교의 정확성을 구분한다.
3. **URL 초기·수정·새 방문:** 유효 compare v1과 기본 모드·unrelated query·hash·history.state를 함께 주입해 최초 복원을 확인한다. 기존 계산 편집은 비교를 유지하고 비교 편집은 과거 compare만 제거한다. 명시 복사 링크에는 최신 숫자 전체만 포함되고 개인 합성 이름은 제외된다. 새 방문에서 숫자만 복원하며 손상/미래버전은 부분 복원 없이 예제+안내다.
4. **실제 TXT·Clipboard·PNG:** 독립 계산값과 모든 조건 이름/상세가 있는 전체 Clipboard/TXT를 대조한다. native Clipboard의 OS CRLF는 논리 줄바꿈으로만 정규화하고 다운로드 UTF-8 bytes는 별도 검사한다. 실제 ShareResult PNG1080×1350에서4조건 요약을 Canvas 원호출 관찰+PNG decode로 확인한다. 이름만 A→B→A인 동안 실제 toBlob 완료를 보류해 같은 수치/URL이라도 resultKey가 늦은 다운로드를 막는지 확인한다.
5. **복사 복구·오래된 요청:** native reject/API부재+legacy false/throw·true, 전체 readOnly 선택/native 재시도. 입력·새 요청·locale 및 실제 unmount 후 오래된 실패의 fallback/안내 차단과 이전 성공 타이머의 소유권을 확인한다. 기존 기본 링크와 비교 링크가 다른 범위임도 확인한다.
6. **320px 다크 KO/EN:** 긴 합성 이름과4카드·입력16px/주요버튼44px·결과 바로가기·문서 overflow0. 언어 변경은 조건 초안을 보존하고 새 반출 문구를 갱신한다. JS/hydration/unhandled/raw key 오류를 수집한다.

실제 파일/DOM/Clipboard와 의도적으로 주입한 권한 실패·late callback을 구분한다. OS 공유창/외부 판매처/가격 조회·장기 저장은 사용하지 않는다. 38 전체 검사를 반복하지 않고33의 새 소비자 resultKey 연결 경계만 검사한다. 원문·이름이 현재 URL 또는 storage/외부 payload에 새로 들어갔는지도 기록한다.
