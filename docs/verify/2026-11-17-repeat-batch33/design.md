초안 행은 `{id, name, unitPrice: string, quantity: string, coupon: string, shipping: string}`다. id는 방문 중 증가하는 안정 ID이며 이름/숫자와 독립이다. 숫자 입력은 `type=text inputMode=numeric`로 원문을 보관한다. 검증된 행은 숫자 projection과 고정 산식 결과를 갖고 원본 draft를 바꾸지 않는다. 이름은40 code point 이내, 줄바꿈은 한 줄 표시 정책으로 정리하며 URL에 절대 넣지 않는다. 이름이 비어 있으면 화면/반출에서 지역화된 `조건 N`을 사용한다.

`evaluateDiscountComparison(drafts)`는 각 행의 `ready | missing | invalid`와 필드 오류, `validCount/totalCount`, 모든 존재 행 유효 여부, 총액/개당 최저 ID 집합을 반환한다. `captureDiscountComparison`은 존재 행이1~4개이고 **모든 행이 유효할 때만** 복제·freeze한 전체 snapshot을 만든다. 복사/TXT/공유 링크가 무효 행을 조용히 누락시키지 않는다.

## 계산과 미완 입력

가격0~1,000,000,000, 수량1~999, 주문 쿠폰0~1,000,000,000,000, 배송비0~10,000,000. 빈칸·소수·음수·지수형·Infinity·범위 밖은 원문을 남기고 오류/입력 필요로 처리한다. 선행0은 초안에서 보존하고 검증된 숫자 projection에만 정규화한다. 비교에는 외부 판매처/할인 정책을 추정하지 않는다.

`상품합계 = 개당가격 × 수량`, `적용쿠폰 = min(입력쿠폰, 상품합계)`, `초과쿠폰 = 입력쿠폰 - 적용쿠폰`, `상품결제액 = 상품합계 - 적용쿠폰`, `총액 = 상품결제액 + 배송비`, `개당평균 = 총액 / 수량`이다. 쿠폰은 배송비에 적용하지 않는다. 정수 총액과 별도 개당 평균을 함께 표시한다.

총액 최저와 개당 최저는 별도로 판정한다. 총액 최대999,010,000,000, 단가 분수 교차곱 최대 `999,010,000,000 × 999 = 998,010,990,000,000 < 2^53`이므로 검증된 범위에서는 정수 Number 연산으로 정확히 비교할 수 있다. 반올림된 표시 값으로 최저/동률을 판단하지 않는다. 평균은 소수 둘째 자리까지 표시하며 표시가 같아도 반올림 전 값이 다를 수 있음을 안내한다. 동률은 해당 모든 ID에 공동 최저 표시를 붙이고 행 순서/이름을 바꾸지 않는다.

미완/오류 행은 그대로 보이며 유효한 행의 개별 산식만 볼 수 있다. `유효 조건 N / 전체 M`을 표시하고 **미완 행이 있으면 전체 최저 판정을 보류**한다. 모든 행이 유효해도1개뿐이면 결과는 보이되 ‘다른 조건을 추가해 비교’로 안내한다. 0개는 빈 상태로 반출을 막는다. 기본 두 예제는 즉시 결과를 보여 주되 실제 판매처/추천으로 표현하지 않는다.

가져오기는 기본 결과와 중복 결과를 구분한 명시 버튼 두 개다. 클릭 시 유한하고 음수가 아니며 원 단위 반올림 후10억 이하인 결과만 `Math.round`로 가져온다. 다른 조건을 덮지 않고 새 행에 수량1/쿠폰0/배송비0을 넣는다. 4개일 때와 기존 최종가>원가 오류일 때는 이유와 함께 가져오기를 막는다. 이후 원래 계산기를 편집해도 가져온 조건은 바뀌지 않는다.

## URL 공존과 프라이버시

제안 owned key는 `compare` 하나, 값은 `v1:unit,quantity,coupon,shipping;…`이다. 최대4개·원시 길이256 이하·정수 문자열만 받으며 행당 정확히4필드다. unknown version/과다행/잘못된 필드/범위 밖을 **전체 실패**로 처리해 일부 조건만 복원하지 않는다. 이름/id/비교 순위는 encode하지 않고 숫자 입력 순서만 보존한다. 수신 이름은 `조건1…N`으로 새로 만든다. 복원 실패는 기본 예제를 유지하면서 명시 안내를 띄우고 기존 계산기의 모드·숫자 복원을 막지 않는다.

초기 같은 hydration 작업에서 부모 기본 계산과 비교를 읽는다. 비교 링크는 명시 공유 시 현재 부모 숫자 + 전체 유효 비교 snapshot으로 생성하며, 자동 writer는 비교 숫자를 새로 쓰지 않는다. 공유 링크를 연 뒤 비교를 편집하면 기존 `compare` 값이 최신 화면처럼 남지 않도록 해당 키를 제거한다. 이 삭제는 이름/원문을 주소에 추가하지 않는다. 부모 숫자 편집만으로 비교 입력을 초기화하지 않으며 부모 writer는 이 키를 새 값으로 재생성하지 않는다.

기존 기본 계산 링크와 새 비교 링크는 라벨로 범위를 구분한다. 기본 계산 링크는 기존5숫자/모드만, 새 비교 링크는 같은 기본값과 최신 유효 조건 전체를 함께 담는다. 둘 다 사용자 이름은 제외한다. 기존 자동 writer가 비교 수신값을 지우지 않는지, 비교 편집 뒤 과거 query가 다시 살아나지 않는지, query/hash/history.state 보존과 새 방문 hydration을 실제 부모로 검사한다. 외부 popstate 복원까지 확장할 경우 같은 query/hash-only 이동은 이름·초안을 초기화하지 않는 기준을 사용한다.

## 복사·TXT·공유 액션

snapshot에는 순서, 전체 이름, 입력4숫자, 상품합계/입력·적용·초과 쿠폰/배송비/총액/평균, 두 최저 ID 집합과 반올림 설명이 들어간다. 전체 텍스트·TXT는 이 snapshot 하나에서 생성하고 파일명은 `discount-comparison.txt`처럼 사용자 이름을 넣지 않는다. Clipboard native 성공 또는 legacy execCommand=true일 때만 성공으로 표시한다. 실패하면 동일 snapshot의 readOnly 선택 영역을 제공한다. 입력/locale/새 액션/언마운트 세대가 바뀌면 늦은 성공/오류/성공 초기화 타이머를 무효화한다. 실제 clipboard에 이미 쓰인 과거 텍스트를 되돌렸다고 주장하지 않는다.

**공용 공유의 별도 주의점:** `ShareResult.tsx:26`의 save는 `await renderShareCard` 뒤 최신 여부를 검사하지 않고 download를 실행한다. 컴포넌트 key를 바꾸는 것만으로 이전 비동기 저장을 취소할 수 없다. 또한 `shareCard.ts:104`는 rows를5개까지만 그리므로 조건별 여러 행을 그대로 주면 누락된다. 제품 변경 없이 읽기로 확인한 경계이며 재현 완료 결함으로 확대하지 않는다.

Root 결정에 따라 **지역 공유 UI를 복제하지 않고 정식 ShareResult를 사용한다.** 28/30 체크포인트 뒤 root 소유38차가 optional resultKey·mounted/request 세대·클릭 시점 card/url/text snapshot·stale 후 fallback/URL 생성/성공 표시 차단·렌더 실패/수동 copy 복구를 보완할 예정이다.33은 이 API를 의존성으로만 기록하고 공용 파일을 직접 수정하지 않는다.33의 resultKey는 입력/locale 변경과 값 왕복까지 구분하는 revision으로 전달한다.38 ready 전에도 독립 순수 계산/UI 준비는 가능하지만 공용 비동기 반출 검증을 완료했다고 주장하지 않는다.

공유 이미지는 조건4개를 각각 한 행의 총액·개당 평균으로 표시하고 기본 `조건 N` 라벨을 사용한다. 전체 이름·입력·쿠폰 상세는 텍스트/TXT에 유지한다. 이미지 요약에5행을 넘게 넣거나 긴 이름을 겹쳐 그리지 않는다. 동일 snapshot에서 나온 요약이라는 점과 전체 내역의 위치를 명시한다.
