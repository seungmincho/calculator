# 33차 계약 — 할인 후 실제 결제금액 비교

> 완료(2026-11-17 KST): 자체33·독립9·실제 Chrome6/6·06:44:29 KST 공통 전체 타입 첫 실행을 통과했다. 복사 안내 A-B-A 경계는 수정 후 영향 검사로 확인했다. [완료 보고서](report.md). 아래는 실행 당시 계약이다.

2026-11-17 KST. 기존 `/discount-calculator/` 개선 계약으로 아래 범위의 구현·검증을 완료했다. 기존 세 계산 모드와 최대3단계 중복 할인을 유지한다. 신규 도구/경로·판매처 조회·가격 추천은 추가하지 않는다.

현재 `DiscountCalculator.tsx`는 원가/할인율/할인금액과 연속 할인 결과를 보여 주지만 배송비·주문 쿠폰·수량을 합친 판매처 비교는 없다. 사용자가 할인 후 가격이 낮은 곳을 골라도 배송비를 합치면 총액이 바뀔 수 있어, 입력한 조건을 나란히 볼 수 있게 한다.

## 제안 범위

- 같은 상품의 구매 조건을 최대4개 비교한다. 각 조건은 이름40자, **할인 후 개당 상품 가격**, 수량, 주문 금액 쿠폰, 배송비를 갖는다. 할인율은 기존 계산기에서 먼저 계산하고 ‘현재 할인 결과로 조건 추가’로 클릭 당시 최종 가격을 가져온다. 기존 입력/모드/중복 할인 결과는 바꾸지 않는다.
- 계산 순서는 `상품 가격×수량 → 상품 합계에서 금액 쿠폰 차감(최소0) → 배송비 추가`로 고정하고 화면에 보여 준다. 쿠폰은 배송비에 적용하지 않는다. 입력 쿠폰 중 실제 적용된 금액과 상품 금액을 넘은 부분을 구분한다. 카드 할인/적립/무료배송 조건/판매처별 쿠폰 정책을 추정하지 않는다.
- 원화 정수 단위이며 가격0~10억, 수량1~999, 쿠폰0~1조, 배송비0~1천만으로 제한한다. 빈칸·소수·음수·범위 밖은0으로 바꾸지 않고 해당 조건의 오류로 남긴다. 기존 계산 결과를 가져올 때만 기존 화면과 동일한 원 단위 반올림을 적용하고 설명한다.
- 총 결제금액과 배송비까지 포함한 개당 평균을 함께 표시한다. 수량이 다른 경우 총액과 개당 금액의 차이를 명시하며 동일 상품/단위라는 사용자 입력 전제만 사용한다. 값이 같은 조건은 공동 최저로 표시하고 이름/입력 순서를 바꾸거나 임의로 추천하지 않는다. 비교는 표시용 반올림 전 값으로 수행한다.
- 기본 두 예제 조건에서 결과가 바로 보이고 조건 추가/삭제/이름 변경·현재 결과 가져오기는 명시 조작이다. 최대4개 조건은 방문 메모리에 두며 새 장기 저장을 도입하지 않는다. 사용자에게 기기 기록 저장을 약속하지 않는다.
- 요약 복사·TXT·ShareResult는 같은 확정 조건/결과 snapshot을 사용한다. 실패 복사는 읽기 전용 선택/재시도, 입력 변경·새 요청·언마운트의 늦은 성공은 무효화한다. 파일명에는 사용자 이름을 넣지 않는다.
- 비교 링크는 명시 공유할 때 숫자 조건만 최대4개를 제한된 v1파라미터로 담고, 직접 입력한 이름은 포함하지 않는다고 설명한다. 수신 시 세 계산 모드의 기존 URL과 함께 복원한다. 부모의 현재 `new URLSearchParams()` writer가 새 비교 파라미터를 조용히 지우지 않게 실제 페이지 복원/편집/공유를 검증한다. 자동 주소 갱신에 비교 이름이나 기타 원문을 넣지 않는다.
- 모바일은 조건별 카드·16px 입력·44px 조작·결과 바로가기와 전체 이름 줄바꿈을 사용한다. 기존 복사 helper의 native/legacy 성공 검사는 유지하되 stale 응답과 성공 타이머도 현재 요청에만 적용한다.

검증은 독립 정수 계산 oracle로0원·쿠폰초과·배송비·수량/동률·경계·반올림, 기존3모드/다중할인 불변, 추가 당시 snapshot·미완 입력·최대4개·URL 정상/손상/재방문, 복사/TXT/공유 숫자 일치·이름 제외, KO/EN·320px로 구성한다. 공용 번역/메타와 전체 타입 검사 후 완료한다. 빌드·배포·커밋은 하지 않는다.
