# 25차 독립 브라우저 계획

완료: 2026-11-17 04:11 KST, **12/12 첫 실행 PASS**. 실제 범위와 fixture/OS 구분은 [최종 보고서](review-browser.md)에 기록했다. 메모 연결 전체는 재실행하지 않고 별도 키의 OCR→TTS 최소 회귀를 수행했다.

24차 전체 타입 검사 통과 후 준비한다. 제품 부모 final ready와 공용 번역 생성 신호까지 Chrome을 열지 않는다. 실제 실행은 기존 localhost:3039·단일 Chrome·순차 격리 컨텍스트이며 서비스워커와 외부 통신을 차단한다. 공개 리더보드 조회/제출은 로컬 route mock으로만 처리하고 실제 서버에 점수를 보내지 않는다.

## 저장 원고 → Diff (6흐름)

1. 실제 글자수 저장본 선택 → 새 탭: 두 원문·이름·현재 탭·opener null·sessionStorage 한 번 소비, 원래 5탭/저장본 bytes/URL 보존. 기존 열린 Diff 입력은 그대로이며 자동 Worker 0회. 명시 비교 후 실제 Worker 결과를 TXT로 받아 두 입력을 재구성한다.
2. 현재 글이 빈 경우도 그대로 전달. 팝업 차단과 새 탭 저장소 거부는 원문/목록을 보존하고 실패 탭을 닫는다. 50,001자는 잘라 보내지 않는다. 놓친 storage event의 변경 raw는 클릭 시 재조회해 전달 중단한다.
3. 수신 payload의 marker 없음·미존재·만료·미지원·역할 역전: 입력과 적용하지 않은 raw를 보존하고 기본 비교 기능은 사용 가능하다. 성공 소비 뒤 새로고침은 재적용하지 않는다.
4. 초기 수신 callback을 제어해 사용자 편집·비교가 우선함을 확인한다. 읽는 중 raw 교체와 소비 직전 새 raw 교체를 나눠 입력/새 데이터 보존을 확인한다. locale·swap·새 payload가 같은 방문의 수정 입력을 다시 덮지 않는다.
5. 받은 문서의 native 복사/TXT 및 복사 실패 수동 선택·dirty snapshot 안내. OCR/메모→TTS는 별도 키로 기존 전달이 되는 최소 회귀를 수행하며 실제 음성 재생은 하지 않는다.
6. 320px 다크 KO→EN, source 전달 버튼/target 16px 입력·44px 주요 조작·가로 폭·escape된 제목·원시 키·JS/hydration. 실사용 원고 없이 합성 문자열만 쓴다.

## 같은 클래식 지뢰판 연습 (6흐름)

7. 일반 클래식 첫 클릭·패배→같은 판: mine/count/크기/첫 칸/noGuessFailed 동일, marks/boom/clicks/time 초기화. 유효한 후속 조작부터 시계 시작. 다시 패배→재연습도 원 배치 불변.
8. 실제 UI 클릭으로 연습 승리/패배: BEST·업적·일일·이름 저장 bytes와 점수 제출 수가 추가되지 않는다. 정상 클래식 승리는 기존 기록을 갱신하고 이름 모달에 도달한다. 배치 관찰은 읽기만 하며 게임 상태를 직접 고치지 않는다.
9. 새 판·같은 난도·같은 classic 탭·custom 적용·daily 왕복은 일반 흐름 복귀. daily bytes 보존, 연습 버튼은 종료한 classic에만 보인다. 작은 5×5/1지뢰 자동 펼침 완료는 순수/부모 증거를 보완할 실제 UI fixture가 가능할 때 포함한다.
10. 오래된 이름 제출 callback과 이미 시작된 mock RPC의 늦은 응답은 새 연습 상태를 바꾸지 않는다. mock 요청은 개수/필요한 테스트 메타데이터만 증거로 남기며 공개 서비스 호출은 0이다.
11. 350ms long-press callback 지연 → 판 교체 → 옛 callback/up/click은 새 판에 영향 0. 이후 정상 터치·F/Enter/방향키가 작동해 입력 잠금이 남지 않는다. 합성 PointerEvent와 실제 마우스·키보드 조작을 구분한다.
12. 320px KO/EN 다크에서 연습 안내·재연습 44px·보드 내부 스크롤/페이지 폭·키보드·raw 번역 키·JS/hydration을 확인한다. 기존 작은 보드 셀을 새 44px 버튼 계약과 혼동하지 않는다.

제품 결함은 담당자에게 재현을 전달하고 영향 사례만 재검사한다. 검증 조건 오류는 별도 기록한다. 완료한 증거를 수시 저장하고 마지막 Chrome 종료 뒤 통합 담당에게 전체 타입 검사 가능 신호를 보낸다. 빌드/서버 재시작/제품 TS/공용 원본/패키지는 변경하지 않는다.
