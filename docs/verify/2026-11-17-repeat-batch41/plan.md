# 41차 실행 계약 — 메모장 작성 내용과 가져오기 보호

상태: 로컬 구현·자체36·독립22그룹·실제 Chrome8/8·공용 검증과08:43:20 KST 전체2GB 타입 첫 실행을 통과해 완료했다. 빌드·배포·커밋·푸시는 하지 않았다. [최종 보고서](report.md).

## 사용자가 겪는 문제

두 탭에서 메모장을 사용할 때 다른 탭 저장 이벤트가 아직 저장하지 않은 현재 글을 바로 덮는다. 파일을 가져오는 동안 수정한 글도 파일 읽기가 끝나면 가져오기 시작 당시 내용으로 되돌아간다. 일반적인 사용 중 원고가 사라지는 문제이므로 저장 성공 안내보다 실제 원고 보존을 우선한다.

`check-notepad-baseline.mjs --record`는 실제 `Notepad.tsx`의 storage/import 핸들러를 추출해 합성 메모와 지연 File 포트로 실행했다. 다른 탭 갱신→로컬 원고 교체, 외부 key 삭제→원고 목록0개, 파일 대기 중 편집→예전 내용 복귀 세 건을 재현했다. `before-fix.json`에 원본 SHA를 보존한다. 실제 사용자 메모/브라우저 localStorage를 읽지 않았다. 기존 package module-type 경고와 제품 실패를 구분한다.

## 개선 계약

1. 기존 `toolhub-notepad-notes` 배열과 settings key, v1 백업 포맷을 유지한다. 새 원격 저장·계정·자동 텍스트 URL을 추가하지 않는다. 현재 입력, 마지막 확인된 저장본, 외부 변경, 쓰기 실패를 분리한다.
2. 최초 읽기는 쓰지 않는다. 현재 permissive `parseNotes`는 가져오기 정리에 쓸 수 있지만 저장본의 손상/미지원 구조를 조용히 정상으로 바꿔 덮는 근거로 쓰지 않는다. 읽기 실패·손상 raw는 해당 key 자동 쓰기를 중단하고 현재 화면의 메모/TXT·JSON 백업은 사용할 수 있게 한다. 실패한 임시 손상 백업을 보존 성공으로 간주하지 않는다.
3. 400ms 자동 저장은 유지하며 키 잠금+raw CAS+readback을 사용한다. pending debounce/lock/언마운트 세대, 자기 확인 write basis 즉시 갱신, unknown write에서 rollback 금지를 명시한다. 잠금 미지원 환경의 원자성을 과장하지 않는다. pagehide는 기다릴 수 없는 비동기 잠금을 새로 시작하지 않게 별도 정책을 설계하고 저장을 보장한다고 말하지 않는다.
4. 외부 storage 이벤트는 dirty/pending 원고를 자동 교체하지 않는다. 내용이 다른 경우 현재 원고를 계속 보존하고 현재 메모 백업/외부 변경 다시 확인/선택적 가져오기 흐름을 제공한다. 외부 삭제와 `clear()`의 key=null도 같은 경계로 다룬다. 원고를 버리거나 외부 값을 덮는 선택은 적용할 대상과 차이를 볼 수 있어야 한다. 무조건 최신 timestamp가 이긴다는 병합을 자동 적용하지 않는다.
5. 파일 가져오기는 클릭 시 파일 목록과 작업 세대를 캡처한다. 읽는 동안 편집/새 메모/삭제/다른 가져오기/외부 변경/언마운트가 발생하면 이전 작업이 현재 메모를 되돌리지 않게 한다. 최신 현재 메모와 충돌 없이 추가만 할 수 있는지 검토하고, 같은 ID 충돌은 분리 보존 또는 사용자가 확인할 명시 적용으로 처리한다. 읽기 오류도 개별 파일별로 보고하고 원문은 유지한다. 취소/같은 파일 재선택·입력 초기화·늦은 완료를 포함한다.
6. 가져오기 undo는 적용 시점의 최신 원고에 기반해야 하며 이후 사용자의 편집/다른 작업을 통째로 지우지 않는다. 삭제/모두삭제 undo와 같은 toast를 공유하므로 작업 소유권/만료 timer를 함께 확인한다.
7. 입력·파일 수·파일 bytes·전체 노트 수/문자 한도는 현재 실제 저장 가능한 legacy 데이터를 먼저 측정한 뒤 정한다. 편의상 작은 새 상한으로 기존 유효 데이터를 손상 취급하지 않는다. 큰 백업 검증/파싱/본문 통계가 메인 스레드를 오래 막는 경우 별도 worker 도입의 실측 근거를 마련한다.
8. 검색/고정/찾기바꾸기/전체화면/보기설정/텍스트·백업 반출/읽어주기 선택 범위 전달을 보존한다. settings 실패가 본문 쓰기를 막지 않게 한다. 접근성·16px·44px·320px KO/EN 및 조합 중 한글 입력을 확인한다. 컴포넌트/번역 조각은 같은 담당, canonical/meta는 통합 담당 소유.

## 검증 단계

- 순수 저장 포트: legacy 정상0write/손상 raw 보존, CAS/잠금 대기/자기 basis/두 writer/Quota/보안차단/readback 불명/취소/Strict 재활성화.
- 실제 부모: 독립 두 탭 저장 이벤트+dirty/pending/clear, 파일 여러 개 지연·역순 완료·읽기 실패·편집/삭제/새 파일/언마운트·undo 세대, 기존 선택 전달/언어전환 회귀.
- 별도 독립 검토와 실제 Chrome 두 탭·실제 TXT/JSON Blob·합성 파일·320px KO/EN. 실제 사용자 메모를 테스트 데이터로 사용하지 않는다.
- 기존 Notepad lint 기준선 오류1건은 이미 이전 체크포인트에 기록되어 있다. 소유 파일 수정 시 해당 진단과 새 변경을 구분하고 해결 범위를 기록한다. 전체 타입은 모든 TS 작성자를 동결한 뒤 통합 담당만 수행한다. 빌드/배포는 하지 않는다.
