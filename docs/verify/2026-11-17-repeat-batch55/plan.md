# 55차 후보 — 서로 다른 QR 묶음 인쇄

상태: 구현·공용 통합·독립8그룹·실제Chrome7/7·전체2GB 타입 첫 실행을 통과했다.10:15:57 KST 사전확인/session68215 exit0이며 최종 근거는 [완료 보고서](report.md)를 따른다. 아래 원래 설계/관측은 당시 계약 근거로 보존한다.

## 사용자 흐름과 중복 제외

`QrGenerator.tsx`의 기존 인쇄는 **같은 코드 하나를 여러 칸 반복**한다. `QrBatchGenerator.tsx`는 서로 다른 최대30행을 PNG로 만든 뒤 ZIP으로 받을 수 있지만, 이30개를 한 장씩 배치해 인쇄하는 기능은 없다. 각 QR에 다른 참여 링크·물품 설명·교실 안내를 넣는 사용자는 ZIP을 풀어 다른 문서 편집기로 옮겨야 한다. 기존 한 코드 반복 인쇄와 여러 이미지 QR 스캔은 그대로 두고 재구현하지 않는다.

## 최소 범위

- 일괄 생성이 모두 완료되고 입력과 결과가 일치할 때 `QR 묶음 인쇄` 버튼을 활성화한다. 기존 입력30,000 UTF-16자/30행/행당1,000 UTF-8바이트·오류정정M·512 PNG·quiet zone4모듈·ZIP을 유지한다. 인쇄 때문에 QR을 다시 생성하거나 payload를 변경하지 않는다.
- 우선 A4 세로, 2열×3행의 한 가지 배치다. 같은 QR 반복이 아니라 원래 순서대로 각 이미지를 한 번씩 넣는다. 최대30개는 최대5페이지이며 마지막 페이지 빈 칸에 코드를 복제하지 않는다. 전체 개수와 페이지 수를 누르기 전에 표시한다.
- 셀에는 실제 QR PNG, 원래 행 번호, 입력한 이름(없으면 행 번호 기반 이름)을 둔다. 원문 URL/연락처/Wi-Fi 비밀번호 등 payload를 QR 아래 평문으로 자동 인쇄하지 않는다. 이름은 최대48코드포인트 표시하고 생략 여부를 인쇄 전 안내한다. 전체 QR payload는 자르지 않는다. 파일명과 셀 이름을 혼동하지 않는다.
- A4 여백12mm, 가용186×273mm 안에서 2열/3행·간격·이름3줄과 충분한 QR 크기를 검증한다. QR는 흰 바탕/검정 이미지와 원래 quiet zone을 유지하고 페이지 사이에 셀을 자르지 않는다. 실제 크기·배율100%와 출력 후 스캔 확인 안내를 제공한다. 특정 실물 프린터/휴대폰 인식률은 보장하지 않는다.
- 클릭 시 이미지·이름·행 순서를 불변 snapshot으로 캡처한다. 준비 중 원문 편집·새 생성·취소·ZIP 선택·다른 인쇄·언마운트는 옛 준비를 무효화한다. 모든 이미지 decode 완료 및 현재 owner 확인 뒤에만 브라우저 print를 호출한다. decode 오류/제한시간 초과는 QR가 빠진 페이지를 성공으로 인쇄하지 않고 오류·재시도를 제공한다.
- 인쇄용 DOM/iframe은 합성한 PNG data URL과 React text/안전한 escape만 사용한다. 이름을 HTML로 실행하지 않는다. 새 창을 불필요하게 열거나 외부 이미지/폰트/스크립트를 요청하지 않는다. 인쇄 후/취소/실패/이탈에는 자기 DOM과 listener만 정리한다. 이미 열린 OS 인쇄 창을 강제로 취소한다고 표현하지 않는다.
- 사이트 메뉴·Footer·다른 도구 결과는 인쇄하지 않는다. 기존 한 코드 반복 인쇄를 수정해야 하는 공통 구조로 만들지 않고 이 배치 인쇄의 소유 문서만 격리한다. 화면에서는44px 버튼·취소·진행 안내를, 모바일에서는 가로넘침 없는 한 열 설명을 사용한다.

## 소유와 검증

한 제품 담당이 새로운 작은 print plan/controller·인쇄용 child, `QrBatchGenerator` 연결과 KO/EN 조각을 함께 소유한다. 기존 QR parsing/generation 정책과 `QrGenerator`의 한 코드 인쇄는 유지한다. canonical/메타는 통합 담당만 변경한다. native 인쇄는 실제 종이를 출력하지 않고 격리 Chrome PDF로 검증한다.
