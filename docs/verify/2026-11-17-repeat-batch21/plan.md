# 21차 준비 계약 — 변환 단계 편집·QR 이미지 순차 읽기

2026-11-17 KST. [코드/공식 디코더 조사](../../handoff/2026-11-17-after-batch20-candidates.md)에 근거한 기존 도구 개선이다. 18~20차가 우선이며 20차 체크포인트 뒤 부모를 연결한다. 새 경로·서버·원문 자동 전송을 추가하지 않는다.

## A. 텍스트 변환 단계 순서와 이력

`/text-converter/`의 기존 변환 규칙과 파이프라인을 유지한다. 각 단계에 44px 위/아래 이동 버튼을 제공하고, 추가/이동/개별 삭제/전체 초기화를 최대 30개 메모리 이력으로 되돌리기·다시 실행한다. 기존의 ‘마지막 단계 제거’ 기능과 새 이력을 혼동하지 않도록 동작과 문구를 맞춘다.

- 원문과 찾기/치환 작성 중 입력을 단계 이력에 섞어 덮어쓰지 않는다. 단계의 options/flags/affix/shuffle seed를 원본대로 복제한다.
- 맨 위를 위로 옮기는 등의 no-op은 이력을 추가하지 않는다. undo 후 새 작업을 하면 redo를 버린다. URL 외부 복원은 새 이력의 기준이며 자기 URL 동기화로 이력이 계속 초기화되지 않아야 한다.
- 기존 URL에서 제외하던 원문/치환 문자열을 새로 넣지 않는다. 새 정규식 규칙·저장소·자동 seed 재생성을 추가하지 않는다. 단계별 실패/REGEX_MAX 정책은 유지한다.
- 계산 규칙 회귀와 순서에 따른 실제 결과 차이, 중복 단계의 위치, 삭제/초기화 undo·redo, 이력 한도·URL·원문 유지·320px/키보드를 확인한다.

## B. QR 이미지 여러 장 순차 처리

`/qr-scanner/` 이미지 흐름에서 최대 10개 파일을 명시 선택해 하나씩 처리한다. 초기 한도는 개당 8MiB·합계 40MiB·원본 16,777,216픽셀이다. 실제 측정에 따라 조정하면 최종 한도/근거를 기록한다. 기다림/처리/성공/미검출/읽기실패/범위초과를 파일별로 보여 주고 취소·실패 항목 재시도·선택 결과 TXT 반출을 제공한다. 중복 파일명은 내부 id로 구분한다.

현재 네이티브 API만으로 모바일 이미지 지원을 포괄할 수 없으므로 **jsqr@1.4.0을 npm 정확 버전 의존성으로 추가하는 구현 선택을 확정**한다. 실제 설치는 21차 착수 때 수행하고 package-lock을 유지한다. 현재 설치된 것이 아니며 새 패키지 관리 도구를 도입하지 않는다.

- `BarcodeDetector`의 qr_code 지원·생성/실행 실패를 확인하고, 미지원/실패/미검출에는 자체 번들 Worker의 jsQR로 한 번 처리한다. 실제 이미지 입력 동작 시에만 Worker/디코더를 로드한다. 제품이 CDN 스크립트를 직접 삽입하지 않는다.
- **파일당 처음 읽힌 QR 한 개**를 표시한다. 한 이미지의 모든 QR, 공간상 첫 위치 또는 ‘이 이미지에 QR은 한 개뿐’이라는 판정을 보장하지 않는다. 사용 안내와 검증도 이 범위로 한다.
- 순차 처리·작업 시간 상한·취소/새 선택/탭 전환/언마운트 세대 검사를 적용한다. 캔버스/bitmap/object URL/Worker를 정리하고 원본 전체를 한 번에 디코딩하지 않는다. fallback 처리 해상도를 줄이는 경우 미검출 한계를 안내하고 임의 성공 결과를 만들지 않는다.
- 카메라 동작과 기존 최근 기록 정책을 유지한다. 새 일괄 원본/결과를 자동 저장하거나 기존 이력에 쏟아 넣지 않는다. 손상된 기존 이력을 조용히 삭제/덮지 않는다.
- QR 내용은 텍스트로 표시한다. 링크는 사용자가 직접 누르는 http/https만 허용하고 Wi-Fi/연락처/스크립트 등을 자동 실행·외부 전송하지 않는다. 복사 실패는 실제 성공과 구분하고 수동 선택 대안을 제공한다.
- 실제 QR 픽셀(한글·동일내용/다른파일·복수QR) 디코딩을 기존 생성기로 만든 fixture와 함께 확인한다. 정상/QR없음/손상/과대 파일 혼합, 늦은 읽기·Worker 완료·취소·재시도, 실제 TXT와 원문, 모바일 긴 텍스트, 카메라 종료/기존 단일 스캔 회귀를 검증한다. mock 오류 검사와 실제 이미지 디코딩을 구분한다.

제품 담당이 UI·ko/en 조각을 함께 작성하고 공용 원본/메타/생성물은 통합 담당이 맡는다. 독립·실제 브라우저 후 Chrome 종료→전체 타입 검사로 완료를 판정한다. 빌드·배포·커밋·푸시는 실행하지 않는다.
