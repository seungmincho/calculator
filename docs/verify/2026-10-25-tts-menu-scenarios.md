# TTS·메뉴 룰렛 검증 시나리오

- 범위: 최근 30일 네이버 유입에 맞춘 기존 TTS·메뉴 룰렛 개선. 빌드·배포는 제외.
- 로컬 개발 서버에서 외부 요청과 서비스 워커를 차단하고 검증한다.
- 화면: 320×740, 375×812, 390×844, 768×1024, 1280×900 및 모바일 다크 모드.

| 시나리오 | 확인할 결과 |
| --- | --- |
| 첫 화면 | TTS 재생과 메뉴 돌리기 버튼이 모바일 하단 내비게이션 위에 보임, 가로 넘침 없음 |
| 터치 | 주요 입력·재생·프리셋·삭제 버튼 높이 44px 이상 |
| TTS 붙여넣기 | 붙여넣은 글로 재생, 권한 거부 시 직접 붙여넣기 안내 |
| TTS 재생 상태 | 긴 글 순차 재생, 일시정지·계속·정지, 문장 이동, 편집 시 이전 발화 취소 |
| TTS 공유 | 글·속도 복원, 복사 실패를 성공으로 표시하지 않음 |
| 실제 음성 | 브라우저 음성 목록과 실제 합성 이벤트 확인. 음성이 없는 환경의 모의 이벤트 검증은 별도로 기록 |
| 메뉴 선택 | 저녁·점심 빠른 선택, 후보 편집, 결과가 현재 후보에 포함됨 |
| 회전 중 변경 | 후보 변경을 막고 완료 후 다시 허용, 후보 변경 시 이전 결과 제거 |
| 공유·회귀 | 공유 URL 후보 복원, 일반 룰렛·순서뽑기 공용 컴포넌트 회귀 확인 |
| 검색 정보 | 제목·OG·Twitter·화면 제목 의미 일치, canonical·JSON-LD 확인 |
| 정적 검사 | 번역 생성·검사, 네임스페이스 감사, 변경 파일 ESLint, tsc, 기존 TTS 유틸 검사 |

실제 기기의 iOS/Android 음성 품질과 네이버 노출·클릭 변화는 로컬 자동화만으로 확인할 수 없다.
