# 16차 성적 입력 기록 독립 검토

담당: writing_versions. 2026-11-17 KST. 15차 최종 수정 경계 확인 후 [16차 실행 계약](plan.md)을 기준으로 새 저장·비교·복원 경계를 검토한다. 조사 후보 문서에 있던 이름 변경/내신 두 기록 비교는 승인된 이번 실행 범위가 아니다.

## 판정

두 제품 final ready 뒤 독립 검토를 완료했다. 내신 자식 패널 **9그룹**·부모 통합 **4그룹**, 수능 도메인 **6그룹**·자식 패널 **9그룹**·부모 통합 **4그룹**, 최초 합계 **32그룹 PASS**다. 수능 도메인에는 593개 선택과목 비교 조합이 포함된다. 이후 브라우저/구현 담당이 발견한 빈칸 공유 URL 정규화 문제의 수정 경계만 **2그룹 PASS**로 추가 확인했다. 독립 실행 증거는 총 **34그룹**이며, 최초 32그룹 전체를 후속 수정 뒤 반복한 것은 아니다. 현재 독립 검토에서 추가 제품 수정 요청은 없다.

구현 중 pending load가 새 입력을 덮지 않는 계약을 내신 담당과 미리 조율했고 최종 구현에서 취소 동작을 확인했다. 제품 파일·공용 번역·Chrome·전체 tsc·빌드·배포는 수정하거나 실행하지 않았다. 배치 전체 수용은 별도 브라우저·통합 결과와 함께 판단한다.

## 조율한 계약

- 내신: `toolhub-grade-records-v1`, version/revision/records. 최대 8개·이름 40자·30행, 과목명 80자·숫자 원문 32자. 입학년도는 부모와 공유하는 2021~2028, 등급제는 5/9. 빈 값·잘못된 문자열·동일 과목명도 그대로 저장하고 요약에는 유효 행만 반영한다.
- 수능: `toolhub-csat-score-records-v1`, 최대 12개·이름 40자. 6개 점수 원문과 선택과목·시험/참고 학년도를 저장한다. 비어 있는 점수는 0점으로 저장/비교하지 않으며, 다른 선택과목끼리 증감을 계산하지 않는다.
- 양쪽 모두 저장본을 자동 적용하지 않는다. 최초 URL 복원 후 액션을 허용하고, 명시적 복원만 현재 입력을 교체한다. 삭제는 현재 원고를 변경하지 않는다.
- CAS/readback와 지원 환경 Web Locks를 사용한다. quota/setItem 실패와 쓰기 후 readback 확인 불가를 구분하며, 후자는 실제 저장됐을 수 있어 rollback이나 원본 불변을 약속하지 않는다.

## 우선 검토 경계

1. 원문 보존: 공백/빈 행/편집 중 값/중복 과목명/동석차와 단위 원문, 상대·절대평가 및 기준 학년도.
2. 엄격한 읽기: 정확한 필드·버전·ID·길이·개수·자료 범위; 잘못된 항목을 조용히 누락하지 않음.
3. 저장 성공 확정과 실패 입력 보존, 다른 탭의 추가/삭제 및 손상·접근 제한, 쓰기 후 재조회 복구.
4. lock 대기 중 현재 입력/ready/선택 변경·취소·unmount에서 늦은 load가 새 원고를 덮지 않음. 구현 전 내신 담당과 이 경계를 조율했다.
5. 부모 URL 초기 복원 우선, 명시적 load 시 행 ID/선택 상태 재구성, 기존 계산·행 추가/삭제·공유를 유지. 수능 기록은 기존 minN/minSum을 의도치 않게 변경하지 않음.

실제 모바일·새 탭·다운로드·브라우저 경합은 별도 검증 보고서와 구분한다.

## 내신 자식 패널 중간 결과

```text
node docs/verify/2026-11-17-repeat-batch16/check-grade-records-component.cjs
Independent grade records: 9 component groups passed
```

실제 `GradeSavedRecords`를 메모리에서 실행했다. `component-harness.cjs`는 React state·layout/effect·저장소·Web Locks·취소 순서를 제어하며 실제 브라우저 검증을 대신하지 않는다.

- 읽기만으로 자동 load하지 않으며 ready=false에서는 액션을 막는다. 확인한 load만 공백·빈 문자열·잘못된 숫자 문자열·중복 과목명을 그대로 전달한다.
- save는 현재 원문을 분리한 snapshot으로 남기고 delete는 선택한 기록만 지운다. 어느 동작도 현재 입력을 복원 콜백으로 바꾸지 않는다.
- quota에서는 원본과 이름을 남기며 명시적 재조회 뒤 성공적으로 재시도한다. 쓰기 후 readback이 막히면 실제 쓰기는 남아 있을 수 있지만 성공을 단정하지 않고 이름을 보존하며 rollback하지 않는다.
- Web Lock을 기다리는 load 도중 부모 입력이 바뀌면 적용을 취소한다. 명시적 취소와 unmount도 대기 중 load/save를 중단한다.
- 같은 raw를 읽은 두 패널이 순서대로 lock을 얻으면 두 번째 stale 쓰기는 거부되고 입력한 이름이 남는다. 손상·미지원 버전은 읽기와 쓰기에서 원본을 유지한다.

## 내신 부모 통합 결과

```text
node docs/verify/2026-11-17-repeat-batch16/check-grade-records-integration.cjs
Independent grade integration: 4 groups passed
```

- 최초 URL 복원 완료 전 child ready는 false이며 주소에 기본값을 쓰지 않는다. 완료 후 해당 입학년도·등급제·과목 원문을 저장 패널에 전달한다.
- 명시적 load는 현재 입력을 원문 그대로 교체하고 기존 객체와 분리한다. 빈 행과 `2abc` 등 계산 불가능한 단위 원문은 저장 상태에 남지만 가중 평균에는 제외한다.
- 이전 선택 과목을 정리하고 새 행 ID를 부여한다. 동일 과목명이어도 두 번째 행만 편집할 수 있고 첫 행 삭제·행 추가·초기화 뒤 다른 행 값이 바뀌지 않는다.
- 96명 중 1등 동점 7명의 9등급제 결과와 단위 가중 평균 1.67을 확인했다. 정상 입력을 복원한 뒤 기존 URL로 다시 방문하면 과목·동석차·등급제·평균 결과가 일치한다.

숫자 입력의 HTML `type=number`는 일부 잘못된 원문을 화면에서 빈 입력처럼 표시할 수 있다. 이 검토는 내부 state와 다시 저장할 snapshot의 원문 보존을 확인했으며, 그 문자열이 브라우저 입력란에 그대로 보인다고 주장하지 않는다. 현재 내신 저장·복원 범위에서 추가 재현 결함은 없다.

## 수능 실제 자식 패널 결과

```text
node docs/verify/2026-11-17-repeat-batch16/check-csat-records-component.cjs
Independent CSAT records: 9 component groups passed
```

- 목록 선택은 비교만 수행한다. 다른 과목·빈 점수·다른 학년도 안내가 표시되고 6개 영역에 등급 변화 대신 원점수만 비교한다.
- URL ready 전 액션을 차단하고 저장·복원·삭제는 명시적 확인 후 실행한다. 공유 입력 교체 안내, 원문의 빈칸·앞자리 0 보존, 삭제의 현재 입력 격리를 확인했다.

- 두 패널의 같은 raw 읽기 후 순차 Web Lock 획득에서 두 번째 stale 쓰기를 거부한다. 손상·미래 버전·용량 초과 저장소는 덮지 않는다.

## 수능 부모 통합 결과

```text
node docs/verify/2026-11-17-repeat-batch16/check-csat-records-integration.cjs
Independent CSAT integration: 4 groups passed
```

- 공유 URL 최초 복원 전에 저장 패널 ready는 false다. 복원 후 점수·선택과목을 전달하고 공유 진입 여부를 한 번만 기록한다. 로컬 편집으로 URL이 생겨도 공유 진입으로 오인하지 않는다.

## 범위와 한계

같은 Web Lock을 사용하는 탭은 직렬화하며 미지원 환경의 CAS/readback에는 완전한 동시 쓰기 원자성이 없다. 하네스의 lock 순서 검사는 실제 브라우저 전체 환경에 대한 보장이 아니다. 내신 저장 원문 보존과 기존 URL의 정상 입력 공유 범위를 구분했다. 수능 URL의 빈칸 보존은 아래 후속 검사로 확인했다. 실제 UI·모바일·브라우저 새 방문·콘솔은 담당 보고서를 따른다. 제품 빌드·배포·검색 색인은 실행하거나 검증하지 않았다.

## 빈 수능 점수의 공유 URL 후속 수정 확인

최초 32그룹은 빈 점수의 저장·비교·부모 state 보존과 정상 완성 입력의 URL 왕복을 각각 확인했다. 이후 브라우저/구현 담당이 빈 기록 복원 후 URL의 기존 `|| '0'` 정규화 때문에 새 방문에서는 0점이 되는 경계를 발견했다. 담당자는 명시적인 빈 query를 보존하고, 파라미터 부재의 기본값과 실제 0점을 구분하도록 최소 수정했다.

```text
node docs/verify/2026-11-17-repeat-batch16/check-csat-records-empty-url.cjs
CSAT empty URL fix: 2 independent groups passed
```

- 과거 기록의 빈 국어·영어·탐구 점수와 `0`/`00`을 복원한 뒤 실제 URL 값이 그대로인지 확인했다. 새 컴포넌트 방문의 hydration 전 주소 보호와 이후 동일 점수/선택과목 복원, 현재 기준·최저 조건·기타 query/hash 유지가 통과했다.
- 파라미터 없는 국어는 기본 84점, `kor=`은 빈칸, `kor=0`은 실제 0점으로 구분된다. 구형 `subject=english&score=`도 빈칸으로 복원되고 이후 정규 query에서도 빈칸을 유지한다.
