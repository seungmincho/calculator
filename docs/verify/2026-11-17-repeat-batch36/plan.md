> 완료(2026-11-17 KST): 자체30·독립11·실제 Chrome8/8·07:13:07 KST 전체 타입 재검사를 통과했다.37 타입 오류1건은 반환형 명시·영향1/lint 뒤 해결했고36 제품 런타임은 변경하지 않았다. [완료 보고서](report.md). 아래는 최초 조사·실행 당시 계약이다.

2026-11-17 KST. 기존 `/dutch-pay/`의 저장·결과 사용성을 읽기 조사한 **후보 계약**이다. 현재 28/30 검증과 이후 승인된 부모 연결이 우선이다. 제품/공용/TS 변경, 검사 실행, Chrome·전체 타입 검사·빌드·배포는 하지 않았다. 새 도구·계정·은행 연결은 제안하지 않는다.

후속 확정: root가 **계산/URL codec을 확장하지 않고 저장 전 정확한 왕복 검증으로100항목 초과·손상 손실을 막는 최소안**을 채택했다. 현재 폼·저장 원본은 보존한다. 실제 codec을 통한 읽기 계산에서 최악의 정상 최근10개 raw339,201 bytes를 확인했고, 최근 raw512KiB/개별 d64KiB/decoded48KiB/계좌 raw1KiB 파싱 상한과 API·단계를 [최종 구현 설계](design.md)에 정리했다. 31/32/38 타입 체크포인트와 root 신호 전에는 제품/검사 TS를 작성하지 않는다. 아래 코드는 최초 조사 시점의 근거다.

## 실제 코드와 사용자 흐름

`src/app/dutch-pay/page.tsx`는 `DutchPay.tsx`를 직접 사용한다. 계산과 URL codec은 `src/utils/dutchPay.ts`, 기존 계산 회귀는 `scripts/check-dutch-pay.ts`에 있다. ko/en 모두 `dutchPay.recent`, `notice.accountNote`, `copied`, `guide`가 실제 UI에 연결되어 있다.

- **저장 기록**: `dutchPay.recent`에 `{d,title,total,n,at}[]` JSON을 쓴다. 명시 저장은 같은 encoded `d`를 제거하고 맨 앞에 추가해 최근 **10개**를 남긴다. 읽기는 JSON cast뿐이고 초기 읽기 실패는 빈 목록으로 처리한다. `null`/잘못된 배열·entry가 그대로 state에 들어갈 수 있다. `saveRecent/removeRecent`는 화면 목록을 먼저 바꾸고 `store()`가 setItem 예외를 무시한다. 저장 버튼은 항상 ‘저장했어요’를 표시하므로 재방문하면 사라질 기록을 저장됐다고 오인할 수 있다.
- **계좌**: `dutchPay.account`는 JSON 문자열이다. 입력은 선택 사항·maxLength 60이고 매 편집마다 메모리와 이 키를 갱신한다. 저장 실패 안내가 없으며 잘못된 JSON 구조도 cast로 들어가 `account.trim()` 등에서 실패할 수 있다. 현재 문구는 ‘이 기기에만 저장돼요. 공유 링크에는 들어가지 않아요.’/‘Saved on this device only…’다. 실패 때도 저장을 단정하는 문구를 상황에 맞게 구분해야 한다.
- **불러오기**: 기록을 클릭해야 `decodeState(d)`로 현재 정산을 바꾸며, 최근 기록을 자동 적용하지 않는다. URL `d`와 과거 `?total=&people=`가 첫 폼 복원의 우선 경로다. 저장 기록/계좌 읽기 때문에 이 입력을 덮지 않아야 한다.
- **복사**: 송금 금액(숫자만), 전체 공지, 보기 전용 링크가 부모 `copy(text,id)`를 공유한다. native Clipboard 거부를 catch한 뒤에도 성공 표시하며, legacy의 false도 확인하지 않는다. 요청/2초 성공 타이머의 세대가 없어 다른 정산·계좌·언어·복사 대상 뒤 늦은 완료가 현재 상태를 덮을 수 있다. `copiedId`는 저장 성공 표시에도 같이 쓰인다.
- **공유 보조 컴포넌트**: `ShareResult`는 별도 구현이고 이미 legacy false를 확인한다. 이번 후보에서 공용 컴포넌트를 통째로 교체하거나 부모와 사이트 전체 Clipboard가 직렬화된다고 주장하지 않는다.

이 경계는 소스에서 확인한 내용이며 실제 사용자 브라우저 재현 결과로 집계하지 않는다.

## 최소 개선 계약

1. **실제 저장 상태를 구분한다.** 기록 저장/삭제는 검증과 raw CAS, 지원 시 같은 key Web Lock, setItem/readback 확인 뒤에만 성공으로 표시한다. 실패면 현재 정산과 마지막으로 확인된 목록을 유지하고 그 자리에서 재시도할 수 있게 한다. readback 불가/불일치는 이미 저장됐을 수 있는 ‘확인 불가’이며 이전 raw로 rollback하지 않는다. 저장 상태는 복사 성공 상태와 분리한다.
2. **손상 원본을 보존한다.** 최근 기록은 배열/entry 필드의 타입·유효 날짜·유한 정수 total/n·지원되는 d 구조를 검증하고, 계좌는 문자열인지 확인한다. 잘못된 원문은 빈 정상 데이터로 취급해 자동 덮어쓰지 않는다. 해당 키의 쓰기만 막고 정산 계산·메모리 계좌 입력·복사는 계속 쓸 수 있다. 명시 재조회는 현재 폼과 계좌 입력을 덮는 범위를 간단히 설명한다. 원본 폐기를 제공한다면 확인된 raw에 대한 별도 명시 동작으로 제한한다.
3. **계좌 자동 저장의 편의를 유지한다.** 입력은 즉시 화면/공지에 적용하며 현행 자동 저장을 유지한다. 실패하면 ‘이 화면에서는 사용할 수 있지만 기기에 저장되지 않았어요’와 재시도를 제공한다. 잠금 대기 중 새 계좌 입력·닫기/이탈은 옛 쓰기/성공 안내를 무효화한다. 다른 탭 변경을 조용히 채택하거나 덮지 않고 재조회로 해결한다. 원문 계좌를 에러 로그·분석 이벤트·검증 캡처에 남기지 않는다.
4. **수동 불러오기와 최신 편집을 보호한다.** 저장 기록의 불러오기 버튼은 현재 정산을 바꾼다는 의미를 명확히 하고 URL 초기 복원 전에는 실행하지 않는다. 저장/삭제/재조회가 잠금을 기다리는 동안 현재 정산을 편집하거나 다른 기록을 선택하면 늦은 작업이 폼을 덮지 않게 한다. 기록 저장은 클릭 당시 정산 snapshot을 저장하며 저장 완료가 현재 폼을 되돌리지 않는다. 단순 불러오기에 새 가입/동의 절차를 넣지 않는다.
5. **복사를 실제 결과대로 표시한다.** native 성공 또는 legacy 정확한 true만 성공이다. 실패하면 클릭 당시 문자열을 readOnly로 보여 주고 전체 선택·재시도·닫기를 제공한다. 금액 복사는 구분자/통화 없는 기존 정수 문자열, 공지/링크는 현재 기존 형식을 유지한다. 복사 대상·정산·계좌로 공지 변경·locale·ro 전환·닫기·이탈에서 이전 요청/성공 타이머를 무효화한다. 늦은 native rejection 뒤 legacy를 시작하지 않는다. 이미 OS에 제출한 복사를 취소한다고 주장하지 않는다.
6. **현재 조작 크기와 안내를 맞춘다.** 수정하는 저장/삭제/복사/복구 버튼은44px, 입력/복구 textarea는16px, 폭은320px KO/EN에서 확인한다. 복구를 닫으면 연결된 원래 버튼 또는 유효한 대체 위치로 초점을 돌린다. 결과 금액·송금 목록은 계산 안내이며 복사/저장 성공을 실제 송금 성공으로 표시하지 않는다.

## 구현 전에 분리할 작은 정책

현재 `decodeState`는 외부 URL을 관대하게 읽으며 이름/항목 수를 자르고 값을 기본값으로 바꾼다. 이 함수를 그대로 ‘저장본 검증’으로 쓰면 일부 항목을 잃어도 유효한 기록으로 판정한다. 저장 parser는 원래 encoded 구조와 복원 가능한 값을 별도로 검사해야 한다.

- **지원 가능한 정상 기존 기록은 그대로 복원**하고, 미래 encoded version/구조 오류/잘림이 필요한 기록은 원문을 보존한 채 문제를 알린다. 유효하지 않은 항목만 조용히 제거하고 다시 저장하지 않는다.
- 새 저장 전에 현재 정산이 codec 왕복에서 동일하게 복원되는지 확인한다. 특히100개 초과 항목은 현행 codec으로 손실 없이 복원되지 않으므로 **현재 폼을 유지하고 저장 지원 범위를 안내**하는 작은 방안을 우선 제안한다. 임의 UI100개 제한이나 URL schema 확장은 별도 승인 없이 넣지 않는다. 기존100개 초과 저장본을 완전히 복원하는 codec 확장까지 필요하면 이 후보의 최소 범위를 넘으므로 root가 별도로 결정한다.
- byte 상한을 추가할 경우 최대 정상 명단/100항목/문자 escape의 실제 직렬화 크기를 먼저 계산한다. 편의상 낮은 상한을 정해 기존 정상 기록을 버리지 않으며 초과 raw는 절단/덮어쓰지 않는다. 이 읽기 조사에서는 근거 없는 새 byte 수치를 확정하지 않는다.

## 예상 소유 파일과 검증

제품 담당 한 명이 `DutchPay.tsx` 최소 연결, 새 `utils/dutchPayStorage.ts`, `utils/dutchPayCopy.ts`, 필요하면 `DutchPayCopyRecovery.tsx`, ko/en 조각을 함께 맡는다. 순수 정산식과 기존 URL codec은 우선 수정하지 않는다. canonical 번역/메타는 통합 담당, 실제 Chrome은 단일 검증 담당이다. `ShareResult`의 기존 별도 복사와 교차 클릭할 때 부모의 옛 fallback이 실행되는지도 이벤트 경계로 확인한다.

- 기존 `check-dutch-pay.ts`의 분배 합계·제외·가중치·반올림·여행 순잔액·URL 회귀를 유지한다.
- 정상 두 저장 형식·최근10개/d 중복 갱신/삭제·읽기0쓰기, null/잘못된 타입/미지원 d/큰 escape·100개 경계와 원문 보존을 도메인 검사한다.
- 저장 quota/읽기 차단/readback 확인 불가/실제 두 탭 CAS·Web Locks 미지원, 계좌 연속 입력·잠금 대기 중 편집/이탈·최신 입력 보존을 확인한다.
- 실제 부모에서 URL/legacy URL 우선·수동 복원·ro 편집 전환, 계좌의 d/최근 기록/ro 공지 미포함과 편집 공지 포함, 계좌 실패 때 메모리 공지 유지, 저장 실패의 성공 표시0을 확인한다.
- 실제 Clipboard true/false/거부/API 없음/다른 금액·공지·링크의 역순 완료·새 정산/locale/닫기/이탈, 수동 선택/초점·320px KO/EN을 검증한다. 합성 계좌/명단만 사용하고 원문은 증거 로그에 남기지 않는다.
