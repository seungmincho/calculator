# 팀 편성 후속 독립 코드 검토

검토일: 2026-11-16. 제품 코드 변경 없이 `src/utils/teamRotation.ts`, `src/utils/teamBoard.ts`, `src/components/TeamDivider.tsx`, 번역 조각, 구현 담당의 도메인 검사를 확인했다.

## 결론

현재 구현에서 재현 가능한 미해결 결함을 찾지 못했다. 별도의 짧은 Node 검사에서 147개 조건이 통과했다. 브라우저·전체 타입 검사·빌드는 실행하지 않았다.

## 독립 도메인 검사 — 147개 통과

`node --input-type=module`로 함수를 직접 불러 구현 담당의 시드와 다른 난수 생성기를 사용했다.

- 4~9명, 2~3팀, 6가지 고정 조합, 무작위·실력 균형 모드의 144개 조건을 확인했다.
- 모든 사람의 포함·유일성, 고정한 사람의 원래 팀 유지, 반복 조합 수와 직전 조합 수를 검사했다. 반복 조합은 별도의 두 사람 집합을 직접 만들어 비교했다.
- 작은 명단의 가능한 팀 크기 벡터를 완전 열거해 고정 조건에서 가능한 최소 인원 차이를 구했다. 함수 결과의 인원 차이와 일치하며 `balanceLimited`도 실제 차이가 1명을 넘는 경우에만 참이었다.
- 실력 균형 결과의 팀별 실력 합계 차이는 반환된 기본 균형 편성 기준보다 크지 않았다.
- 추가 2개 조건은 200명·2팀 또는 8팀에서 160명을 첫 팀에 고정한 극단 조건이다. 누락·중복 없이 고정을 유지하고, 가능한 최소 인원 차이 및 실제 반복 조합 수가 맞았다.
- 마지막 1개 검사는 편성 후 수동 이동의 반복 수 재계산과 이전 비교 메타의 불변성을 확인했다. 이전 `teams`·`comparison.previous`·`edited`를 보존하므로 되돌린 상태의 반복 수가 원래 편성 결과와 일치한다.

## UI·상태 흐름 확인

- `handleRotate`는 공개 중·드래프트 중·주장 모드를 거부하며, 유틸에서 현재 명단과 완료된 팀 구성의 일치 여부를 다시 검증한다.
- 새 결과를 적용하기 전에 `rememberBoard`가 이전 팀·고정 목록·결과 모드·비교 메타를 함께 저장한다. `undoBoard`는 네 항목을 함께 복원한다.
- 비교 기준은 직전 팀을 깊게 복사하며, 이후 비교 메타 갱신은 새 객체로 이루어진다. 기록에 든 이전 메타 객체를 수정하지 않는다.
- 반복 조합 수는 현재 팀과 저장된 직전 팀으로 매번 계산한다. 수동 이동·교환 후에는 `edited` 표시로 원래의 실력 기준과 고정 제한 설명을 숨긴다.
- 실력 입력이 달라지면 저장해 둔 실력 스냅샷과 비교하여 이전 기준 수치 설명을 숨긴다. 기준의 팀별 합계 계산은 기존 `distributeTeams`·`rating`을 재사용한다.
- 명단 추가·삭제·일괄 입력·프리셋·명단 불러오기·팀 수 변경은 편성 및 비교 기록을 초기화한다.
- 공유 링크에는 현재 팀·실력·결과 모드만 담고 비교 메타를 추가하지 않는다. 화면도 새로고침으로 비교가 사라지고 링크에는 현재 팀만 담긴다고 설명한다.

- 실제 UI의 클릭·카드 공개·되돌리기·공유 복원·모바일·모션 감소 검증은 별도 브라우저 담당의 결과를 따른다.
- 40개 후보 탐색이므로 모든 입력에서 수학적 최적 반복 수나 반복 0을 증명하지 않는다. 문구도 이 한계를 명시한다.
