# 5~7차 병렬 작업 분업 기록

2026-11-16. 사용자가 root에게 계속 다음 개선을 선정하고 위임하도록 요청했다. 5~7차는 기존 6개 도구로 범위를 확정했고, 작업 에이전트 6개와 root가 아래 역할로 협업했다. 역할을 바꿀 때 이전 도구의 결함 수정이 새 구현보다 우선하도록 했다.

## 충돌과 자원 사용 관리

- UI 담당자가 자기 기능의 번역을 함께 작성했다. 공용 `messages/ko.json`·`en.json`은 통합 담당 한 명만 병합하고 생성물은 스크립트로만 갱신했다.
- 도구별 컴포넌트·유틸·검사 스크립트는 각각 한 담당자가 소유했다. 독립 리뷰 담당은 제품 파일을 직접 고치지 않고 재현 조건을 전달했다.
- 기존 3039 개발 서버를 재사용했다. 브라우저 실행은 한 번에 하나로 순차 진행했고, 총 34개 흐름을 통과한 뒤 모두 닫았다. 메모리 여유 5.92GiB를 확인한 후 전체 타입 검사를 2GB 힙 한도로 단독 실행해 통과했다.
- 5차가 구현되는 동안 root가 6차 후보를 조사했고, 최초 도메인·lint 검증이 끝난 담당을 다음 도구로 재배정했다. 7차는 별도 에이전트가 구현해 공용 파일 쓰기를 피했다.
- 기존 미커밋 변경을 보존했다. 빌드·배포·커밋·푸시는 범위에 포함하지 않았다.

## 리뷰로 보완한 항목

- 글 수정본의 실제 두 탭 동시 쓰기를 Web Locks로 직렬화했다. 미지원 브라우저에서는 기존 저장 동작을 유지하며 원본 비교·쓰기 후 읽기 확인을 적용했다.
- 숫자 일괄 변환의 100줄 뒤 마지막 줄바꿈을 빈 101번째 행으로 오인하지 않도록 보완했다. 긴 숫자와 사용자 텍스트의 스프레드시트 자동 변환·수식 실행도 점검했다.
- 제목·본문·기존 글꼴 카드의 CSS 소유권을 분리해 필요한 글꼴 스타일을 서로 지우지 않게 했다. 실제 글꼴 파일 실패와 CSS 요청 성공을 구분하는 브라우저 경계 검증을 추가했다.
- 택시의 짧은 조건 프리셋은 요약과 명시적 불러오기 동작으로 충분하다는 제품 결정을 기록했다. GPA·긴 원고 교체와 삭제에는 확인을 유지했다.

단독 작업과의 대조 실험을 하지 않았으므로 속도 배수나 토큰 효율 개선 수치를 주장하지 않는다. 최종 검사 결과는 각 [5차 보고서](../2026-11-16-repeat-batch5/report.md)·[6차 보고서](../2026-11-16-repeat-batch6/report.md)·[7차 보고서](report.md)에 기록한다.
