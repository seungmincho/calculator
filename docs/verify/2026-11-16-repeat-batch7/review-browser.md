# 팀 동료 회전 독립 브라우저 검증

기존 팀보드 검증 흐름을 이어서 실제 Chrome 한 개로 순차 실행한다. 서비스 워커·외부 요청은 차단하며 기존 3039 개발 서버만 재사용한다.

1. 완료 편성 → 동료 회전의 실제 반복 수 검산 → 두 번째 회전 → 메타데이터를 포함한 되돌리기.
2. 회전 후 카드 이동·교환·드래그와 반복 수 재계산 → 되돌리기 → 실제 링크 복사와 새 페이지 복원.
3. 실력 균형·고정 조건 보존 및 누락·중복 없음, 표시된 기준보다 실력 편차가 나빠지지 않음.
4. 320px 다크·모션 감소·영어 설정에서 회전 → 기존 주장 드래프트 전환·완료 회귀 및 가로 넘침 검사.

## 결과

**4/4 통과**, JavaScript 예외 0·hydration 오류 0. 결과는 `browser/final-results.json`에 있으며 실제 카드 편성을 읽어 독립적인 사람 쌍 집합으로 표시된 반복 수를 검산했다.

- 6명을 2팀으로 나눈 뒤 반복 동료 수가 줄고 사람이 누락·중복되지 않았다. 두 번째 회전 후 되돌리면 첫 회전의 팀과 비교 문구가 함께 복원되고, 다시 되돌리면 처음 편성과 비교 패널 없음 상태가 복원됐다.
- 이동·교환·드래그 후 반복 수가 실제 팀과 일치하고, 되돌리기와 실제 클립보드 공유 링크 복원이 동작했다. 공유된 팀은 복원하지만 공유하지 않은 직전 회전 기록은 나타나지 않는다.
- 5·4·4·3·2·1 실력값에서 고정한 사람의 팀이 유지됐고 팀 인원 차이는 0, 실력 합계 차이는 표시된 기본 균형 기준 이하였으며 고정 카드는 이동 불가였다.
- 320px 다크·모션 감소에서 회전 버튼과 결과가 동작하고 페이지 가로 넘침이 없었다. 주장 모드에서는 자동 회전 대신 안내가 보이고, 드래프트 중에는 회전 구역이 숨겨졌다. 기존 주장 선택 완료 후 6명과 명단 입력 상태가 정상 복구됐다.

첫 실행의 기능 검사는 모두 완료됐으나 검증용 초기 스크립트가 `about:blank`에서 localStorage를 읽어 수집 오류가 있었다. HTTP(S) 문서에만 적용하도록 고친 뒤 네 시나리오가 모두 오류 없이 통과했다. 제품 수정은 하지 않았다.

스크린샷: `browser/desktop-rotation-board.png`, `browser/rotation-320-dark-panel.png`, `browser/rotation-320-dark-top.png`. 원시 번역 키가 없고 ko/en 회전 키 구조가 일치한다. 공통 번역기의 한국어 전용 제약에 따라 실제 영어 UI 전환 검증은 포함하지 않는다. 빌드·배포·전체 타입 검사·개발 서버 재시작·git 작업은 하지 않았다.
