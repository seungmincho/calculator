# 11차 독립 코드·도메인 검토

검토 담당: writing_versions. 제품 파일은 고치지 않고 재현 조건을 담당자에게 전달한다. Chrome과 전체 타입 검사는 각각 독립 브라우저 담당과 통합 담당이 실행한다.

## 판정

팀 명단 백업과 GPA 시나리오 백업의 코드·도메인 독립 검토를 완료했다. 재현된 P2 두 건은 구현 담당자가 수정했고, 독립 재검증에서 해결을 확인했다. 이 범위에 남은 재현 가능한 high/medium 결함은 없다.

원고 수정본 백업은 이 검토 담당의 구현이므로 여기서 독립 통과 대상으로 세지 않는다. 별도 담당의 [원고 교차 검토](writing-independent-review.md)를 따른다. 실제 브라우저·전체 타입 검사와 이 문서의 코드·도메인 판정은 구분한다.

## 발견 및 수정 확인

| 심각도 | 재현 | 수정 | 독립 재검증 |
|---|---|---|---|
| P2, 해결 | 팀 명단의 ID/제목 충돌 복사본을 사용자가 다른 제목으로 바꾼 뒤 원본 파일을 가져오면, `importOrigin`과 본문만 비교하여 변경된 모임을 중복으로 제외했다. | 충돌 복사의 최종 제목 `copyTitle`을 검증·투영·왕복 보존하고 현재 제목도 일치할 때만 출처 중복을 인정한다. 초기 2필드 출처는 보수적으로 처리한다. | 변경 없는 복사는 duplicate, 제목만 변경한 기존 복사는 conflict, 파일 안에서 제목을 바꾼 복사도 conflict, 자체 왕복 뒤 원본은 duplicate, 본문 같고 다른 모임 제목은 new. 5조건 PASS. |
| P2, 해결 | GPA A 파일의 추가가 Web Lock 대기 중일 때 B 파일을 선택해 최신 미리보기를 만들면, 늦은 A의 stale catch/finally가 B 미리보기·선택을 지웠다. | addSelected catch/finally와 raw 변경 후 예약 콜백에 generation 가드, 새 파일 시작 때 busy 초기화. | 실제 `GpaScenarioBackup.tsx`를 불러오는 브라우저 없는 이벤트 하네스에서 수정 전 `newestPreviewRetained:false`, 수정 후 true. 저장소는 두 경우 모두 변경 없음. |

## 우선 확인할 경계

1. 자체 내보내기 → 가져오기 왕복에서 정상 최대 크기와 JSON 제어문자 이스케이프를 수용하는지 확인한다. 팀 2 MiB·GPA 16 MiB의 파일 읽기 전 제한과 읽은 뒤 실제 크기 검사를 구분한다.
2. 파일 선택은 미리보기만 만들고, 선택 추가 전에 기존 저장 목록이나 현재 작업을 쓰지 않는지 확인한다.
3. 동일 내용의 재수입, 같은 ID의 다른 내용, 다른 제목의 명단을 구분한다. 충돌 복사를 다시 가져올 때는 제외하되, 복사본을 사용자가 편집한 뒤 과거 `importOrigin`만으로 다른 내용을 중복 판정하지 않는지 확인한다.
4. 속성 순서, 허용되지 않은 속성, 중복 ID, 다른 도구 형식, 미래 버전, 잘못된 내부 항목을 검사한다. GPA는 외부 시나리오 ID만 바꾸고 내부 학기·과목 ID 및 전공·재수강·목표를 보존해야 한다.
5. 전체 용량 초과는 부분 저장 없이 거절해야 한다. 선택을 줄인 뒤 동일 미리보기에서 정상 추가할 수 있어야 한다.
6. 파일 읽기 중 새 파일 선택·취소·현재 문맥 변경, 미리보기 후 저장 목록 변경, 잠금 대기 중 취소가 오래된 결과를 반영하지 않아야 한다.
7. quota/read 실패와 원본 비교 충돌이 기존 저장 목록·파일·선택·현재 편성/현재 성적을 보존하는지 확인한다. Web Locks 미지원의 완전한 동시 쓰기 원자성 한계는 별도로 기록한다.

## 독립 실행 증거

```text
node docs/verify/2026-11-16-repeat-batch11/check-independent-domain.ts
Independent team/GPA review: 15 groups passed

node docs/verify/2026-11-16-repeat-batch11/reproduce-gpa-backup-stale.cjs
{"oldImport":"A waiting on lock","newestPreview":"B.json","newestPreviewRetained":true,"storedUnchanged":true}
```

독립 15그룹은 팀 출처·제목·이름 순서·능력치 변경과 원본 재수입, 다른 모임 보존, 특수 이름 키와 임의 필드 제거, 용량 초과의 전체 거부, GPA 외부 ID만 변경 및 내부 과목 ID·전공·재수강·목표 보존, 동등한 시각/속성 순서 정규화, 모든 중첩 레벨의 투영, quota/stale 저장 원본 보존을 확인했다.

코드 경로도 확인했다. 팀 onImported는 저장 목록 선택 UI만 갱신하고 현재 이름·능력치·팀·잠금 상태를 호출하지 않는다. GPA onCommitted는 시나리오 목록을 갱신하며 `gpa-calculator-v2` 자동저장 경로를 호출하지 않는다. 팀의 기존 저장·갱신·삭제와 가져오기는 같은 잠금 키와 CAS/readback을 사용한다. 각 도구는 파일 크기 읽기 전 검사와 실제 UTF-8 크기/스키마 검사를 갖고 있다. 최대 데이터 자체 왕복은 담당자의 기존 도메인 증거(팀 10그룹, GPA 39검사)를 함께 참조하며 같은 검사를 불필요하게 다시 실행하지 않았다.

## 범위와 한계

- 브라우저·다운로드 대화상자·실제 기기 저장 할당량·320px 화면은 독립 브라우저 담당의 결과를 따른다. 이 검토에서는 Chrome을 실행하지 않았다.
- 전체 TypeScript 검사는 통합 담당에게 남겼으며, 빌드·배포·커밋은 실행하지 않았다.
- Web Locks가 없는 환경의 raw 비교/readback은 완전히 동시에 실행되는 별도 탭 쓰기의 원자성을 보장하지 않는다. 이 기존 fallback 한계는 새로 해결됐다고 주장하지 않는다.
