## 공통 사용자 흐름

1. 명시적인 `백업 파일 저장` 버튼으로 저장 목록 전체를 JSON 파일로 내보낸다. 현재 저장 목록이 손상됐거나 읽을 수 없으면 빈 백업을 정상으로 내보내지 않는다.
2. 파일 선택은 검사와 미리보기까지만 한다. `format`(도구별 고유 식별), `version:1`, `exportedAt`, 목록 필드를 가진 자체 백업 형식만 받는다. 파일 크기는 읽기 전 제한(팀2MB·GPA16MB·원고2MB), 실제 JSON 길이/기존 항목 스키마도 검사한다. 한글·제어문자 JSON 이스케이프를 포함한 기존 스키마의 최대 데이터도 자체 내보내기→가져오기 왕복이 가능해야 한다. 타 도구 파일/미래 버전/손상/중복 ID는 기존 저장소를 건드리지 않고 오류를 보여준다.
3. 미리보기에는 각 항목 이름과 요약, 추가/이미 있음/충돌 상태, 선택 체크박스, 기존 개수와 추가 후 개수를 보여준다. 정상 신규 항목은 기본 선택, 동일 ID·동일 내용은 중복으로 선택 불가. 동일 ID·다른 내용은 기본 미선택이며 사용자가 선택하면 **새 ID의 별도 항목으로 추가**한다는 설명을 보여준다. 기존 항목은 교체하지 않는다.
4. 명시적인 `선택한 항목 추가`에서만 저장한다. 용량을 넘으면 선택 수를 줄이도록 알리며 임의로 앞쪽 항목만 저장하지 않는다. 같은 파일을 다시 가져와도 내용이 완전히 같은 기존 항목은 중복으로 설명하고 제외한다(충돌 복사로 새 ID가 된 항목도 포함).
5. 가져온 것은 저장 목록에만 추가한다. 적용은 기존의 불러오기 버튼을 따로 눌러야 한다. 파일 읽는 동안 새 파일 선택/취소/탭 변경/저장소 변경 시 구식 미리보기를 적용하지 않는다.

비교는 속성 순서와 무관한 도구별 정규화 데이터로 한다. 임의 객체 속성을 UI/state/storage로 spread하지 않고 허용 데이터만 투영한다. 내부 GPA 과목 ID는 유지하고 외부 시나리오 ID만 충돌 시 바꾼다. 팀 명단 제목이 겹칠 경우 사용자에게 구분 가능한 이름을 제시하고 길이40자 제한 안에서 복사 접미사를 붙인다. 제목을 자르거나 바꾸는 경우 미리보기에서 최종 이름을 보여준다.

팀 명단의 동일한 구성에 서로 다른 모임 제목을 붙인 기존 항목은 각각 보존한다. 제목을 중복 비교에서 제외해 합치지 않는다. ID/제목 충돌 복사에만 선택적 `importOrigin: { id, title, copyTitle? }`를 검증해 저장하고 백업에도 보존한다. 새 복사에는 복사 당시 최종 제목인 `copyTitle`도 기록한다. 같은 원본을 다시 가져왔는지는 이 출처와 현재 제목·이름 순서·능력치·팀 수·모드를 함께 비교한다. 현재 제목이 복사 당시와 달라진 항목도 새로운 내용으로 취급한다. 사용자가 내용을 바꾼 항목을 출처 ID만 같다는 이유로 같은 내용이라고 간주하지 않는다. 기존 항목에는 이 필드를 임의로 추가하지 않는다.

저장 작업은 해당 도구의 기존 잠금/원본 비교/읽기 확인 패턴을 재사용한다. 팀 명단은 기존 write 경로도 같은 방식으로 조정하여 새 가져오기와 동시에 서로 덮어쓰지 않게 한다. Web Locks가 없는 환경에서는 완전한 탭 간 원자성을 보장하지 않는 한계를 기록한다. quota 실패는 기존 파일/저장 목록/현재 작성 내용을 그대로 둔다.

각 담당은 번역 ko/en 조각·검사 스크립트를 함께 작성한다. 공용 메시지와 메뉴/페이지는 통합 담당만 수정한다. 독립 브라우저에서 실제 다운로드 → 삭제 없는 별도 테스트 저장소 → 가져오기 왕복, 충돌·중복·용량·quota·모바일·현재 작업 보존을 확인한다. 빌드/배포/커밋/푸시는 실행하지 않는다.
