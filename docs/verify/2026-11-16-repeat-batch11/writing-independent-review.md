# 원고 수정본 백업 독립 검토

검토자: gpa_scenarios. 대상: `WritingVersionsBackup.tsx`, `writingVersionsBackup.ts`, `WritingVersionsPanel.tsx` 연결과 `CharacterCounter.tsx`의 기존 복원/실행 취소 경로. 제품 파일은 수정하지 않았다.

## 결과

검토한 범위에서 재현 가능한 새 결함을 발견하지 않았다. 다음 검사는 모두 통과했다.

`node docs/verify/2026-11-16-repeat-batch11/check-writing-independent.cjs` — 실제 제품 컴포넌트를 메모리에서 읽어 이벤트와 지연된 파일 읽기/Web Lock을 실행한 독립 6개 검사:

1. A 파일 읽기가 늦게 완료되어도 새 B 파일 미리보기가 유지된다.
2. 파일 읽기 중 취소하면 늦은 완료가 미리보기를 되살리지 않는다.
3. A 가져오기가 잠금을 기다리는 동안 취소 후 B를 고르면, A 잠금 해제는 저장하지 않고 B 미리보기도 지우지 않는다.
4. 잠금 대기 중 현재 작성 탭을 바꾸면 가져오기를 취소한다.
5. storage 이벤트가 오지 않았어도 실제 원본 바이트가 바뀌면 쓰기 직전 충돌로 거부한다.
6. 명시적 추가는 수정본 키만 한 번 쓰며, 현재 5개 원고의 저장 키와 가져오기 성공 안내를 보존한다.

`node scripts/check-writing-versions-backup.ts`도 독립 실행해 통과했다. 최대 20개/총 300,000자의 한글·이모지·6바이트 JSON 제어문자, 메타데이터 경계, 2 MiB 왕복, 잘못된 형식/버전/중복 ID, 충돌 복사 후 재수입, 용량 전체 거부, quota/원본 충돌을 확인한다.

## 코드 경로 확인

- 파일 선택은 검사와 미리보기만 수행한다. 새 선택·취소·저장 원본/현재 탭/차단 상태 변경은 세대를 바꾼다. 잠금 콜백 전과 완료 후 모두 같은 세대인지 확인한다.
- 충돌 복사는 외부 ID만 바꾸며, 내용 지문은 이름·제목·원고·기준·목표·출처 탭·시각을 포함한다. 같은 ID라는 이유만으로 내용이 다른 원고를 중복으로 취급하지 않는다. 내부 파일의 동일 내용은 미리보기에서 중복으로 분류한다.
- 파서는 허용된 필드만 투영한다. 가져오기 추가 함수와 기존 저장 함수는 변경 전 원본을 비교하며 저장 후 다시 읽는다. 용량 초과를 부분 저장으로 숨기지 않는다.
- 백업의 `onCommitted`는 부모 수정본 목록만 갱신한다. 현재 5개 작성 탭과 실행 취소 상태로 이어지는 `onRestore`는 기존 명시적 복원 확인에서만 호출된다. 백업 경로에 현재 원고/undo setter가 없다.

## 범위와 한계

위 6개 검사는 DOM/React 렌더러를 대체한 이벤트 실행 검사이므로 실제 브라우저 포커스·파일 선택 UI·모바일 표시를 보증하지 않는다. Chrome은 실행하지 않았으며 독립 브라우저 담당의 결과를 별도로 사용한다. 전체 TypeScript·빌드·배포도 실행하지 않았다. Web Locks 미지원 환경에서는 기존 CAS/readback만 사용하므로 완전한 탭 간 원자성은 보장하지 않는다.
