## 추천하는 한 가지 흐름

**뽑힌 메뉴가 오늘 마음에 들지 않거나 식당이 쉬면, 결과의 ‘이번에는 제외’를 눌러 다시 돌리고 나중에 ‘복구’한다.**

현재는 후보 줄을 삭제한 뒤 다시 타이핑하거나, 실제로 먹지 않은 메뉴를 식사 기록에 추가해야 비슷한 효과를 낼 수 있다. 원본 후보를 유지하는 임시 제외 목록과 복구가 없다. 새 흐름은 실제 먹었다는 기록과 오늘 선택을 잠시 미루는 행동을 구분한다.

우선순위는 작은 P1 후보로 제안한다. 한 결과 옆 버튼과 제외 목록으로 동작이 설명되고 기존 룰렛·식사 기록을 재사용할 수 있다. 실제 방문/전환 통계를 조회하지 않았으므로 재방문율이나 매출 향상을 단정하지 않는다.

## 정확한 최소 범위

1. `menuMode`에서 현재 확정 결과에 **‘이번에는 제외’** 버튼을 추가한다. 자동 제외는 하지 않는다. 클릭한 결과의 현재 run ID와 이름을 함께 확인해 옛 결과 버튼이 새 추첨을 수정하지 못하게 한다.
2. 원본 `rouletteItems`를 수정하지 않고 메모리의 `temporaryExcluded`에 메뉴 키를 추가한다. 키 비교는 기존 식사 제외와 같은 **trim 후 문자열 동등성**으로 한다. NFKC/대소문자 접기·유사 메뉴 합치기는 추가하지 않는다.
3. **같은 이름의 모든 줄을 함께 제외**한다. 사용자는 그 메뉴를 피하려는 것이므로 한 줄만 제거한 뒤 같은 메뉴가 다시 나오는 모호함을 피한다. 원본에는 각 중복 줄과 순서를 모두 남기고 복구 시 원래 줄 수·위치대로 돌아온다. UI 안내에 ‘같은 이름의 후보도 함께 제외됩니다’를 포함한다. 예: `[피자, 국수, 피자, 김밥]` → 피자 제외 → `[국수, 김밥]` → 복구 → 원래 4항목.
4. 결과 아래 가까운 위치에 임시 제외 목록·각 메뉴 **복구**·**모두 복구**를 표시한다. 원본 후보 편집 목록에는 제외 이유를 표시해 실제 원본 삭제와 혼동하지 않게 한다. 원본 삭제 버튼의 기존 의미는 유지한다.
5. 새 제외로 **실제 회전 후보가 2항목 미만**이 되면 실행을 막고 이유와 복구 선택을 표시한다. 중복 줄도 기존처럼 별도 회전 항목으로 센다. 예: `[피자, 피자, 국수]`에서 피자 제외는 불가, 국수 제외 뒤 피자 2칸은 기존 의미 그대로다. 0/1개 후보를 자동으로 당첨 처리하지 않는다.
6. 식사 기록의 기존 제외 때문에 이미 후보가 0/1개라면 기존 부족 안내를 유지하고, 임시 제외가 남아 있으면 복구로 되돌릴 수 있게 한다. 임시 복구는 식사 기록 때문에 제외된 메뉴를 강제로 되살리지 않는다.
7. 임시 제외/복구가 실제 후보를 바꾸면 현재 결과·복사/복구 요청은 기존 `clearRouletteResult`로 무효화한다. 기존 최근 추첨 이력은 지우지 않는다. 똑같은 제외·없는 이름 복구 같은 no-op는 새 추첨·history·저장 변경을 만들지 않는다.

## 원본 변경·식사/계획·URL 정책

- **직접 후보 추가/삭제, 명시 프리셋 적용 시 임시 제외를 모두 해제**한다. 동일 프리셋을 명시 선택한 경우도 새 선택 시작으로 보고 해제한다. 비어 있는 입력 제출처럼 아무것도 바꾸지 않은 동작은 해제하지 않는다. 짧은 안내로 후보 변경 시 제외가 풀린다는 사실을 알린다.
- 식사 기록/제외 기간/날짜 경과로 **기존 식사 제외를 적용한 후보 배열이 실제 바뀌면** 임시 제외를 해제한다. 관계없는 날짜 기록 추가처럼 해당 후보 배열이 그대로면 유지한다. 이 기준은 원본 배열+식사 필터 뒤의 값/순서를 비교하며 매 렌더의 새 배열 참조로 초기화하지 않는다.
- 식사 기록 저장은 기존의 ‘오늘 먹은 메뉴로 저장’ 명시 경로에서만 실행한다. 임시 제외/복구는 `toolhub-meals-v1` 및 `toolhub:meal-plan`을 읽거나 쓰지 않는다. 설정 창·저장소 동의·백업/다중 탭 프로토콜을 새로 추가하지 않는다.
- 기존 `wheelItems`를 개념적으로 `mealEligibleItems`(원본+기존 식사 제외)와 실제 회전 `wheelItems`(추가 임시 제외)로 나눈다. **주간 계획의 후보는 기존과 동일한 `mealEligibleItems`**로 유지한다. 이번 추첨에서 싫다고 한 메뉴가 앞으로 일주일 계획까지 자동 제외되지 않게 한다. 주간 계획 파일/수학은 미수정이다.
- 새 정보는 현재 페이지 메모리에만 둔다. 새로고침/이탈 후 임시 제외를 자동 복원하지 않는다. 다른 탭에도 전달하지 않는다.
- 기존 URL의 `roulette`는 원래 후보 목록을 계속 표현한다. 임시 제외·뽑힌 결과는 새 parameter로 넣지 않는다. **링크에는 후보 목록만 담기며 이번 제외는 담기지 않는다**는 안내를 둔다. 기존 comma codec·unrelated query/hash/history.state 유지 동작을 바꾸지 않는다.

## 수명·확률 보존과 접근성

- 제외/복구/직접 후보 변경은 스핀 중 UI disabled와 handler 양쪽에서 막는다. 새 handler는 캡처된 `isSpinning`만 보지 않고 현재 `spinningRef`, mounted, tab/run ID를 확인한다.
- 기존 RAF 회전 시간·이동 각도·당첨 index 수학은 그대로 둔다. 필요 시 현재 `rouletteRunRef`를 spin 시작에 캡처하여 callback에서 확인한다. 완료 뒤 `spinningRef=false` 또는 run 교체된 옛 RAF를 직접 호출해도 과거 결과·이력을 다시 기록하지 않게 하는 최소 수명 guard만 추가한다.
- 복구 후 자동으로 다시 돌리지 않는다. 현재 copy/PNG 결과와 이번 후보가 다르면 기존 결과를 비우고 사용자가 다시 돌린다. 이미 OS에 제출한 Clipboard를 되돌린다고 표현하지 않는다.
- 버튼 최소 44px, 메뉴 이름 줄바꿈, 320px KO/EN에서 수평 넘침 없음. 복구 목록은 실제 button과 명확한 이름(예: ‘피자 복구’)을 쓴다. 키보드 Tab/Enter/Space와 focus-visible을 보장한다.
- 결과의 제외 버튼을 누르면 해당 결과가 사라지므로, 명시 동작 완료 뒤 유효한 ‘돌리기’ 버튼으로 초점을 옮긴다. 복구 버튼이 사라지는 경우도 같은 유효 목표로 복귀한다. locale 변경/날짜 경과·외부 이벤트에서는 초점을 훔치지 않는다. 후보 수 변화는 짧은 `role=status`로 알린다.
- 기존 reduced-motion 클래스·캔버스/결과 안내를 존중한다. 장식 효과/새 애니메이션은 추가하지 않는다.

## 다음 착수 시 검증 계약

1. 순수 모델: 원본 배열 깊은 보존·동일 이름 중복 전체 제외/복구·순서·빈/특수문자/trim 동등성·2항목 하한·no-op·후보 문맥 변경/동일 프리셋 초기화.
2. 실제 부모: 결과→제외→다시 회전→개별/전체 복구, 원래 후보/URL/식사·주간 저장 raw 불변, 결과/복사 경합, 추가/삭제/프리셋/날짜 필터 변경, disabled 우회와 옛 RAF 강제 callback.
3. 기존 경로 회귀: 일반 룰렛 및 order 자동/수동·입력/복사/PNG, 식사 기록 추가/삭제·최근 제외, 주간 빈 날 채우기/직접 원고 보존. 임시 제외만으로 식사 기록이 생기거나 계획 후보가 줄지 않음.
4. native: 한 Chrome 담당이 320px KO/EN, 실제 keyboard/focus, 반복 회전·spin 중 action 차단·이미 제외된 메뉴 복구, 저장 차단 환경에서도 메모리 기능 동작 확인. 실제 사용자 식사 기록을 읽거나 바꾸지 않는 합성 key fixture 사용.
5. 전체 타입은 기존 checkpoint 담당, scoped lint/번역 정적 키 감사는 해당 소유자가 수행. 빌드·배포는 이 기획 승인에 포함되지 않는다.

이번 조사에서는 위 실제 소스·기존12차 주간계획 완료 큐를 읽어 중복을 제외했으며, 제품 실행/MJS probe가 필요할 만큼 불명확한 현재 경로는 없었다. 제안 테스트는 아직 실행 결과가 아니라 다음 구현의 완료 조건이다.
