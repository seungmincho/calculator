## 최소 범위

- 유효한 각 카드 결과에서 `비교에 담기`를 눌러 현재 계산을 페이지 메모리에 최대6개 담는다. 자동 저장·서버·새 route·localStorage는 없다. 새 방문에 남는다고 표현하지 않는다. 상한에서는 기존 항목을 조용히 밀어내지 않고 먼저 제거하도록 안내한다.
- 각 항목은 도구 카드 종류·관련 원본 입력값·당시 소수 자릿수·한글 수 표시·결과 숫자/단위·계산식을 불변 snapshot으로 가진다. 입력이 바뀌어도 담은 결과는 그대로다. 결과 unit은 비율/증감/연속할인 `%`, 퍼센트포인트 `%p`, 그 외 기존 숫자 표시를 보존한다.
- 카드 종류가 달라도 나란히 참고할 수 있으나 서로 다른 종류·기준의 차이나 우열을 자동 계산하지 않는다. 수치로 수익성/합격/추천을 판단하지 않는다.
- 같은 snapshot은 중복 추가하지 않고 이미 담겼음을 알린다. 항목 하나 제거/전체 비우기 제공. 원래8카드 입력·계산·한 줄 질문·5단계 연속 할인·표시 설정·초기화의 기존 의미는 유지한다. 새 비교 목록 비우기와 전체 계산 초기화는 서로 다른 명시 행동이다.
- 전체 비교 내용 복사·TXT 다운로드를 제공한다. 클릭 시 현재 목록 snapshot 전체를 사용하고 preview 일부만 내보내지 않는다. clipboard 거부/legacy false는 성공으로 표시하지 않고 직접 선택·재시도 경로를 제공한다. 기존 카드 숫자 복사와 목록 반출의 늦은 응답이 서로 덮지 않도록 출력 소유권을 통합한다. 선택/입력/표시언어/목록 수정/unmount 뒤 늦은 fallback을 막는다.
- 기존 `percent.ts` 계산식은 변경하지 않는다. 다만 유한한 입력들의 곱/나눗셈이 계산 가능 범위를 넘어 결과가 Infinity/NaN이 되는 경우의 현재 표시 경로를 먼저 probe한다. 실제로0 등 정상 결과로 바뀌면 최소 유효성 guard로 카드 오류를 표시하고 비교 목록·복사에 담지 않는다. 새 임의 금액 상한은 추가하지 않는다.
- 기존 상태→URL 코드가 새로운 query 객체와 null history state를 쓰므로, 이 작업에서 입력/복사 context를 연결할 때 현재 URL의 소유 키만 갱신하고 알 수 없는 query/hash/history state를 보존할 수 있는지 actual-parent probe 후 최소 수정한다. 최초 복원이 기본값을 공유 주소에 쓰거나 사용자 편집을 덮지 않게 한다. 기존 값 키/형식과 URL로8카드 복원은 그대로 지원한다. 새 비교 목록은 URL에 추가하지 않는다.
- 새 패널은 명확한 보조 버튼·44px 이상 터치영역·16px 직접복사필드, 모바일1열/큰화면비교목록을 쓴다. 기존 카드의 관련 버튼·입력도 같은 최소 터치/글자크기를 맞춘다. 디자인 토큰을 사용한다.
