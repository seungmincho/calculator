# TTS·메뉴 룰렛 개선 결과 — 2026-10-25

**상태: 로컬 구현·검증 완료. 미커밋·미배포.** 빌드는 사용자 요청 전 실행하지 않았다.

## 범위와 변경

최근 30일 네이버 자료의 관련 키워드를 합산하면 TTS는 노출 1,833회·클릭 45회, 메뉴 룰렛은 노출 1,213회·클릭 15회다. 이 표는 키워드별 클릭·노출 통계이며 실제 검색 결과 순위로 해석하지 않는다.

- TTS: 입력란 바로 아래에 재생·일시정지·정지 배치, 모바일 입력·버튼 확대, 읽기 화면에서 재생 버튼으로 이동, 키보드로 문장 선택 가능. 클립보드 실패 안내, 저장 설정 검증, 공유 링크의 글·속도 복원 개선.
- 메뉴 룰렛: 검색 제목·H1을 ‘저녁메뉴 추천 룰렛’으로 맞추고 저녁·점심 빠른 선택과 돌리기를 후보 편집보다 먼저 배치. 후보는 직접 편집 가능하고 메뉴 전용 목록에서 벌칙 프리셋은 제외했다. 일반 룰렛에는 유지한다.
- 룰렛 회전: 속도 감쇠로 최소 회전수를 기다리던 방식을 시간 기반 애니메이션으로 변경. 회전 중 후보 변경을 막고 후보가 바뀌면 이전 결과를 지운다. 결과는 돌리기 버튼 근처에서도 확인할 수 있다.
- SEO: 두 페이지의 title·description·OG·Twitter·WebApplication 설명 정렬, OG 이미지와 RSS·메뉴 수정일 갱신. OG 생성기가 메타데이터 상수보다 페이지의 다른 설명을 먼저 고르던 우선순위도 수정했다.
- TTS와 메뉴 룰렛의 한국어·영어 원본 번역 및 생성본 갱신. 공통 결정 도구 이동 메뉴의 터치 높이도 44px로 조정했다.

## 모바일 실측

320px 폭에서 버튼 아래쪽의 위치를 페이지 상단 기준으로 측정했다. 최초 수정 전 측정값은 작업 중 브라우저 출력에서 기록했다.

| 항목 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| TTS 재생 버튼 아래쪽 | 883px | 609px |
| 메뉴 돌리기 버튼 아래쪽 | 1,214px | 556px |
| 메뉴 페이지 가로 너비 | 350px | 320px |

최종 320×740 화면에서 두 버튼 모두 하단 내비게이션 위에 보인다. 375·390·768·1280px와 모바일 다크 모드에서도 가로 넘침이 없고 검사한 주요 버튼·입력 높이는 44px 이상이다.

기존 회전식은 초기 속도 15일 때 감속 후 총 이동량이 약 12.25rad에 그치지만 종료 조건은 최소 3회전(약 18.85rad)을 요구했다. 최소 회전 조건에 도달하지 못하면 종료하지 않았다. 수정 후 4.2초 시점의 프레임에서 종료하며, 난수 0·0.999999 및 실제 무작위 회전을 검증했다. 백그라운드 탭에서는 브라우저의 프레임 제한으로 화면 반영이 늦어질 수 있다.

## 확인 범위와 후속 측정

- 실제 음성 이벤트는 볼륨 0으로 검사했으므로 청감 품질은 판정하지 않았다. iOS Safari·Android 실기기의 키보드·음성 품질·클립보드 권한 UI는 별도 확인이 필요하다. 음성 목록은 기기와 브라우저가 제공한다. [MDN SpeechSynthesis](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis)
- 영어 모드는 공통 내비게이션과 다크 모드 회귀를 확인했다. 기존 도구 번역 로더가 한국어 네임스페이스를 등록하므로 도구 본문의 완전한 영어 전환을 이번 범위에서 구현한 것은 아니다.
- 정적 export 빌드를 실행하지 않았으므로 배포용 HTML·번들 검증은 아직 남아 있다. 개발 서버의 SSR·hydration 검증과 구분한다.
- 배포 이후 같은 키워드 묶음의 노출·클릭·CTR을 2~4주 단위로 비교한다. 이번 수정만으로 검색 순위나 클릭 증가를 보장할 수 없다.

이전에 작업한 택시·택배 수정과 사용자 기존 package.json/lock·.claude·.github 작업은 함께 남아 있다. 커밋·푸시·배포는 수행하지 않았다.
