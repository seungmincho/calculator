상태: 완료(미배포). 작성자 23·독립 16·Chrome 8흐름과09:43:59 KST 전체2GB 타입 재검사·번역/범위lint/diff를 통과했다. [완료 보고서](report.md). 아래 실행 계약과 사전 조사/수정 전 근거는 이력으로 보존한다.

## 확인한 현재 동작

`TextToSpeech.tsx`는 원문을 component state에 두고 voice와 rate/pitch/volume만 localStorage에 보관한다. 원문 공유 URL은1,500자까지, OCR/메모장 전달은sessionStorage30,000자까지다. 새로 방문하면 URL/명시 전달/기본예시에서 시작하며 긴 원고와 읽던 위치를 목록에서 여는 기능은 없다. `chunkText`는 원문 offset을 유지하는 재생 조각을 만들고13차 recovery는 정확한 원문·문장·반복 범위·generation을 대조한다.

## 최소 사용자 경험

- `읽기 목록에 저장`을 누를 때만 이름40자·원문최대30,000 UTF-16·현재 재생 문장 위치·음성 선택/속도/높이/음량·기기 음성만 사용 여부를 캡처한다. 최대8개다. 원문과 위치가 이 브라우저에 저장된다는 한 문장 안내를 버튼 옆에 둔다. 현재 일반 입력의 무상한을 새로 제한하거나 원문을 잘라 저장하지 않는다.
- 저장 위치는 현재 재생/일시정지 문장, 실패 복구가 있으면 그 정확 문장, 아직 읽지 않았으면 첫 문장이다. 반복 재생의 회차/진행을 영속화해 자동으로 이어 돌리지 않는다. 첫 범위는 목록 이름·날짜·문자 수·읽던 문장 번호/짧은 미리보기·명시 열기·삭제다.
- `원고 열기`는 선택한 원문과 설정/위치만 복원하고 자동 발화하지 않는다. 현재 원고를 바꾼다는 뜻을 버튼/설명으로 분명하게 한다. 사용자의 재생 클릭이 저장 위치부터 시작하게 한다. 기존 반복은 끄고 이전 실패 복구·발화/대기 timer를 무효화한다. 삭제는 지금 열어 둔 원문/재생을 지우지 않는다.
- 저장된 voice가 현재 기기에 없으면 현재 기기에서 사용할 수 있는 음성으로 선택하도록 알린다. 저장한 `기기 음성만` 조건은 보존하고, 이를 만족하는 음성이 없을 때 원격 음성으로 몰래 바꾸지 않는다. 실제 음질/OS 동작을 보장한다고 설명하지 않는다.
- 원문을 정확 보존하고 문장의 start/end/text를 다시 검증한다. 나중에 분리 규칙이 바뀌어 위치가 일치하지 않으면 임의로 가장 가까운 다른 문장을 읽지 않는다. 원고는 열되 첫 문장부터 다시 선택하도록 안내한다. 기존13차 복구와 새 목록은 저장 시점/실행 세대가 다르므로 서로의 token을 재활용하지 않는다.
- 새 목록은 초기0쓰기·버전/구조/중복ID/정확 범위 검증·Web Locks/CAS/readback을 따른다. 손상/미지원/raw 초과는 원문 보존·쓰기 차단, 현재 TTS는 사용 가능하게 한다. 같은 목록의 다른 탭 변경은 명시 재조회하며 현재 입력/읽기를 바꾸지 않는다. 저장 실패/확인 불명은 성공 표시나 rollback으로 숨기지 않는다.
- 데이터는 URL/서버/analytics에 자동으로 보내지 않는다. URL/전달 진입을 저장 목록이 덮거나 자동 목록 추가하지 않는다. JSON백업/발음사전/새 음성모델은 이 첫 범위에 넣지 않는다.

## 준비·검증

제품 담당은 TextToSpeech의 원고 교체/재생 시작 경계, 신규 TtsReadingList와 ttsReadingRecords 순수 모듈, KO/EN fragment를 함께 쓴다. canonical/가이드/메타/updatedDate는 통합 담당 소유다. 신규 raw 보호 예산은2MiB를 제안하며8개×30,000자·JSON escape·설정/이름/위치의 실제 serializer 상한을 합성 측정해 자체 저장 왕복을 먼저 검증한다.

순수 검사는 정확 원문/offset/한도/음성 조건/잘못된 문장 위치·저장 충돌·확인 불명을 포함한다. 실제 부모는 읽는 중 저장/열기, 실패 후 저장, old utterance onend/onerror/onboundary, 반복 대기, 편집/URL/전달 초기 우선, localVoicesOnly·음성 없는 기기·locale를 확인한다. 기존13차 회귀는 변경된 경계에 한해 적용한다. 브라우저는 SpeechSynthesis 제어 포트와 native 저장/Clipboard/키보드/320 KOEN을 구분하며 실제 마이크·실제 개인 원고·원격 음성 전송을 시험하지 않는다. 범위lint·번역·전체타입·독립 검토 뒤 완료 판정한다.

이 후보는 긴 글을 다시 붙여 넣고 문장을 찾는 반복을 줄이려는 기능 제안이며 실제 이용 통계 기반의 수요 검증은 아니다.

## 합성 준비 관측

`measure-reading-records.mjs`는 JSON escape가 많은30,000 UTF-16 원문8개와 제안 위치/설정 wrapper를 메모리에서 만들었다.1,445,817 UTF-8bytes로2MiB 제안 예산 안에서 정확 왕복했다. 실제 voiceName 상한/타임스탬프 등 최종 schema가 아직 없으므로 모든 유효 기록의 엄밀한 최대 크기를 증명한 것은 아니다. 실제 저장소/개인 원고는 읽지 않았고 결과는 [측정 JSON](preparation-measurements.json)에 있다.

같은 읽기 조사에서 기존 chunkText가139개 ASCII 뒤의 emoji surrogate pair를140번 위치에서 둘로 나누는 사실을 확인했다. 전체 조각을 이어 붙이면 원문은 같지만 각 발화 조각은 고립 surrogate로 끝/시작한다.46 구현 시 원문 offset을 보존하면서 정상 code point 경계를 유지하는 최소 보완을 별도 회귀와 함께 검토한다. 기존 public max 인수의 아주 작은 값/진행 보장과 meetingHandoff 사용처를 확인하고, 모든 grapheme cluster 또는 실제 OS 발음을 해결했다고 확대하지 않는다. 지금은 재현만 완료했고 제품 코드는 수정하지 않았다.
