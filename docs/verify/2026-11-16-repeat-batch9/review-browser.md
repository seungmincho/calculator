# 9차 독립 브라우저 검증

기존 개발 서버 3039와 Chrome 한 개를 순차 사용한다. 제품 코드·의존성은 수정하지 않는다. 서비스 워커와 외부 요청은 차단한다. 8차 전체 타입 검사 종료 후 시작한다.

| 대상 | 계획 |
| --- | --- |
| 연속 타이머 | 단계·반복·일시정지·재개·건너뛰기·완료 1회, 300초 백그라운드 경과, 알림 함수 호출 횟수/음소거, 기존 타이머·스톱워치 동시 실행 차단과 키보드, 저장 실패·재방문·손상 원본, 320px 다크 |
| 단위 고정 | 값 유지하며 변환 쌍/정밀도/rem 복원, 이름 변경/삭제, URL 우선권, 비선형 온도·연비, 저장 오류·두 탭, 320px 다크 |
| 여러 QR | 실제 PNG ZIP 안 고유 이름·행순서·서로 다른 원문 독립 디코딩, 오류 행 전체 중단·수정·취소·오래된 결과 차단, 기존 단일 QR, 320px 다크 |

QR 디코더는 [공식 README](https://github.com/cozmo/jsQR/blob/master/README.md)의 브라우저 RGBA 입력 API와 [공식 package.json](https://raw.githubusercontent.com/cozmo/jsQR/master/package.json)의 1.4.0 버전을 확인했다. 공식 GitHub Releases에는 배포 기록이 없으므로 릴리즈 검증으로 주장하지 않는다. 필요 시 정확히 `https://cdn.jsdelivr.net/npm/jsqr@1.4.0/dist/jsQR.js` 요청만 검증 컨텍스트에서 허용하고 검증용 생성 QR만 읽는다. npm 설치·실사용자 데이터 접근은 하지 않는다.

## 결과

최종 **13/13 PASS**, JavaScript·hydration 오류 **0**. Chrome은 종료했다. `browser/final-results.json`은 각 시나리오의 최신 결과와 원본 실행 파일을 가리킨다.

| 대상 | 통과 | 확인 결과 |
| --- | ---: | --- |
| 연속 타이머 | 5 | 단계/회차 이동, 일시정지 시간 불변, 계속/다음 단계/초기화, 완료 중복 없음. 300초 경과를 한 번에 진행해 현재 단계·잔여 시간 복원. Web Audio oscillator 호출 관찰로 경계당 기존 3음 신호 1회, 여러 경계 건너뛴 복귀도 1회, skip/음소거는 호출 0. 기존 타이머·스톱워치 동시 실행 차단, 내부 Space/Enter 동작, 기존 랩 기록. 프로필 load·quota·손상·재방문 수동 시작, 320px 다크. |

검증 환경 Chrome에는 `BarcodeDetector`가 없었다. 허용한 외부 요청은 고정 jsQR 파일 한 개이며, 테스트 컨텍스트에서 생성한 PNG만 읽었다. 디코딩 증거와 API 가용성은 `browser/qr-independent-decoded.json`, 실제 파일은 `qr-three.zip`, `qr-001-same.png`부터 `qr-003-CON.png`, `single-wifi.png`, `single-vcard.png`이다. 원문이 주소나 localStorage에 기록되지 않는 것도 확인했다.

이번 브라우저 검사에서 추가 제품 결함은 확인되지 않았다. 초기 실패는 비동기 루틴 불러오기 대기, 단위 분류의 `tab` 역할, 반복 입력 후 textarea 선택자, 기존 Wi-Fi `H:false` 및 vCard `TYPE=CELL` 직렬화 기대값 등 테스트 조건을 고쳐 해결했다. 수정한 사례만 재실행했으며 원본 실패 기록은 보존했다.

모바일 증거는 각 `*-320-dark-panel.png`, `*-320-dark-top.png`와 긴 단위/QR 패널의 `*-320-dark-detail.png`이다. 가로 넘침이 없었으며 이미지 파일을 직접 열어 확인했다. 긴 요소 전체 캡처에 고정 헤더가 끼어드는 촬영 현상을 줄이기 위해 실제 viewport와 개별 결과 카드를 사용했다.

ko/en 추가 키 구조를 대조했고 `language=en` 설정에서 기능과 원시 번역 키 노출을 검사했다. 한국어 전용 공통 번역 런타임 제약으로 실제 영어 UI 전환을 통과했다고 주장하지 않는다. 타이머는 Playwright Clock으로 시간 경과를 제어하고 실제 Web Audio API 호출을 관찰했으며 OS 스피커 음향과 실기기 백그라운드 정책은 별도 검증하지 않았다. 저장소/다운로드 실패는 API 수준으로 주입했다. 제품 의존성 추가, build/dev 재시작, 배포, git 명령은 실행하지 않았다.
