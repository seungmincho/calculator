# 멀티 에이전트 실험 기록

사용자 요청: 남은 사용량을 활용해 멀티 에이전트 병렬 개발을 경험하고, 다음에도 활용할 수 있게 한다.

2026-11-16 21:53 KST에 공통 계약을 작성한 뒤 작업 에이전트 4명과 통합 담당 1명으로 시작했다. 각 에이전트는 같은 저장소를 공유한다. 모델을 바꾸거나 새 사용자 채팅을 만들지 않았다.

| 역할 | 병렬 작업 | 직접 수정하는 영역 |
|---|---|---|
| domain | 전달 형식·날짜 검증·기존 데이터 파싱·중복 방지·순수 로직 검증 | 새 데이터 유틸과 단위 검사 |
| meeting_ui | 회의록 할 일 선택·기본 정보 확인·원본 ID 저장·새 탭 전달 | 회의록 화면과 본인이 작성한 번역 조각 |
| kanban_ui | 회의 전용 열/기존 열로 가져오기·담당자·모바일 이동·저장 오류 처리 | 칸반 화면과 본인이 작성한 번역 조각 |
| verification | 독립 리뷰·실제 사용자 흐름 검증·문제 재현 | 브라우저 검사와 리뷰 기록 |
| root | API·범위 조정·번역 병합·메타데이터·전체 타입 검사·회귀·완료 판단 | 공용 번역 원본·설정·최종 문서 |

## 시작 전에 정한 것

- [공통 API와 제약](contract.md)을 먼저 고정했다. 서로의 구현이 끝날 때까지 기다리지 않고 같은 이름과 자료형으로 작업할 수 있게 했다.
- 각 UI 담당자가 해당 번역도 작성한다. 공용 ko/en JSON을 동시에 수정하지 않도록 조각을 넘기고 root만 병합한다.
- 원래 있던 작업 중 변경을 보호하며, 같은 제품 파일의 수정 소유자는 한 명으로 제한한다. 리뷰 담당은 수정 대신 재현 조건과 영향을 구현 담당자에게 보낸다.
- 각 담당자는 자기 범위 lint·로직을 검사한다. 전체 타입 검사는 통합 담당이 실행해 같은 무거운 검사를 여러 프로세스가 동시에 돌리지 않게 한다.
- 완료 판단은 코드 제출이 아니라 기존 기능 보존, 새 기능 검증, 통합된 상태의 검사 결과를 기준으로 한다.

## 기록의 한계

실제 중간 결정·발견 사항과 최종 결과는 `review.md`와 `report.md`에 남긴다. 한 에이전트로 같은 일을 한 대조 실행이 없으므로 속도 향상 배수를 계산하지 않는다. 사용량·쿠폰 잔액 API도 없으므로 한도 소모량이나 쿠폰 사용을 추정하지 않는다. 병렬 작업 자체의 토큰과 전달·리뷰 비용은 생기지만, 이번 실행은 실제 기능과 검증에만 사용한다.

## 이번 실행의 결과

약 12분 동안 계약 작성부터 16개 신규 브라우저 검증과 전체 타입·린트 통과까지 진행했다(21:53→22:05 KST, 문서 마무리 시간 제외). 완료된 meeting_ui 담당자에게 ID 생명주기 교차 리뷰를 맡겨 구형 자동저장본과 명명 저장본 사이의 중복 문제를 찾았다. 구현 담당자가 보완하고 독립 검증자가 해당 재현 흐름을 검증했다. 기능·제한·증거는 [최종 보고서](report.md)에 정리했다.
