# 회의록 → 칸반 독립 검증

## 검증 범위

- 실제 Chrome + localhost 개발 서버에서 사용자 클릭 → 새 탭 → 선택 확인 → 저장 → 편집 → 재로드 → 재전달을 검증한다.
- 실제 탭 두 개를 사용하여 다른 탭의 최신 카드가 보호되는지 확인한다.
- v1 JSON 파일을 실제 파일 입력과 다운로드로 왕복 검증하고 빈 보드 저장도 확인한다.
- 320px 다크 모드에서 가져오기 패널, 눈에 보이는 카드 편집과 열 이동, 본문 가로 넘침을 확인한다.
- 저장 용량 부족은 브라우저의 `Storage.setItem`에 `QuotaExceededError`를 주입한다. 팝업 차단은 `window.open` 반환값을 `null`로 대체한다. 실제 디스크 용량 부족/브라우저 팝업 설정을 바꾼 검증은 아니다.
- 손상·신규 버전 보드와 만료된 전달은 저장소에 테스트 fixture를 준비한다. 테스트 fixture 준비 외의 보드 변경과 새 탭 전달은 제품 UI를 거친다.
- 외부 네트워크 요청은 차단하며 JavaScript 예외와 hydration 오류를 모은다. 외부 분석·광고 기능, 실제 배포본/static export, Safari·Firefox·실물 터치 기기는 검증 범위 밖이다.
- 빌드·배포·커밋은 실행하지 않는다.

## 실행

`node scripts/check-meeting-kanban-browser.mjs` (전체), 마지막 인자로 시나리오 이름 일부를 지정하면 해당 시나리오만 실행한다.

실행 전 UI 번역 원본 병합과 생성을 완료한다. 결과는 `browser/results.json`, 실패 화면과 주요 모바일 화면은 같은 폴더에 저장한다. `!legacy`처럼 `!`로 시작하는 인자는 해당 이름을 제외한다.

## 리뷰 메모

- 기존 칸반 코드에는 모달 라벨과 입력 연결이 없고 카드 편집 조작이 hover 전용이었다. 구현 담당에게 전달한 뒤 최종 UI에서 연결된 라벨, 상시 편집 버튼, 44px 열 이동을 확인했다.
- TTL 안내 문구의 '10분 안에 추가'는 최초 전달 읽기만 10분이라는 최종 계약과 달랐다. 담당자가 시간 제한 문구를 수정했다.
- UI 날짜 검증과 도메인의 연도 0 거부 조건, 중복 action ID 거부 경계를 담당자와 대조했다. 최종 UI/파서에서 동일하게 거부한다.
- root가 발견한 구형 저장 슬롯 ID 승계 경계를 별도 시나리오로 검증했다.
- 독립 검증 완료 시점에 해결되지 않은 제품 결함은 발견하지 못했다.
- 다른 탭 보호는 localStorage 읽기/쓰기 비교와 storage 이벤트 기반이다. 동시에 같은 순간에 쓰는 두 저장을 데이터베이스 트랜잭션처럼 원자적으로 잠그는 보장은 이번 범위에 포함되지 않는다.
