## 실행 결과

최종 **19/19 통과**, JavaScript 예외 0, hydration 오류 0. `browser/final-results.json`이 각 시나리오의 최종 실행 결과와 원본 실행 파일을 연결한다. 브라우저는 실행마다 하나만 띄웠고 컨텍스트를 순차로 닫은 뒤 최종 브라우저도 종료했다. 빌드·개발 서버 재시작·전체 타입 검사·git 작업은 하지 않았다.

- 택시: 거리·수동 시간·지역·요금·URL 복원, 이름 변경·삭제, 재방문, 자동 시간 재계산, 저장 스냅샷 불변을 확인했다.
- 학점: 재수강 전 성적 제외·P/NP·전공을 포함한 독립 fixture에서 누적 4.20/4.5, 변경 후 4.00/4.5와 차이 -0.20을 확인했다. 복원 시 전체 학기·과목·목표가 일치하고 공유 링크에서는 개인 자동 저장 바이트가 변하지 않았다.
- 글자 수: 원고·제목·목표·기준 저장/복원, 비교 본문, 다른 문항 복원과 전체 설정 되돌리기를 확인했다.
- 세 도구 모두 할당량 실패에서 기존 저장값과 입력/이름을 보존하고 복구 후 재시도했다. 손상 JSON·미지원 버전은 그대로 유지되며 저장을 차단한다.
- 세 도구 모두 실제 Web Lock을 잠시 잡은 상태에서 두 탭의 저장 UI를 실행한 후 잠금을 풀었다. 첫 번째 저장만 성공하고 다른 탭은 충돌을 표시했으며, 목록을 다시 읽고 재시도한 뒤 세 기록이 모두 남았다.
- 320px 다크 스크린샷 세 장을 직접 확인했고 페이지 가로 넘침은 없었다. 스크린샷은 `taxi-320-dark-en.png`, `gpa-320-dark-en.png`, `writing-320-dark-en.png`다.

## 리뷰와 검증 중 수정

독립 코드 리뷰에서 글자 수 저장의 read/compare/write가 서로 다른 탭에서 겹치면 둘 다 성공할 수 있음을 발견했다. 구현 담당이 수정본 저장·삭제와 기존 원고 자동 저장·초기화를 Web Locks로 직렬화했다. 이후 호환성 결정에 따라 잠금 미지원 환경은 raw 비교와 쓰기 후 readback을 유지하는 fallback으로 변경했고, 이 경로의 원고 자동 저장·수정본 저장·재방문 복원이 추가 통과했다. **Web Locks 미지원 환경의 완전한 동시 쓰기 원자성까지 보장하지는 않는다.** Chrome 잠금 지원 환경의 실제 동시 저장 경합은 통과했다. 제품 파일은 검증 담당이 수정하지 않았다.

초기 학점 실패는 검증 코드의 select 라벨 완전 일치 선택과 자동 저장/공유 링크 hydration 대기 누락이었다. 선택 상자 역할 및 실제 저장/입력 상태를 기다리도록 스크립트를 수정했다. 실패 캡처가 hydration 전에 caret 스타일을 바꾸며 유발한 경고도 확인했고 캡처에 `caret: 'initial'`을 적용했다. 최종 재실행에는 이 오류가 없다. 기본 sandbox의 로컬 네트워크 차단은 자동 승인된 확장 권한 실행으로 해결했다.

## 검증 범위의 한계

공통 `src/lib/i18n.ts`는 한국어 정적 레지스트리만 렌더링한다. 따라서 `language=en` 상태에서 기능 유지 및 신규 ko/en 키 구조 일치를 확인했으며 **실제 영어 UI 전환을 검증한 것은 아니다**. 외부 요청과 서비스 워커는 차단했고, 개발 서버에서 실행했으므로 빌드 산출물·운영 배포 검증은 포함하지 않는다. 택시의 짧은 조건 프리셋은 요약과 명시적 불러오기 버튼을 확인했으며 별도 교체 확인창은 제품 결정상 요구하지 않는다.
