## PDF 페이지 정리

1. 고유 ASCII 문구·각기 다른 크기·원회전90/180/270을 가진 실제3페이지 PDF를 생성한다. UI 이동/회전/삭제→undo/redo→실제 출력 PDF를 독립 재읽기해 내용 순서·크기·원회전+추가회전을 확인한다. 출력 후 새 편집은 이전 결과를 무효화한다.
2. 30개 이력 한도·no-op·undo 뒤 새 분기·전체 reset도 한 전이·전체 삭제 복구, Ctrl/⌘+Z·Shift+Z·Ctrl+Y 및 카드/이력 버튼의 실제 초점을 확인한다. 편집 입력의 native undo·IME 이벤트 제외도 검사한다.
3. 잘못된 새 PDF 읽기는 현재 문서·카드·이력을 유지한다. File.arrayBuffer의 완료를 제어해 A→B 역순 읽기, 탭 이동/이탈 뒤 늦은 완료가 기존 입력을 덮지 않는지 확인한다.
4. 클릭 당시 반출 snapshot과 작업 세대: 처리 중 편집/탭 전환/새 작업 뒤 늦은 결과·자동 다운로드 차단. 실제 연산 성공 파일과 지연 Promise 경계는 구분한다.
5. 공통 guard 영향을 받은 병합·분할·이미지PDF를 실제 파일로 최소 회귀한다. PDF 페이지 내용·개수/크기, ZIP 파일별 내용·고유 이름, 이미지 XObject 존재를 독립 확인한다. 이전 배치 전체 검사를 반복하지 않는다.
6. 320px 다크 KO/EN에서 undo/redo·카드 조작44px·새 문서 입력/키보드·가로폭·원시 번역 키/JS/hydration을 확인한다.

## 비밀번호 결과별 재생성

7. 일반/PIN/단어 조합의 각 설정을 실제 UI로 적용하고 한 위치 재생성 뒤 나머지 값이 그대로인지, 해당 버튼 DOM과 초점이 유지되는지 확인한다. 현재 난수 API가 호출되었는지 관찰하되 우연히 같은 결과를 오류로 취급하지 않는다.
8. 무효 옵션·옵션 수정·전체 재생성 및 앱 언어 전환/강도 입력 보존. 생성값/강도 입력을 URL·local/sessionStorage·요청·콘솔에 추가하지 않는지 검사한다. 증거 JSON/테스트 로그에는 생성 원문 대신 개수·길이·동일성 여부만 기록한다.
9. 실제 native Clipboard 개별/전체 현재값 복사, API 없음/reject+legacy false 실패·readonly 수동 선택·재시도/닫기·legacy true 성공을 검사한다. 실패에서 성공 체크가 보이지 않아야 한다.
10. 복사 pending 중 한 항목/전체 재생성·설정 변경·탭 전환·이탈, 다른 복사 뒤 늦은 resolve/reject·오래된 안내 timer를 제어해 stale 안내/복구/fallback을 차단하는지 확인한다. OS에 이미 전달한 쓰기의 취소로 표현하지 않는다.
11. 320px 다크 KO/EN에서 긴 결과 줄바꿈·한 항목 버튼44px·복구16px·키보드 탭과 실제 초점·번역 키/JS/hydration을 확인한다. 캡처에는 검증용 결과 값과 복구 원문을 마스킹한다.

제품 결함은 담당자에게 재현과 함께 전달하고 해당 영향만 재검사한다. 검증 코드 오류와 제품 오류를 구분한다. 최종 Chrome 종료 뒤 통합 담당에게 전체 타입 검사 가능 신호를 보낸다.
