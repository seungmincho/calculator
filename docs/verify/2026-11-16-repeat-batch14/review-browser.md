# 14차 독립 브라우저 검증

저장한 글꼴 스타일 조합의 실제 UI 흐름을 기존3039 서버·단일 Chrome에서 순차 확인한다. 제품 파일을 수정하지 않으며 발견한 결함은 구현 담당에게 전달한다. 번역 생성과 구현 ready 뒤 실행한다.

| 흐름 | 검증 범위 |
| --- | --- |
| 저장·사용 | 현재 스타일 저장, 새 방문 목록 유지/자동 적용 없음, 명시 불러오기 시 현재 제목·본문 유지, 명시 삭제 |
| 경계·보호 | 이름40자·최대6개, 손상/미래버전/불량 ID·범위 원본 보존, quota·저장소 읽기 차단·두 탭 충돌과 다시 읽기 |
| 기존 기능 | 공유 URL 초기 복원, 저장 스타일 우선 적용과 현재 원고 유지, CSS/링크 복사, 접기/재열기 draft, 기존 카탈로그 핀·즐겨찾기 |
| 폰트·화면 | 저장 스타일 변경 뒤 오래된 로드 결과 무시, 선택한2개 실제 폰트의 허용된 CSS/바이너리 로드,320px 다크·16px 필드·44px 버튼·JS/hydration |

대부분의 시나리오는 외부 요청을 차단한다. 실제 폰트 확인1건만6차 방식의 제한 목록을 사용하며 Noto Serif KR/Nanum Gothic CSS와 그 CSS에서 확인한 fonts.gstatic.com 파일만 허용한다. 공개 검증 문구만 사용한다. 로드 세대 경합은 별도 API mock으로 제어하며 실제 폰트 로드 증거와 구분한다. ko/en 키 구조와 language=en 상태를 확인하지만 기존 공통 한국어 전용 레지스트리의 영어 UI 전환을 검증했다고 보고하지 않는다.

2026-11-17 KST, 실제 Chrome에서 **8/8 PASS**. JavaScript 예외·hydration 오류0. 브라우저를 정상 종료하고 공용 통합 담당에게 최종 타입 검사 가능 시점을 알렸다. 브라우저 검사 중 제품 파일은 수정하지 않았다.

첫 실행6/8에서 공유 URL 관련2건은 테스트 helper가 `pair=1` URL의 자동 열림과 동시에 열기 버튼을 클릭해 패널을 다시 접으면서 시간 초과가 났다. 기존6차와 같이 URL 자동 열림을 기다리고, 접은 뒤 수동 재열기는 명시 클릭하도록 테스트만 수정했다. 영향받은2건만 재실행해 통과했다. 기본 저장 목록이 열린 상태라는 실제 DOM assertion도 포함했다. 초기 실패 기록은 보존했다.

320px 다크 패널·긴 이름 상세와 실제 폰트 미리보기 캡처를 직접 검토했다. 제목/설명/입력/조작 버튼을 읽을 수 있고 가로 넘침이 없다. ko/en 추가 번역 구조와 language=en 저장 상태의 기능을 확인했지만 기존 한국어 전용 레지스트리의 실제 영어 UI 전환 통과를 의미하지 않는다.

증거: `browser/final-results.json`, `style-profile-without-manuscript.json`, `restored-profile.css`, `restored-style-font-network.json`, `font-profiles-320-dark-panel.png`, `font-profiles-320-dark-detail.png`, `font-profiles-320-dark-top.png`, `restored-style-real-fonts-preview.png`. 실행 스크립트는 `scripts/check-repeat-batch14-browser.mjs`다.

검증 한계: 실제 웹폰트는 지정한2개 family와 검증 문구에 한정한다. 전체 카탈로그·모바일 실기기·로컬 폰트 파일·정적 빌드·배포는 검사하지 않았다. Web Locks 미지원 환경의 완전 동시 쓰기 원자성을 보장한다고 주장하지 않는다. 외부로 전송된 문구는 기본 공개 예시와 검증용 ToolHub/Public font verification뿐이며 사용자 원고는 사용하지 않았다.
