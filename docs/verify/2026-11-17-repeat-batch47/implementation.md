# 47차 선택 병합 — 부모 연결

2026-11-17. 기존 문서 비교의 마지막 성공 결과에서 변경 구간별 원본/수정본을 선택해 별도 문서를 만든다. 두 입력 원문은 그대로 두고, 전체 병합 문서 복사와 TXT 다운로드를 제공한다. 예제부터 모두 원본 유지 상태로 표시한다.

## 동작

- 성공 비교마다 새 문서 id와 기본 선택을 함께 적용한다. 편집/교환/실패/취소 중에는 이전 성공 문서와 선택을 유지하며 현재 입력과 다르면 이전 비교 안내를 표시한다. 초기화·원고 전달 적용은 예제/이전 병합을 함께 정리한다.
- 실제 Worker client가 요청 원문과 응답의 모든 내용·줄 번호·수량을 대조한다. 구조만 정상인 다른 문서 응답이나 빠진 끝 빈 줄을 성공으로 적용하지 않는다. 기존 작업량·입력 한도, timeout·terminate·취소는 유지한다.
- 부모는 실제 문서/결과 객체와 언어별 출력 context의 동일성을 검사한다. 같은 내용 재비교, KO→EN→KO, 입력/선택 변경과 늦은 clipboard fallback이 현재 결과를 건드리지 않는다.
- 비교 표시 텍스트와 병합 문서의 복사/TXT는 공용 출력 owner를 쓴다. 실패 복구는 누른 버튼 가까이에 표시하며 전체 원문은 사용자가 직접 열어 선택할 때만 textarea에 넣는다. 수동 선택·다시 복사·닫기를 지원한다.
- 선택 블록 6개/페이지, 병합 미리보기 200줄/페이지와 문자 한도를 사용한다. 전체 출력은 최대 2MiB·20,000줄, 끝 줄바꿈/빈 줄 보존 및 LF 정규화다. 빈 문서 복사·0바이트 TXT는 명시적으로 안내한다.
- writing versions의 전달 소비/편집 취소를 유지하고 자동 비교는 하지 않는다. 새 저장 키·원문 포함 URL·모델·서버·새 경로는 추가하지 않았다.

독립 부모 검사에서 pending 전달 timer 전에 병합 선택 또는 비교/병합 복사·TXT를 누르면 늦은 전달이 결과를 지우고 payload를 소비하는 5동선을 재현했다. 현재 문서/출력 context 검사 뒤 기존 `userAction()`으로 전달을 취소하도록 3개 handler를 최소 보완했다. 수정 전 제어 포트 근거는 `independent-parent-handoff-before-fix.json`에 보존했다. 실제 브라우저 발생 증거와는 구분한다. 기존 작성자 전달 영향1은 재통과했고 수정한 부모 lint도 오류·경고0이다.

`check-line-merge-parent.mjs`는 실제 부모·실제 client와 제어 Worker/clipboard/download 포트를 실행한다. 새 성공만 선택 초기화, 내용이 틀린 정상형 응답 거부, 600행/정확히 2MiB 전체 출력, copy/TXT 6방향 소유권 경합, 입력/선택/재비교/언어 ABA/replay/unmount, 전체 복구와 토큰, 같은 원문 재비교의 옛 핸들러, 빈 문서, 전달 consume/dirty 취소를 확인했다. 실제 브라우저 증거로 집계하지 않는다.

부모 독립8 + core/output9 = **독립17그룹 PASS**, 해당 검사 lint0이다. 위 pending 전달 P2의5동선과 수신 중 두 번째 storage 읽기에서 시작한 선택까지 원문/현재 결과를 보존함을 확인했다.

native 뒤 한국어 조사 오류 `병합 문서을`을 없애기 위해 copied/failed2문구를 정밀화했다. 키/placeholder/제품TS는 그대로이고 canonical 정적107사용·생성check1578만 영향 확인했으며 native 집계를 더하지 않았다. 최종 전체 타입은 연결한 다른 기능들과 묶어 수행할 예정이며 아직 통과로 기록하지 않는다.
