# 47차 문서 비교 선택 병합 — 미연결 준비

2026-11-17. 기존 `/diff-viewer/` 안에서 비교가 끝난 두 문서의 변경 구간을 골라 병합한다. 새 도구·새 저장 키·원문 URL·원문 자동 덮어쓰기는 없다.

## 구현 범위

- `src/utils/lineMerge.ts`: 요청 원문과 비교 응답의 내용·줄 번호·수량을 대조한다. 연속 추가/삭제 구간을 하나의 선택 단위로 만들고 기본값은 모두 원본 유지다. 변경 구간마다 원본/수정본 한쪽을 택하며 LF로 정규화한 끝 줄바꿈·빈 줄을 보존한다. 팩토리에서 만든 문서/결과만 사용하며 중첩 배열까지 불변으로 유지한다.
- 최대 출력 2MiB·20,000줄. 입력 제한은 기존 한쪽 1MiB·10,000줄·4M DP cells를 유지한다. 미리보기는 페이지당 200줄·50,000 UTF-16 문자, 한 줄 2,000 문자다. 표시만 줄이며 복사/TXT 전체 문서는 자르지 않는다.
- `src/lib/diff/output.ts`: 비교 표시 텍스트와 병합 문서의 복사/TXT를 같은 출력 소유자로 관리한다. 기존 공용 클립보드/다운로드 유틸을 사용하고 이전 작업의 늦은 fallback·알림·닫기를 차단한다. 빈 문서 복사와 0바이트 TXT도 명시적 행동으로 지원한다.
- `LineMergePanel.tsx`: 변경 구간 6개씩, 병합 결과 200줄씩 탐색. 라디오 선택·모두 원본/수정본·이전 비교 안내·전체 복사/TXT 동작. 콜백은 실제 문서/결과 객체를 전달하므로 부모에서 객체 동일성으로 마지막 결과를 확인할 수 있다.
- `DiffCopyRecovery.tsx`: 실패한 전체 내용을 사용자가 열었을 때만 textarea에 넣는다. 전체 선택 실패 안내·재시도·닫기, 이전 토큰의 펼침/오류를 새 출력으로 넘기지 않는다.
- `translations-line-merge.json`: 두 자식과 부모 연결에 필요한 KO/EN 조각. 아직 canonical에는 병합하지 않았다.

## 다음 부모 연결 경계

1. `TextDiffWorkspace`의 성공 결과마다 단조 증가 id로 `prepareLineMerge`를 만들고 원문/선택/출력을 함께 교체한다. 새 성공만 선택 초기화. 비교 실패·취소·입력 변경 중에는 마지막 성공 결과와 선택을 유지하고 이전 비교임을 표시한다.
2. Worker 응답은 구조 검사뿐 아니라 요청 원문 대조도 통과해야 성공으로 취급한다. 실제 브라우저에서 잘못된 Worker 응답이 발생했다는 주장은 하지 않는다.
3. 출력 전체가 하나의 owner를 공유하게 연결한다. 원문·선택·언어·새 비교·초기화·전달 문서 변경·unmount 시 작업을 무효화한다. 오래된 문서/결과 객체의 클릭 콜백을 부모에서 차단한다.
4. 초기화·writing versions 전달 교체 시 병합 상태도 정리한다. 전달 문서의 dirty/cancel/consume·자동 Worker 실행 없음은 기존 동작을 유지한다.
5. 기존 비교 200행 페이지·표시 방식·전체 비교 표시 복사/TXT·문자수·오류는 유지한다. 제품 부모 검사 → 독립 검사 → canonical 생성/audit → 실제 Chrome KO/EN 320px·전체 파일/클립보드 → 동결 후 전체 타입 검사 순서로 완료한다.
