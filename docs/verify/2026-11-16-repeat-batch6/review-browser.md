# 6차 독립 브라우저 검증

기존 개발 서버 `http://127.0.0.1:3039`와 단일 Chrome을 사용한다. 서비스 워커는 차단하고 각 시나리오는 격리 컨텍스트에서 순차 실행한다. 통상 UI 검사에서는 외부 요청을 막는다. 웹폰트 실제 로딩 검사 1건은 선택한 두 Google Fonts 패밀리의 CSS와 해당 CSS가 가리키는 fonts.gstatic.com 파일만 허용한다. 이때 공개 테스트 문구만 사용한다.

| 번호 | 시나리오 |
| --- | --- |
| 1 | 숫자 정상·오류·빈줄·20자리 정수·0/음수/소수 혼합 → 원본 줄과 부분 성공 수 확인 |
| 2 | 실제 클립보드 TSV·CSV 다운로드 → 오류행 유지, 긴 숫자 보존·스프레드시트 수식 차단 |
| 3 | 100줄 경계·101줄/문자 한도·복사 거부 오류 → 잘못된 성공 표시 없음 |
| 4 | 단일 숫자 URL·빠른 더하기·표기 옵션 회귀 및 일괄 입력 URL 비노출 |
| 5 | 숫자 320px 다크·영어 설정 → 결과 표 내부 스크롤, 페이지 넘침·원시 번역 키 없음 |
| 6 | 글꼴 조합 입력·서로 바꾸기·실제 CSS 복사·명시적 링크 공유 왕복 |
| 7 | 잘못된 URL 값·지원 굵기 보정·복사 실패·기존 즐겨찾기/고정 비교 회귀 |
| 8 | 글꼴 320px 다크·영어 설정 → 조합 조작·긴 본문, 페이지 넘침·원시 번역 키 없음 |
| 9 | 선택 두 웹폰트의 CSS/폰트 실제 응답과 FontFace 로딩 확인 |
| 10 | CSS 200·실제 폰트 파일 차단 → FontFace 오류와 사용자 실패 안내 함께 확인 |
| 11 | Font Loading API 미지원·15초 시간 초과·빠른 재선택 복구 (이 케이스만 API/성공 CSS fixture 사용) |

공통 번역기가 한국어 전용이므로 영어 설정의 기능 유지와 신규 ko/en 키 구조 일치만 확인하며 실제 영어 UI 전환을 주장하지 않는다. 브라우저 JavaScript·hydration 오류, 다운로드, 모바일 스크린샷, 실제 웹폰트 요청을 `browser/`에 남긴다.

## 결과

**11/11 통과**, JavaScript 예외 0·hydration 오류 0. 최종 결과와 실행별 근거는 `browser/final-results.json`에 있다. Chrome은 한 번에 하나만 실행했고 모든 검증 후 닫았다.

- 숫자 5건: 20자리 정수를 그대로 보존하고 원본 줄 번호·오류행·빈줄·부분 성공 수를 확인했다. 100줄은 처리되고 101줄 및 30,000자 초과는 전체 출력을 중단한다. 실제 클립보드 TSV와 다운로드한 BOM CSV에서 오류행·수식 입력의 apostrophe 보호·긴 숫자를 확인했다. 원본 파일은 `browser/number-table.tsv`, `browser/number-to-korean-batch.csv`다. 단일 URL 복원·빠른 더하기·접두어·띄어쓰기 회귀도 통과했다.
- 폰트 6건: 제목/본문 선택·지원 굵기 보정·CSS 실제 복사·폰트/굵기만 서로 바꾸기·공유 URL 왕복·즐겨찾기/고정 비교 재방문을 확인했다. 입력 중 주소창에는 조합 문구가 추가되지 않는다. 기본 진입에서는 패널이 닫혀 있고 pair 전용 CSS 링크가 없으며, 닫기 후 링크가 정리되고 다시 열 때 선택·원고가 유지됐다. `pair=1` 공유 링크는 자동으로 열렸다.
- 실제 폰트 로딩: Noto Serif KR 700, Nanum Gothic 400의 선택 CSS와 해당 CSS가 가리킨 fonts.gstatic.com 파일만 허용했다. 현재 서브셋 CSS가 준비된 뒤 같은 시점의 `document.fonts.load` 결과 두 패밀리가 모두 `loaded`임을 확인했다. CSS/폰트 응답은 모두 200이었다. `browser/font-network.json`, `browser/font-real-webfonts.png`에 증거가 있다.
- 폰트 실패: CSS 응답은 200으로 유지하고 그 CSS의 폰트 파일만 차단했다. 실제 FontFace `error`와 실패 안내가 함께 나타난다. 별도의 API fixture 검사에서는 미지원 안내, 15초 timeout, 빠른 재선택 후 정상 상태 복구가 통과했다. 이 fixture 결과를 실제 웹폰트 로딩 증거로 사용하지 않았다.
- 320px 다크 화면에서 숫자 표는 영역 안에서 가로 스크롤되고 페이지 넘침은 없었다. 폰트는 96px 제목·긴 무공백 본문·CSS 표시까지 페이지 넘침 없이 줄바꿈된다. 패널 및 상단 캡처를 직접 확인했고 기본 접힘 화면은 `browser/font-320-dark-collapsed-top.png`에 있다.

## 발견한 결함과 수정

CSS 링크의 load 이벤트만으로 글꼴 준비 상태를 표시해 실제 폰트 파일 실패 때 경고가 사라지는 제품 결함을 실제 네트워크 차단으로 재현했다. 구현 담당이 CSS 이후 선택 패밀리·적용 굵기·현재 서브셋 문구로 Font Loading API를 확인하고, 실패·미지원·시간 초과 및 오래된 요청 결과를 처리하도록 고쳤다. 같은 실패 조건과 정상 실제 로딩을 다시 실행해 통과했다. 검증 담당은 제품 파일을 변경하지 않았다.

초기 고정 비교 재방문 실패는 검증 코드가 다른 `aria-pressed` 버튼을 준비 신호로 사용한 문제였고 실제 고정/즐겨찾기 버튼을 기다리도록 고쳤다. 초기 실제 폰트 검사는 400ms 서브셋 교체 전후의 서로 다른 FontFace 상태를 두 번 읽어 빈 배열을 받았다. 현재 선택 서브셋 CSS와 같은 polling 시점의 로드 결과를 기록하도록 수정했으며, 최종 증거에는 실제 CSS/폰트 200과 두 패밀리 loaded가 함께 있다.

영어는 공통 한국어 전용 렌더러의 기존 한계를 유지한다. 신규 ko/en 키 구조와 영어 설정의 기능을 검증했으며 영어 UI 전환을 주장하지 않는다. 통상 UI 시나리오의 외부 폰트 실패는 의도한 네트워크 차단 결과이고 실제 글꼴 모양 검증은 위 허용 목록 시나리오에 한정한다. 빌드·배포·전체 타입 검사·개발 서버 재시작·git 작업은 하지 않았다.
