# 40차 실행 계약 — 테트리스 키보드·터치 조작 안정화

> 완료 상태(2026-11-17): 최종 native8/8과08:08:20 KST 전체2GB 타입 exit0·진단0을 확인했다. 구현·독립·공용 검사와 한계는 [최종 보고서](report.md)에 기록했다. 빌드·배포·커밋·푸시 미실행.

## 확인한 문제와 범위

`check-tetris-input-baseline.mjs --record`는 실제 `Tetris.tsx` 키보드·보드·패드 핸들러를 추출해 VM에서 실행했다. 버튼 위 Space가 하드 드롭으로 가로채이고, 종료 화면 링크 위 Enter가 새 게임을 시작하며, 패드에는 키보드 활성화 핸들러가 없고, 다른 포인터의 up이 첫 포인터의 보드 제스처를 종료·회전시킨다. TEXTAREA 제외는 기존대로 정상이다. 원본 SHA와 결과는 `before-fix.json`에 저장했다. 아직 실제 Chrome 재현은 아니다.

기존 창 blur/탭 hidden 자동 일시정지는 이미 있다. 이를 새 기능으로 다시 구현하거나 완료로 세지 않는다. 기본 SRS·7bag·DAS/ARR·홀드·점수·최고 기록·실적·이름 입력·명시 리더보드 제출·게임 공유를 유지한다.

## 개선 계약

1. 전역 게임 키는 입력/선택/편집 영역뿐 아니라 버튼·링크·summary와 명시 interactive role 안에서 발생한 이벤트를 가로채지 않는다. 자식 SVG/아이콘에서 발생한 이벤트도 가장 가까운 실제 컨트롤로 판정한다. defaultPrevented·IME 조합 이벤트는 무시한다. 전역 키는 실제 게임 배경/보드에서 기존대로 동작한다.
2. 패드는 실제 button의 Space/Enter/보조기술 클릭으로 해당 라벨 동작을 한 번 수행한다. 마우스·터치는 기존 누르는 즉시 동작과 연속 이동을 유지한다. pointerdown 뒤 합성 click으로 이중 회전/드롭하지 않도록 소유권을 구분한다. `event.detail===0`만 맹신하는 방식의 보조기술 호환은 실제 브라우저 검사로 확인한다.
3. 누른 이동 상태는 키 코드/포인터 ID 등 입력 소유자별로 추적한다. 한 손가락을 놓아도 같은 방향을 누른 다른 손가락/키 입력은 유지한다. 좌우 동시 입력은 마지막 눌린 방향 우선, 해제 후 아직 눌린 반대쪽으로 전환한다. 반복 keydown은 최초 press를 중복 실행하지 않는다. 실제 게임 동작과 UI 소유권 로직을 분리한다.
4. 보드 제스처는 한 활성 포인터만 소유하고 다른 pointerdown/move/up/cancel은 무시한다. pointer capture 상실은 해당 소유자만 해제한다. 유효하고 0보다 큰 보드 폭에서만 이동 단위를 계산한다. 좌표·시간이 유한하지 않으면 동작을 버린다.
5. pause/start/gameover/hidden/blur/unmount 때 키·포인터·제스처와 이전 작업 세대를 모두 정리한다. pause→resume 후 이전 pointerup, 새 게임 이후 늦은 RAF/팝업 타이머가 새 게임을 조작하지 않게 한다. React Strict effect replay 뒤 첫 시작/버튼/루프는 정상 사용 가능해야 한다. 이미 실행된 엔진 동작을 되돌렸다고 주장하지 않는다.
6. 320px KO/EN에서 버튼 최소 44px·포커스 표시·aria 라벨·상태 안내를 확인한다. 실제 상호작용 설명이 추가되는 경우 구현 담당이 KO/EN fragment까지 작성한다. 공용 canonical/메타데이터는 통합 담당만 수정한다.
7. 로컬 최고 점수/통계/handling 저장 계약, 이름 모달, 게임 성과 기록 시점은 변경하지 않는다. 테스트는 합성 게임·격리 저장소·가짜 네트워크/소리로 진행하고 실제 리더보드에 점수를 제출하지 않는다.

## 검증

- 순수 입력 소유권: 키+터치 혼용/동일 방향 두 포인터/반대 방향 전환/중복 press·release/모든 reset/포인터 ID 불일치.
- 실제 부모: focused 버튼 Space/Enter·링크 Enter·TEXTAREA·contentEditable·SVG 자식·IME/defaultPrevented, 패드 키보드 1회와 touch 1회, Strict replay, pause→resume 늦은up, 새 게임 이전 RAF, 보드0폭 안전성.
- 독립 검토 후 실제 Chrome 키보드 탭 탐색·touch/pointer·모바일 제스처·최고기록/공유 회귀. engine scoring/SRS의 기존 의미는 별도 필요한 회귀만 확인한다.
- 전체 타입은 실행 중인 다른 TS 작업을 동결한 뒤 통합 담당이 수행한다. 빌드·배포·리더보드 실데이터 변경은 하지 않는다.
