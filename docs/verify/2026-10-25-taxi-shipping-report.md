# 택시·택배 검색 표기 및 모바일 개선 검증

- 일자: 2026-10-25 (한국 시간)
- 결과: 로컬 Chromium 브라우저 검사 **18/18 PASS**, 페이지 런타임 오류 0
- 시나리오: [검증 시나리오](2026-10-25-taxi-shipping-scenarios.md)
- 실행: `node scripts/verify-taxi-shipping.mjs` (로컬 `npm run dev` 필요)
- 빌드·배포·커밋은 수행하지 않았다. 검증용 서버는 종료했다.

## 변경 내용

- 택시 제목을 '택시 요금 계산기'로 정리하고, 설명 첫 문장에서 지역·거리 기반 예상 요금을 안내했다. title/description, OG, Twitter, JSON-LD 설명을 같은 상수에서 읽는다.
- 택배의 메뉴·검색·공유·본문 명칭을 '택배비 계산기'로 맞췄다. 집 배송과 편의점 수령 조건을 비교할 수 있다는 점을 설명했다.
- 두 도구의 OG 이미지를 재생성하고 menuConfig의 updatedDate, RSS를 갱신했다.
- 모바일 1열과 grid 자식의 최소 폭을 지정했다. 표 가로 스크롤은 표 영역 안에 한정했다.
- 입력과 주요 선택 버튼을 최소 높이 44px로 조정하고, 택시 시각 선택 칸을 넓혔다. 택배 치수는 한 줄 입력 및 소수점 키패드로 정리했다.
- 첫 화면 결과 바로가기에서 상세 결과로 이동한 뒤 입력으로 돌아올 수 있다. 택배 바로가기에도 서비스 종류를 표시한다.
- 배송 가능한 요금이 없을 때 결과 영역을 유지하고 원인과 다음 행동을 안내한다.
- 공유 URL을 여는 택시 페이지에서 서버 기본 결과와 브라우저 입력이 달라 hydration 오류가 발생하는 것을 재현했다. 두 도구 모두 첫 렌더는 기본값을 유지한 뒤 URL 조건을 한 번 복원하고, 그 이후 URL 동기화를 시작하도록 수정했다. 택시 자동 소요 시간은 입력에서 바로 계산한다.

## 브라우저 결과

| 검사 | 건수 | 결과 |
|---|---:|---|
| 두 도구 × 320·375·390·768·1280px | 10 | 가로 넘침 없음, 입력/선택 버튼 높이 최소 44px |
| 두 도구 × 375px 다크 모드·영어 내비게이션 설정 | 2 | 가로 넘침 없음, 다크 모드 적용 |
| 두 도구 검색 메타데이터·JSON-LD·canonical | 2 | 명칭/설명 일치, canonical 유지 |
| 택시 거리·심야·시외할증·공유 복원·초기화 | 1 | 8,300원 → 21,120원, 공유 URL에서 동일 결과 복원 |
| 택배 상자·4.5kg·제주·편의점·공유 복원·초기화 | 1 | 입력·선택·요금 복원, 기본값 초기화 |
| 320px에서 100kg 배송 제한·입력 재수정 | 1 | 안내·결과 앵커 유지, 정상 무게로 바꾸면 요금 복구 |
| 모든 검사 중 브라우저 pageerror | 1 | 0건 |

모바일 320·375·390px에서 결과 바로가기 하단은 문서 상단 기준 **336px**로 첫 화면 안에 있었다. 768px에서는 324px이며, 1280px에서는 모바일 바로가기가 숨겨진다. 바로가기와 입력 수정 링크를 실제 클릭해 화면 이동도 확인했다.

스크린샷과 기계 판독 결과는 `.next/verify-taxi-shipping/`에 저장된다. 첫 화면, 결과 카드, 배송 제한 안내 및 OG 이미지를 직접 확인했다.

## 범위와 배포 후 비교

모바일 검증은 실제 휴대폰이 아닌 Chromium 뷰포트·터치 에뮬레이션이다. 프로젝트의 기존 도구 번역 레지스트리는 한국어 고정이므로 영어 내비게이션 설정에서 화면이 유지되는 것까지 확인했으며, 도구 전체 영어 지원을 완료했다는 의미는 아니다. 새 문구의 영어 원본은 함께 작성했다.

사용자가 제공한 최근 30일 네이버 TOP 30의 기준값은 택시 관련 검색어 합산 **33,517회 노출 / 109클릭 / CTR 0.33%**, 택배비 계산 **2,052회 노출 / 35클릭 / CTR 1.71%**다. TOP 30에 없는 검색어는 포함하지 않았고 실제 조회 시작·종료일은 화면에 표시되지 않았다.

배포일과 네이버 재수집·보고서 업데이트 기준일을 기록한 뒤 같은 검색어·기기·기간으로 비교한다. 현재 검증은 구현·사용성 검증이며 검색 순위나 CTR 상승을 확인한 것은 아니다.
