## 코드에서 확인한 사용 흐름

`ImageWatermark.tsx`는 텍스트/이미지 워터마크·9개 위치·회전·투명도·타일과 원본 해상도 PNG를 이미 제공한다. 현재 업로드와 드롭은 첫 파일 하나만 사용한다. 두 FileReader와 Image onload에는 오류/취소/새 선택 보호가 없고, reset 뒤 이전 사진이 늦게 다시 표시될 수 있다. 내보내기의 비동기 toBlob도 reset/설정 변경 이후 자동 다운로드를 만들 수 있다. 여러 사진에 같은 문구를 넣으려면 수동 반복이 필요하다.

## 사용자 결과

사진을 최대10개 고르고 같은 워터마크를 명시적으로 일괄 적용한다. 사진별 미리보기와 처리 결과를 보고, 성공한 현재 결과를 개별 PNG 또는 ZIP으로 내려받는다. 기존 한 장 사용도 같은 화면에서 간단히 유지한다. 사진/로고/문구를 기기 기록·URL·서버로 전송하거나 저장하지 않는다.

## 범위

- 파일당8MiB·합계40MiB, 원본16,777,216픽셀 이하를 사전 검사하고 실제 decode 크기도 확인한다. 로고는4MiB·4,194,304픽셀 이하. PNG/JPEG/WebP/GIF의 정지 프레임만 다루며 애니메이션 보존을 약속하지 않는다. 지원하지 않는 형식/깨진 파일은 명시 오류로 남기고 다른 파일을 계속 처리한다. 파일명이나 확장자만으로 이미지라고 판단하지 않는다.
- 파일목록은 File 참조와 안정 ID를 보관한다. 원본 비트맵10개를 항상 메모리에 펼쳐 두지 않는다. 선택 사진 미리보기는 축소 캔버스, 결과는 원래 크기의 PNG이며 둘이 같은 좌표/비율 계산을 사용한다. 기존 텍스트 px·로고 너비 비율·여백·투명도·회전·타일 의미를 바꾸지 않는다. 아주 작은 소스의 타일 간격/반복 횟수도 제한해 무한·과도 반복을 막는다.
- '모두 만들기'에서 현재 문구/로고/설정 snapshot을 잡고 한 파일씩 처리한다. 설정을 편집하는 매 순간10장을 자동 재처리하지 않는다. 만들기 전에는 필요한 입력/로고/색/범위를 검증하고 설명한다. 문구는200자로 제한하고 줄바꿈 처리 규칙을 명시한다. 잘못된 색 입력을 이전 canvas색으로 조용히 대체하지 않는다.
- 중지/계속·실패만 재시도·행 삭제·전체 비우기를 제공한다. 이미 실행된 decode/toBlob을 즉시 중단한다고 주장하지 않고 실제 종료까지 작업 슬롯을 유지한다. row ID+설정 key+작업 세대가 맞는 결과만 반영한다. 새설정/새로고/비우기/언마운트 뒤 늦은 성공은 해제하고 결과를 부활시키지 않는다. 취소는 실패 개수에 넣지 않는다.
- 로고 읽기 실패는 마지막 유효 로고를 유지하고 새로 고른 로고가 적용됐다고 표시하지 않는다. 새소스/로고/reset/언마운트의 늦은 FileReader/decode 결과와 미리보기 URL/비트맵을 정리한다. 출력 누적 Blob은80MiB를 상한으로 두고 초과 시 추가 성공으로 표시하지 않는다. 출력 파일과 미리보기 픽셀은 실제 결과로 검증한다.
- 설정 변경 후 이전 결과는 현재 설정 결과로 반출할 수 없게 한다. ZIP은 클릭 당시 현재 key의 선택된 성공 Blob 참조를 snapshot으로 잡는다. 선택이 없는 경우와 일부 실패가 있는 경우 포함 파일 수를 명확히 표시한다. 중복 이름은 기존 검증된 `imageUniqueNames`를 재사용하고 예약 원본 이름과 충돌하지 않게 한다. Blob참조 ZIP을 사용해 이후 row URL회수가 이미 요청한 ZIP을 깨지 않게 하되 새 ZIP/언마운트 후 옛 자동 다운로드는 막는다.
- 압축용 queue를 워터마크 옵션에 억지로 연결하지 않는다. 반복할 공통 로직이 있으면 작은 새 모듈로 격리하고 기존 압축/변환/리사이즈 호출을 수정할 때만 해당 회귀를 추가한다. 기존 `imageCompress`의 옵션/품질 계산은 바꾸지 않는다.
- 사진 선택·행 이동은 키보드/터치로 가능하게 하고 주요 조작44px·입력16px·모바일1열·디자인 토큰을 적용한다. 실제 워터마크 색 선택은 콘텐츠 색이므로 디자인 토큰 제한과 구분한다. 결과 카드/가이드에서 원본 해상도·PNG·애니메이션 미보존·기기 메모리 상한을 사실대로 설명한다.
