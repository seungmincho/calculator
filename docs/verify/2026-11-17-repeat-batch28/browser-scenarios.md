# 28차 실제 PNG·ZIP 브라우저 준비

35차 실제SW 서버/Chrome은 종료했다. 부모 final ready·최종 번역 생성 뒤 기존3039에서 단일 Chrome으로 시작하며 현재는 실행하지 않는다. 독립 코드 검토는 taxi 담당이라 중복하지 않는다. 소유는 전용 브라우저 mjs·이 문서·browser 산출물이다.

1. **기존 한 장 텍스트 PNG** — 합성 가로/세로/작은/투명 PNG만 사용. 파일 선택만으로 일괄 출력하지 않고 명시 만들기 후 실제 PNG를 다운로드한다. 원래 치수·배경/alpha·워터마크 적용 픽셀을 독립 PNG reader로 확인한다. 글꼴 raster의 완전 동일성은 주장하지 않는다.
2. **투명 로고9위치·preview 좌표** — 작은 비대칭 반투명 로고와 큰 원본을 사용해9위치의 bounding box/여백·너비 비율을 독립 기하값과 비교한다. preview의 축소 배율을 적용한 영역과 원본 PNG 영역이 대응하는지 확인한다. 회전/불투명도/작은 타일의 적용·유한 완료를 포함한다.
3. **여러 장·부분 선택 ZIP** — 서로 다른 픽셀/치수의 파일과 중복 이름을 올린다. 개별 PNG와 실제 ZIP의 엔트리 이름·개수·고유 이미지·CRC를 검증하고 선택한 성공만 포함되는지 확인한다. 같은 행의 전체/부분 반출 이름 안정성을 확인한다.
4. **깨짐·한도·로고 실패** — 형식은 실제 header로 검사하는지,8MiB/합40MiB/10개·16MP/로고4MP 거부와 다른 정상 행 진행을 확인한다. 실제 거대한 비트맵 대신 잘못된 치수를 가진 header fixture를 사용한다. 로고 오류 뒤 마지막 유효 로고를 유지하고 늦은 교체가 새 선택을 덮지 않는지 확인한다.
5. **실제 작업 슬롯·pause/resume·retry** — native File.arrayBuffer/decode/toBlob의 실제 결과를 만든 뒤 callback 전달만 보류한다. pause는 실패가 아니며 진행 슬롯은 원 작업 settle 전 열리지 않는다. 일시적 decode 실패 행만 재시도하고 성공 행은 재처리하지 않는지 확인한다. 제어 지연과 실제 이미지 계산을 보고서에서 구분한다.
6. **편집/reset/삭제/이탈·늦은 PNG** — 실행 중 문구/로고/설정 변경·행 삭제·전체 비우기·SPA unmount 후 늦은 callback을 전달한다. 예전 결과 부활/잘못된 current 반출/추가 자동 다운로드0, URL/bitmap 정리를 확인한다.
7. **ZIP snapshot·늦은 다운로드** — 실제 PNG Blob ZIP을 클릭한 뒤 선택/행 변경으로 기존 참조를 회수해도 클릭 당시 ZIP은 온전하다. 새 ZIP/이탈 후 이전 완료는 자동 다운로드0이며 물리 ZIP busy 정책을 확인한다.
8. **320px KO/EN·키보드** — 선택 행/preview/문구를 유지한 언어 전환,16px·44px·overflow0·키보드 행 선택과 부분 반출. 합성 사진/로고/문구가 storage/URL/network로 가지 않는지 확인한다.

대용량80MiB accounting은 기존 독립 포트 검사와 분리하며 Chrome에서 의미 없이80MiB를 할당하지 않는다. 실제 사람 사진/카메라/마이크/외부 다운로드는 사용하지 않는다. 원본 이미지 alpha/결과PNG/ZIPCRC 검증을 화면을 봤다는 주장과 혼동하지 않는다. 필요한 실제 PNG·부분패널 캡처만 보존하고 마지막 Chrome 종료 뒤 통합 담당에게 알린다.
