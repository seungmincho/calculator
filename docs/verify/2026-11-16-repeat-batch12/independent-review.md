# 12차 독립 코드·도메인 검토

검토 담당: writing_versions. 제품 파일은 수정하지 않으며, 구현 담당의 ready 통지 뒤 정적 검토와 작은 순수 로직 검사를 진행한다. 실제 브라우저 검증은 별도 담당이 수행한다.

## 판정

7일 메뉴 계획과 전사문 묶음 내보내기의 코드·도메인 독립 검토를 완료했다. 이 범위에서 재현 가능한 high/medium 결함을 발견하지 않았다. 실제 브라우저 결과와 전체 타입 검사는 각 전담자의 결과를 따른다.

오늘 참석자는 taxi_repeat 담당의 [별도 독립 검토](attendance-independent-review.md)로 분리했다. 이 문서의 통과 수에는 참석자 검토를 포함하지 않는다.

## 우선 확인할 경계

### 앞으로 먹을 7일 계획

- 현지 날짜·윤일·주 경계를 따르며, 저장하지 않은 편집과 다른 주의 저장 날짜를 구분한다.
- 빈 날 채우기는 후보를 중복 제거하고 이미 사용한 메뉴를 제외한다. 후보 부족을 숨겨 반복 메뉴로 채우지 않는다.
- 명시적 저장은 최대 90개 날짜·메뉴 80자·중복 날짜·원본 비교를 검사하고, 다른 주 날짜를 보존한다.
- 미래 계획을 먹은 기록에 추가하지 않으며, 과거/오늘 추가에서도 실제 기록 저장 성공과 날짜·메뉴 중복 여부를 확인한다.
- 복사/TXT·삭제·저장 실패가 룰렛 결과와 기존 먹은 기록을 바꾸지 않아야 한다.

### 전사문 묶음 내보내기

- 최대 20개·개별 12,000자·합계 240,000자를 검사하고, 선택 전체가 유효하지 않으면 일부만 내보내지 않는다.
- 현재 편집 중인 전사문과 제목·현지 녹음 시각·길이를 포함하고, 화면과 같은 최신순으로 정렬한다.
- 검색 결과 전체 선택/해제는 검색 밖 선택을 숨겨서 없애지 않으며, 삭제·본문 비우기 후 선택의 유효성을 확인한다.
- 기존 busy 정책, 다운로드 실패 안내, 오디오 Blob·원본 저장의 비간섭을 확인한다.

## 독립 실행 증거

```text
node docs/verify/2026-11-16-repeat-batch12/check-independent-domain.ts
Independent menu/voice review: 12 groups passed
```

메뉴 계획 7그룹에서는 2000~2200년의 모든 월말 시작일 2,411개가 정확한 7일을 만드는지, 허용 범위를 넘는 마지막 주를 거부하는지 확인했다. 겹치는 주의 같은 날짜 초안과 다른 주 초안 보존, NFKC/대소문자 후보 중복 제거, 90개 한도에서 제거·수정·추가 순서 독립성, 미래 버전·손상·quota 원본 보존, 먹은 기록의 미래/중복 구분, 현재 초안으로 만든 7일 TXT를 검사했다.

음성 5그룹에서는 선택 순서 24개 순열 모두 같은 최신순/동일 시각의 화면순을 내보내는지 확인했다. 삭제·빈 전사·초과 길이·중복 ID는 전체 내보내기를 거부하며, 현재 편집 텍스트의 공백/줄바꿈/Unicode와 제목·길이가 보존된다. Blob getter에 접근하지 않는 점, 20×12,000자 정확 최대치, 개수 초과 거부, 녹음 시각의 실제 기기 UTC offset도 확인했다.

## 통합 코드 확인

- `MealPlanPanel`은 날짜별 draft map을 사용하고 명시적 저장에서 변경 날짜만 기존 entries에 합친다. 저장 성공 전 draft를 지우지 않으며 quota와 원본 충돌에서 입력을 남긴다. 저장은 별도 계획 키를 사용하고 룰렛 결과/먹은 기록 콜백을 호출하지 않는다.
- 명시적 먹은 기록 추가는 현지 오늘 이하·중복 검사를 거치고 기존 `onAddMeal`의 boolean 성공을 기다린다. 부모 persistMeals는 실제 원본 raw를 비교하고 readback 뒤에만 성공을 반환한다. 새 기록과 별도로 계획 내용은 유지된다.
- 전사문 선택은 부모가 보관한다. 검색 밖 선택 수와 유효하지 않은 선택을 표시하며, 내려받기 직전 전체 선택을 다시 검사한다. 현재 transcript 상태를 전달하므로 기기에 저장하기 전 편집 내용도 사용한다.
- 전사문 패널과 체크박스는 기존 녹음/전사/저장 busy를 따른다. 선택/다운로드는 오디오 Blob 또는 기존 기기 저장 API를 호출하지 않는다. Blob/anchor 생성·클릭 실패는 오류로 표시하며 성공 메시지를 먼저 만들지 않는다.

## 범위와 한계

브라우저의 실제 다운로드, 검색/선택/편집 상호작용, 모바일 레이아웃은 브라우저 전담 검증에 남겼다. Chrome·전체 tsc·빌드·배포·커밋은 실행하지 않았다. Web Locks 없는 저장 fallback의 완전한 동시 탭 원자성 한계는 그대로다. 의도적으로 입력한 같은 메뉴는 여러 날짜에 저장할 수 있으며, 자동 빈 날 채우기에만 해당 주 중복 방지가 적용된다.
