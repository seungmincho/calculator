# 45차 실행 계약 — 저장한 글꼴 조합 백업·선택 가져오기

상태: 로컬 구현·자체22·독립14그룹·실제 Chrome7/7·공용 검증과08:43:20 KST 전체2GB 타입 첫 실행을 통과해 완료했다. 빌드·배포·커밋·푸시는 하지 않았다. [최종 보고서](report.md).

## 기존 상태와 목적

`FontPairProfiles.tsx`와 `fontPairProfiles.ts`는 key `toolhub:font-pair:profiles`, version1, 최대6개·이름40자·정규화 이름 중복검사·CAS/WebLocks·현재 제목/본문을 보존하는 스타일 적용을 제공한다. `FontPairPreview.tsx`의 조합 CSS/URL과 글꼴 실제 로딩도 이미 있다. 프로필 목록 자체를 파일로 옮겨 다른 브라우저에서 복원하는 기능은 없다.

## 구현 계약

- 정상 저장 조합만 명시적으로 JSON 백업한다. app/version/exportedAt/profiles wrapper와 기존 styles(title/body의 fontId/size/weight)를 사용한다. 원고·미리보기 제목/본문·업로드한 로컬 글꼴 파일/임의 CSS URL은 포함하지 않는다. 새 서버나 계정 동기화는 없다.
- 입력 파일은 처음부터 쓰지 않고 검증한 목록·이름·요청 스타일의 미리보기를 보여 준다. 사용자가 가져올 항목을 선택하고 각 이름을 고쳐서 추가한다. 기존6개를 자동 삭제/전체 덮어쓰지 않는다. 정상 중복/빈 이름/유니코드 정규화 중복/잔여 슬롯 부족은 행별로 설명한다.
- fontId는 현재 catalog의 허용 ID만 받는다. 모르는 글꼴/미래 버전을 기본 글꼴로 몰래 치환하거나 일부만 성공한 척하지 않는다. 파일 원문은 보존하고 목록에 표시한 문제를 해결할 수 없으면 적용하지 않는다. 실제 적용 굵기가 catalog에서 가까운 값으로 바뀌는 기존 정책은 요청 굵기와 구분해 표시한다.
- 선택한 항목은 새 ID로 한 번에 추가한다. 잠금 안에서 읽은 현재 raw와 preview basis가 다르면 멈추고 다시 확인하게 한다. 여섯 슬롯 상한과 이름 충돌을 lock callback 안에서 다시 확인한다. 저장 후 읽기 확인 실패는 성공으로 표시하지 않고 이전 raw로 rollback하지 않는다.
- 늦은 File.text/read 거절·새 파일/같은 파일 재선택·탭 이동·unmount·초기값 복원을 세대로 구분한다. 파일을 읽는 동안 저장 목록이 바뀌면 preview를 새 basis에 자동 적용하지 않는다. 취소는 원고·현재 선택 스타일·저장 목록을 바꾸지 않는다.
- 파일 용량 보호 제안은64KiB다. 구현 전에 기존 최대6개와 이름·ID·한글/escape·pretty wrapper의 자체 백업 최대값을 합성으로 측정해 정확 왕복을 확인한다. 기존 localStorage parser의20,000 UTF-16 한도를 새 파일 상한과 혼동하지 않는다.
- 화면은 기존 프로필 구역에 작은 백업/가져오기 버튼과 선택 목록으로 추가한다. 가져오기는 저장 목록만 바꾸고 현재 미리보기/원고에 자동 적용하지 않는다.320 KO/EN에서 행 이름/선택/오류/확정 버튼을 모두 사용할 수 있어야 한다.

## 파일과 검증

제품 담당이 FontPairProfiles와 신규 fontPairBackup/child, KO/EN fragment를 같이 소유한다. 기존 profile writer를 확장할 경우 이전 add/delete 회귀·잠금 안 CAS/확인 의미를 유지한다. canonical/가이드/메타/updatedDate·생성물은 통합 담당만 쓴다.

순수 왕복은 정상 최대6개/요청굵기·문자열 특수값/원고·로컬파일 제외/미래버전·미지글꼴·중복/슬롯 경계를 검사한다. 독립 검토는 새 ID 생성·선택/이름 편집/preview 후 외부 변경·unknown write·같은 파일·늦은 읽기를 확인한다. 실제 Chrome은 다운로드 JSON→다른 격리 탭 가져오기→기존 원고 보존→명시 적용 후 실제 두 글꼴 로딩, 취소/320 KOEN/키보드 초점을 확인한다. 관련14차 회귀·범위lint·번역·전체타입 뒤에만 완료다.

사용 빈도는 현재 코드와 기존 사용자 요청을 근거로 정한 후보 우선순위이며 새 분석 데이터로 검증한 순위가 아니다.

## 읽기 준비 측정

`measure-backup.mjs`로 현재 catalog의 가장 긴 fontId,80자ID,40 UTF-16 이름(JSON escape가 필요한 unpaired surrogate39개+고유숫자)을 넣은 합성6개가 기존 parser를 통과하는지 확인했다. 기존 저장 JSON2,912bytes, 제안 pretty wrapper3,913bytes이며 정확 profiles 왕복을 확인했다. 제안64KiB는 이 자체 반출보다 크다. 원문 공백을 임의로 늘린 모든 JSON 파일의 최대값을 보장하는 측정은 아니다. 실제 사용자 저장소/원고/글꼴 파일은 읽지 않았다. 측정 당시 JS lint0/0만 확인했으며 제품 백업 API·브라우저 검증은 진행 전이었다. 이후 구현·검증 결과는 상단 완료 상태와 최종 보고서에 기록했다. 수치는 [측정 JSON](backup-size-measurement.json)에 보존한다.
