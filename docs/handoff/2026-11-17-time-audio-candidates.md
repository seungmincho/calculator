# 후속 후보 — 미팅 시간을 캘린더로·집중 소리 재사용

2026-11-17 KST. 26차 다음의 기존 도구 후보 조사다. 제품 코드 수정은 없다.

## 세계 시계의 선택 시간 보존과 일정 파일

`WorldClock.tsx`에는 도시 저장·미팅 시간대 표·텍스트/링크 공유가 이미 있다. 그러나 공유 `at`를 읽을 때 현지 시간의 시(hour)만 `sel`에 보관하므로 분이 사라지고, 일광절약 전환일에는 시간대 표의 인덱스와 현지 hour도 다를 수 있다. `daySlots()`는 항상24칸이며 현재 grid도24열로 고정돼 있다. 이 상태에서 ICS만 추가하면 잘못 복원된 시간이 일정으로 반출된다.

현재 유틸과 부모의 복원식을 그대로 적용한 Node 읽기 검사:

- 서울 `2026-11-19T03:30:00Z` → `03:00:00Z`, 30분 손실.
- 뉴욕 `2026-11-01T06:30:00Z` → `05:00:00Z`, 90분 손실.

이 검사는 계산 경로 재현이며 실제 브라우저 URL 재현 완료로 주장하지 않는다. 미팅의 기준은 UTC 순간으로 보존하고, 도시별 표시·복사·공유와 일정 파일이 그 순간 하나를 사용하게 만드는 것이 우선이다. 제목과30/60/90/120분 길이를 선택해 로컬 ICS를 다운로드하면 일정 앱으로 옮길 수 있다. 외부 캘린더 계정 조작/참석자 초대/알람 전송은 없다.

## 백색소음의 실제 종료 시간과 내 설정

`WhiteNoise.tsx`는6종 합성 소리·음량·5~60분 타이머가 있다. 타이머는 interval 호출마다1초를 빼며, 재생 중 타이머 버튼을 바꿔도 이미 실행 중인 타이머에는 적용되지 않는다. 반대로 소리 종류를 바꾸면 `startNoise()`가 기존 타이머를 처음부터 재시작한다. 사용자에게 선택 시간과 실제 종료 시간의 관계가 명확하지 않다. 설정 저장도 없다.

우선 실제 종료 기준을 두고 남은 시간을 계산하도록 바꾸며, 재생 중 종류/음량 변경은 같은 종료 시각을 유지한다. 타이머 변경은 ‘지금부터 N분’으로 명시한다. 원하는 사람은 마지막30초 천천히 줄이기를 켜고, 자주 쓰는 종류·음량·타이머·페이드 설정을 이름 붙여6개 저장해 불러온다. 방문/불러오기만으로 소리가 나지 않는다. ‘수면 치료’ 같은 새 효능 주장은 추가하지 않는다.

기술 참고는 [RFC 5545 VEVENT](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.6.1)와 [W3C Web Audio의 예약된 소스 종료](https://www.w3.org/TR/2021/REC-webaudio-20210617/#dom-audioscheduledsourcenode-stop)다. 일반 JS 타이머만으로 모바일 OS의 백그라운드 실행을 보장할 수 없으므로 오디오 예약과 복귀 시 보정을 함께 검토하고 실제 검증 범위를 명시한다.
