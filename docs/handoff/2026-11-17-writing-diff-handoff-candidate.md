# 글자수 저장 버전 → 줄 단위 비교 연결 후보

2026-11-17 KST. 현재 21~23차가 우선이고, 24차 후보 뒤에 검토할 읽기 전용 조사다. 구현하지 않았다.

`WritingVersionsPanel.tsx`는 저장한 글과 현재 탭 원문을 나란히 보여 주고 글자 수 차이를 계산한다. 실제 어느 줄이 추가/삭제됐는지 비교하는 흐름은 없다. 19차 `TextDiffWorkspace`는 이미 Worker 줄 비교·200행 페이지·복사 복구·TXT·취소를 제공하므로 다른 비교 엔진을 만들 필요가 없다.

추천안은 저장 버전 영역의 명시적 ‘줄 단위로 비교’에서 저장본/현재본 두 snapshot을 새 텍스트 비교 탭으로 전달하는 것이다. 기존 글자수 세기 탭과 저장 버전은 변경하지 않는다. 사용자가 편집을 이어갈 수 있도록 대상은 클릭 시점 snapshot임을 표시한다. 현재 저장 목록이 충돌/손상 상태라면 최신 저장본처럼 전달하지 않는다.

`textHandoff.ts`의 메모→읽어주기는 새 about:blank 탭의 sessionStorage 쓰기/읽기 확인, opener 제거, 대상 경로 replace, 실패 시 새 탭 닫기, 원문 URL 제외 패턴을 이미 갖는다. 이를 참고하되 기존 OCR/TTS v1 key와 payload를 확장해서 다른 흐름을 깨지 말고 두 문서용 별도 제한 있는 payload/key를 둔다. 50,000자까지의 기존 저장본은 Diff의1MiB 한도 안이지만 줄수/DP 한도는 별도로 적용한다.

받는 쪽은 명시된 source일 때 유효한 만료 전 payload를 한 번 읽고, 사용자가 문서 두 개를 확인해 ‘비교’를 눌러야 Worker를 실행한다. malformed/expired/없음/이미 소비된 링크에서는 기본 도구를 계속 사용할 수 있게 한다. 지우기 전 원래 읽은 raw와 같음을 확인해 새 전달을 삭제하지 않는다. 원문을 query/hash/localStorage/로그/서버에 넣지 않는다.

팝업 또는 sessionStorage가 차단되면 원본 탭을 이동하거나 입력을 교체하지 않고 실패와 수동 대안을 제공한다. 대상 초기 복원이 늦게 도착해 사용자가 이미 고친 Diff 입력을 덮지 않도록 첫 복원/사용자 편집 세대를 구분한다. 대상 locale 변경도 재소비·재적용하지 않는다. 원문이 빈 저장본/현재본도 비교에서는 유효하므로 OCR의 비어 있지 않은 텍스트 조건을 그대로 재사용하지 않는다.

검증은 양쪽 실제 text equality, 현재/저장 원문·원본 raw bytes 불변, 팝업/저장 차단과 새 탭 정리, 만료/미지원/역순 전달/새 값 삭제 방지, 사용자가 대상에서 편집하기 시작한 뒤 재적용 금지, 실제 Worker/TXT, 기존 OCR/Notepad→TTS 회귀와320px다. 글자수 차이와 실제 줄 비교라는 두 사용자 동작을 구분해 기존 비교를 없애지 않는다.
