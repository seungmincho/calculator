## 1. 수능 점수 기록과 변경 비교

**이미 있는 것.** [CsatGrade.tsx](../../src/components/CsatGrade.tsx)의 `sel`·`scores` 상태와 URL 동기화는 선택과목/원점수/단일 최저 조건을 재현한다. 과목별 등급, 추정 표준점수·백분위, 등급 평균과 공유도 있다. 현재 컴포넌트에는 localStorage 기반 점수 목록이나 이전 입력 비교가 없다. 조사 시점 근거는 상태 52–76행, URL 동기화 82–92행, 결과 계산 94–105행이다.

**빠진 흐름.** 사용자가 첫 가채점 입력을 남기고 일부 답안을 수정한 뒤 무엇이 바뀌었는지 비교하거나, 지난 모의고사 입력을 다시 가져오는 흐름이다. 현재는 링크를 별도로 보관하고 화면을 번갈아 열어야 한다.

**최소 범위.** 최대 8개, 이름 40자의 명시적 저장·이름 변경·삭제·수동 불러오기. 저장 대상은 과목 선택, 입력 점수, 저장 시각과 계산 자료 식별자/버전이다. 현재 입력과 선택한 기록 하나의 원점수 차이를 표시한다. 같은 과목·같은 자료 기준일 때만 등급/최저합 변화도 비교한다. 과목이 바뀌면 같은 척도처럼 증감을 표시하지 않는다. 자료 버전이 바뀐 기록은 원점수를 유지하고 결과 비교 제한을 알리며, 원래 기록을 조용히 다시 계산해 덮지 않는다. 공유 링크로 들어온 점수를 저장 목록에 자동 추가하거나 기존 기록에 덮어쓰지 않는다.

공식 성적표 기록이나 합격 예측으로 표현하지 않는다. 현재 상대평가 결과가 기존 자료 기반 추정이라는 15차 표현을 저장 목록·비교에도 유지한다. 긴 추세 차트, 전체 기록 백업, 새 점수 기준 추가는 첫 범위에서 제외한다.

**소유 파일 제안.** 기존 `src/components/CsatGrade.tsx`의 입력 연결, 신규 `src/components/CsatScoreRecords.tsx`, `src/utils/csatScoreRecords.ts`, `scripts/check-csat-score-records.ts`. ko/en은 기존 `csatGrade` 아래 전용 키를 제품 담당자가 조각으로 작성하고 공용 담당자가 병합한다. `src/utils/csatGrade.ts` 계산식은 유지한다.

**검증.** 점수 0/최댓값, 과목 변경, 절대평가와 상대평가 구분, 자료 버전 불일치, 빈 입력의 0점 오인, URL로 받은 값과 저장 원본의 분리, 삭제 후 현재 입력 보존을 검사한다. 저장 손상/미지원 버전/quota/다중 탭 충돌과 320px에서 목록·비교·복원 동작을 확인한다.

## 2. 내신 시험/학기별 입력 저장과 복원

**이미 있는 것.** [GradeCalculator.tsx](../../src/components/GradeCalculator.tsx)는 입학년도와 5/9등급제, 여러 과목의 단위·석차·동석차·수강자수, 가중 평균과 등급 경계를 계산한다. `encodeRows`/`decodeRows`와 URL 복원·동기화(35–85행)가 있고 공유도 있다. 이름 붙인 시험/학기 목록이나 로컬 입력 저장은 없다. [gradeRank.ts](../../src/utils/gradeRank.ts)의 기존 계산은 그대로 재사용할 수 있다.

**빠진 흐름.** 이번 시험을 저장한 뒤 다음 시험의 과목 구성을 재사용하거나, 이전 시험 입력으로 돌아오는 흐름이다. URL은 전체 입력을 재현하지만 도구 안에서 기록을 고르고 다시 사용하는 목록은 제공하지 않는다.

**최소 범위.** 최대 10개, 이름 40자의 입력 스냅샷 저장·이름 변경·삭제·수동 복원과 선택한 두 기록 비교. 입학년도, 선택 등급제, 과목별 원본 입력 필드를 보존한다. 입력 중인 빈 행도 보관하되 계산 불가 행을 정상 결과로 취급하지 않는다. 동일 과목명이 여러 행에 있더라도 자동 합치지 않는다. 복원 시 UI 행 ID를 새로 부여하고 선택한 과목 포인터를 정리한다. 기존 화면을 교체한다는 안내를 제공한다.

두 기록의 등급제·입학년도·가중 평균·유효 과목 수·단위 합계를 나란히 보여 준다. 같은 등급제이고 양쪽 평균이 있을 때만 중립적인 수치 차이를 표시하며, 서로 다른 5/9등급은 평균 차이를 계산하거나 좋고 나쁨으로 판정하지 않는다. 여러 학기의 공식 누적 내신, 학교별 반영 비율, 과목 이름만으로 대응시키는 자동 비교는 추가하지 않는다.

**소유 파일 제안.** 기존 `src/components/GradeCalculator.tsx`, 신규 `src/components/GradeSavedRecords.tsx`, `src/utils/gradeSavedRecords.ts`, `scripts/check-grade-saved-records.ts`. 번역은 기존 `gradeCalc` 아래. 기존 `src/utils/gradeRank.ts`와 `scripts/check-grade-rank.ts`는 계산 회귀 근거로 사용한다.

**검증.** 5/9등급제와 입학년도 각각의 왕복, 동석차와 가중 단위 보존, 빈/잘못된 입력 행, 같은 이름의 여러 과목, 저장 한도, 복원 이후 행 추가/삭제와 선택 상태를 검사한다. 비교할 두 기록의 삭제/다중 탭 갱신, 다른 등급제 비교 제한, 유효 과목이 없는 기록을 확인한다. 구버전 URL 및 공유 입력을 보존하고 저장 손상/미지원 버전/quota/다중 탭 충돌을 확인한다. 모바일에서 입력과 저장 목록의 가로 넘침·키보드 동작도 검사한다.

### 16차 내신 기록 준비 계약 — 최종 실행 범위로 갱신

소유자는 `team_rotation`이다. root의 16차 계약 후 순수 저장 도메인·검사·자식 UI를 준비한다. 기존 부모 연결은 15차 최종 검사 종료 신호 이후다. CsatGrade 두 후보는 `gpa_scenarios`가 연속 소유한다.

- **보존:** `gradeOf`, `boundaries`, `weightedAverage`, `systemForYear` 계산을 바꾸지 않는다. 현재 과목 입력·동석차 처리·등급 경계·공유와 구형 URL 복원을 유지한다.
- **저장:** 최대 8개, 기록 이름 1–40자. 버전 있는 별도 저장소에 ID·이름·저장 시각·입학년도·5/9등급제·과목 원본 필드를 저장한다. 렌더링용 행 ID나 파생 결과를 원본으로 저장하지 않는다. 삭제는 현재 폼을 건드리지 않는다. 목록 선택만으로 복원하거나 자동 저장하지 않는다. 이름 변경은 최초 범위에서 제외한다.
- **필드 검증:** 알려진 필드만 투영하고 배열 개수·문자열 길이·중복 ID·등급제·입학년도·숫자 필드 형태를 검증한다. 빈 입력과 잘못된 학업 입력을 보관할 수 있는 구조 검증/계산 유효성 검증을 구분한다. 저장 용량 한도는 명시하고 초과 시 폼을 보존한 채 실패한다. 현재 UI는 과목 추가 개수와 과목명 길이를 제한하지 않고 URL 복원만 30행/이름 30자로 자르므로, 신규 저장 한도를 기존 UI 한도라고 잘못 간주하거나 자동 절단하지 않는다. 제안 저장 한도는 30행/과목명 80자/숫자 원문 32자로 두고 16차 계약에서 확정한다.
- **초기 진입:** URL 입력 복원이 우선이며 로컬 저장 목록을 읽어도 폼에 자동 적용하지 않는다. URL이 없는 진입도 현재 예시/기본 동작을 유지한다. 저장 데이터 읽기 실패가 현재 입력이나 결과를 가리지 않는다.
- **복원:** '현재 입력을 이 기록으로 바꾸기'라는 명시적 동작으로만 실행한다. 확인/취소를 제공하고 취소 시 변화가 없어야 한다. 복원 후 행 ID는 새로 만들고 선택 포인터를 정리한다. 기존 URL 동기화가 복원한 입력을 반영하도록 한다.
- **요약:** 저장 항목에 등급제·유효 과목 수·단위 합계를 표시한다. 비교 표와 과목 대응은 최초 범위에서 제외한다. 서로 다른 5/9등급제를 수치 차이로 평가하지 않는다.
- **쓰기 실패/다중 탭:** Web Locks, 원본 CAS, readback을 적용한다. 손상·미지원 버전은 덮지 않고 quota/접근 불가/충돌은 별도 안내한다. 실패 시 성공 안내나 임시 목록 갱신을 하지 않는다. storage 이벤트에서는 충돌을 알리고 명시적으로 목록을 다시 읽게 하며 현재 폼을 보존한다. 쓰기 후 확인 실패는 이미 반영됐을 수 있음을 안내한다. 잠금 미지원 환경의 완전 원자성 한계를 기록한다.
- **검증 순서:** 순수 파서/저장·삭제/왕복/오류 주입과 기존 `check-grade-rank.ts` → 범위 lint → 별도 담당 단일 브라우저의 저장·재방문·링크 우선·복원 취소/승인·다중 탭·320px 검사 → 통합 담당 전체 타입 검사. 빌드·커밋·배포는 실행하지 않는다.

## 3. 수능최저 단순 조건을 여러 개 유지하고 비교

**이미 있는 것.** CsatGrade의 `minN`·`minSum`은 단일 목표를 갖는다. 동시에 `sums = [2, 3, 4]...`로 2·3·4개 영역의 최상위 합을 이미 모두 표시하므로, 이를 다시 만드는 것은 중복이다. 현재 [csatGrade.ts](../../src/utils/csatGrade.ts)의 `bestSum`(133–135행)은 국어·수학·영어·탐구 상위 1과목 중 상위 n개를 고른다. 한국사 별도 조건, 필수 영역, 탐구 두 과목 평균을 적용하는 대학별 조건 엔진은 아니다.

**빠진 흐름.** 사용자가 여러 목표 이름과 임계값을 유지하고, 점수를 고칠 때 조건별 충족 여부를 한 화면에서 확인하는 흐름이다. 현재는 한 임계값을 교체해야 한다.

**최소 범위.** 최대 6개, 이름 40자의 사용자 조건을 추가·수정·삭제하고 나란히 비교한다. 한 조건은 이름, 영역 수 2/3/4, 등급 합 상한으로 제한한다. 기존 `bestSum`만 사용하고 현재 공통 계산 범위를 표 위에서 설명한다. 각 행에 현재 합, 사용자가 입력한 상한, 충족/부족을 보여 준다. 조건 저장은 명시적으로 실행하고 점수 기록과는 분리한다. 대학 이름을 적더라도 도구가 확인한 입시요강으로 표시하지 않는다. 기존 단일 조건 URL과 공유는 유지하며 새 조건 목록은 첫 범위에서 URL에 자동 포함하지 않는다.

필수 과목, 한국사 제한, 탐구 반영 방식 등 실제 모집요강별 차이는 첫 범위에서 지원하지 않는다. UI는 '입력한 단순 조건 충족'이라고 표현하고 대학 지원 가능·합격으로 결론 내리지 않는다. 현재 계산 범위와 다른 조건을 가진 사용자에게는 이 비교를 적용할 수 없음을 분명히 알린다.

**소유 파일 제안.** 후보 1과 같은 담당자가 `src/components/CsatGrade.tsx`를 이어 소유. 신규 `src/components/CsatMinimumConditions.tsx`, `src/utils/csatMinimumConditions.ts`, `scripts/check-csat-minimum-conditions.ts`. 기존 `csatGrade` 번역 아래 조각 작성. 계산 엔진 변경 없음.

**검증.** 동일 점수에서 2합/3합/4합 결과, 상한과 같은 경우, 1등급 차이 부족, 탐구 상위 1과목 선택, 한국사 점수 변경이 기존 합에 영향을 주지 않는 계약을 확인한다. 입력 점수 변경 시 모든 조건이 즉시 재계산되는지, 조건 CRUD가 점수·기존 URL을 바꾸지 않는지 검사한다. 저장 보호와 모바일 긴 이름 줄바꿈도 확인한다.

## 공통 실행 조건

새 저장소는 버전·개수·문자열 길이·필드 구조를 검증하고 손상/미지원 원본을 덮지 않는다. Web Locks 지원 시 직렬화하고, 미지원 시 원본 비교·쓰기 후 확인과 한계를 유지한다. 기존 GPA/JSONPath/명단 저장 보호 패턴을 참고하되 관련 없는 도구 저장소를 공유하지 않는다.

ko/en 키는 제품 담당자가 함께 작성하고 통합 담당자가 원본에 병합한다. 신규 유틸·자식 파일을 먼저 준비한 뒤 기존 부모 import를 연결한다. 의미 있는 도메인 검사와 범위 lint 이후 단일 브라우저 검증·전체 타입 검사를 순차 진행한다. 디자인 토큰, 입력 16px, 터치 44px, 320px, 기존 공유 동작을 완료 조건에 넣는다.

이 메모의 검증은 코드와 완료 문서 대조까지다. 실제 브라우저에서 확인한 기능 동작이나 새로운 회귀 검사 통과로 해석하지 않는다.
