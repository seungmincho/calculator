# 이미지 압축 작업 제어 후보

2026-11-17 KST. 기존 `/image-compressor/` 코드 조사에 근거한 후속 후보이며 아직 구현하지 않았다. 현재 19차 검증과 20·21차 큐가 우선이다. 실제 방문 통계 순위는 아니다.

## 사용자 문제와 이미 있는 기능

여러 장을 압축하다가 잠시 멈추거나 실패한 사진만 다시 처리할 방법이 없다. 현재 자동 처리는 설정 키 또는 파일 개수가 바뀔 때 시작된다. 같은 설정으로 실패한 항목은 키가 같으므로 파일을 다시 넣거나 설정을 바꾸지 않으면 다시 시도하지 않는다.

`src/components/ImageCompressor.tsx`에는 이미 여러 파일 업로드/붙여넣기, 순차 압축, 품질·목표 용량, 제출/메일/블로그/SNS 프리셋, 크기 제한, 개별 다운로드·ZIP, 전후 비교가 있다. 따라서 일괄 압축이나 프리셋을 다시 만드는 후보는 제외한다.

현재 effect의 세대 검사는 이전 결과 반영을 막지만 이미 진행 중인 `compressFile`의 목표 용량 반복을 중지하지 않는다. 설정을 빨리 바꾸면 이전 작업과 다음 작업이 겹칠 수 있다. ZIP은 시작 시점 결과를 잡고 비동기로 생성하며 오류 안내나 그동안의 입력 변경을 구분하는 정책이 없다. 이는 코드 경로 조사 결과이며 아직 실제 브라우저 재현 결과는 아니다.

## 권장 최소 범위

현재 자동 처리 방식을 유지하면서 **일시정지·계속 처리·실패 항목 재시도**를 추가한다. 완료된 현재 설정 결과는 재사용하고, 설정 변경 시에는 이전 설정 결과를 새 설정의 완료 결과처럼 반출하지 않는다. 원본 파일은 메모리에만 둔다. 저장 프리셋이나 서버 처리는 추가하지 않는다.

- 단일 작업 실행기를 두어 설정 변경/새 파일/재시도가 실제 압축 실행을 중첩하지 않게 한다. 대기열의 항목은 내부 id로 구분하고 중복 파일명은 유지한다.
- 일시정지는 다음 인코딩 단계와 다음 파일로 넘어가지 않게 한다. 이미 시작한 브라우저 이미지 디코딩/인코딩 자체가 즉시 멈춘다고 약속하지 않는다. 늦게 반환된 취소 결과와 object URL을 정리한다.
- `compressFile`에 선택적 취소 신호를 전달해 디코딩 후, 각 인코딩 전후, 목표 용량 반복 사이에서 확인한다. 취소를 일반 오류 항목이나 압축 성공으로 표시하지 않는다. `fitToSize`의 품질/축소 계산 규칙과 포맷·회전·투명도 처리는 유지한다.
- 실패 재시도는 명시적으로 선택한 실패 항목만 현재 설정으로 처리한다. 성공한 다른 사진을 불필요하게 재처리하지 않는다. 일시정지 중 새 파일을 추가하거나 설정을 변경해도 자동으로 재개하지 않는다.
- 전체 삭제/개별 삭제/설정 변경/언마운트와 완료가 경합해도 삭제한 사진이 되살아나거나 오래된 완료 수가 남지 않게 한다.
- ZIP은 사용자가 눌렀을 때의 파일 목록과 설정을 명시한 고정 결과로 생성하는 안을 우선 검토한다. 도중 목록을 바꿔도 원본 결과 Blob을 안정적으로 사용하고 생성 실패는 현재 화면에 설명한다. 새 ZIP 요청 또는 언마운트 뒤 오래된 다운로드는 실행하지 않는다. 개별/ZIP 파일명 충돌 정책도 실제 추출로 확인한다.

## 검증과 완료 조건

1. 실제 JPEG/PNG 픽셀로 기존 품질·목표 크기·투명 JPEG 변환·회전·전후 비교 회귀를 검사한다. 기본 알고리즘 단위 검사는 기존 `scripts/check-image-compress.ts`를 재사용한다.
2. 제어 가능한 비동기 포트에서 중간 일시정지, 취소 직후 새 설정, 실패 재시도, 삭제, 언마운트 순서를 검사하고 실제 압축 동시 실행 수가 1인지 확인한다.
3. 완료 항목 재사용과 실패만 재시도, 일시정지 중 추가/설정 변경, 실제 ZIP 내용·중복 이름·도중 입력 변경·ZIP 실패를 확인한다. 취소 후 모든 자원이 즉시 반환된다는 과장 없이 해제 가능한 자원과 실행 중 API 한계를 기록한다.
4. 입력/버튼 16px/44px, 320px, 키보드, KO/EN, 범위 lint·독립 검토·단일 실제 브라우저 후 전체 타입 검사를 마친다.

관련 파일은 `src/components/ImageCompressor.tsx`, `src/utils/imageCompress.ts`, 신규 작업 제어 유틸/테스트다. 다른 도구도 가져오는 이미지 유틸의 호출부를 먼저 확인하고 기본 API 호환성을 유지한다. 공유 메시지/메타/생성물은 통합 담당에게 조각을 전달한다. 빌드·배포·커밋·푸시는 실행하지 않는다.

호출부 추가 확인: `imageResize.ts`는 decode/fitToSize를, `imageConvert.ts`는 decode/outputName을 재사용한다. ImageResizer·ImageConverter·PdfTools는 `uniqueNames`를 사용한다. 현재 이름 함수는 입력 `a.jpg`, `a (2).jpg`, `a.jpg`에서 만들어 낸 이름과 원래 이름의 충돌을 피하지 않으므로 고정 ZIP 스냅샷 검증에 이 조합도 포함한다. 공유 유틸을 수정하면 이 호출부의 기존 회귀를 함께 확인하고 새 압축 제어 기능이 다른 도구의 자동 처리 방식을 바꾸지 않게 한다.

이 이름 충돌은 현행 유틸을 Node strip-types로 직접 호출해 재현했다: 출력이 `a.jpg`, `a (2).jpg`, `a (2).jpg`였고 대소문자를 무시한 고유성 검사 결과는 false였다. 이 결과는 파일명 함수만 확인한 것이며 실제 ZIP 추출 손실까지 재현했다고 해석하지 않는다.
