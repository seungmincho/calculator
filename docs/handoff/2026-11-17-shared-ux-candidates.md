# 후속 공용 사용성 후보 — 코드 조사

2026-11-17 KST. 15~17차 제품 작업과 별도로 root가 확인한 후보이며 아직 구현하지 않았다.

## 언어 선택과 실제 본문 언어 일치

`src/components/LanguageToggle.tsx`는 한국어/English를 선택하고 `LanguageContext`를 바꾼다. 그러나 `src/lib/i18n.ts`의 공용/도구 레지스트리는 한국어 생성물만 읽으며 주석에도 다국어 복원이 향후 과제로 적혀 있다. 그래서 헤더/탐색은 English인데 도구 본문은 한국어로 남을 수 있다. 15차 모바일 캡처에서도 이 조합을 확인했다.

실행 전 검토할 최소 범위:

- 선택한 언어가 기존 `useTranslations` 본문에도 반영되게 한다. 전체 번역 JSON을 모든 페이지에 넣지 않고 기존 네임스페이스별 분할을 유지한다.
- 정적 HTML과 첫 클라이언트 렌더는 같은 한국어를 사용하고 초기화 뒤 저장 언어를 적용한다. 페이지 전체 Suspense나 본문 숨김을 추가하지 않는다.
- 영어 미존재/로드 실패에는 한국어 내용으로 복구하며 원시 키나 배열 타입 오류를 만들지 않는다. 신규 도구 로딩, 새로고침, 언어 왕복, HMR을 확인한다.
- 언어 전환 때문에 입력한 점수·원고·저장 목록이 초기화되지 않아야 한다. 번역 함수의 참조 안정성과 기존 effect 의존성 영향을 독립 검토한다.
- `LanguageContext.tsx`의 저장소 읽기/쓰기는 현재 예외 보호와 ko/en 값 검증이 없다. 저장이 차단되어도 화면에서 언어를 바꿀 수 있게 한다.
- 새 영어 URL·canonical·영어 SEO 구축으로 범위를 확대하지 않는다. 현재 한국어 메타데이터 정책과 별도 문제다.

공용 영향이 크므로 16~17차가 끝난 안정된 체크포인트에서 단독 묶음으로 검토한다. 초기 SSR 본문·한국어 기본 요청량·영어 선택 시 지연 로드·이미 입력한 폼 보존·여러 도구를 이동한 결과를 검증한 뒤 완료로 판정한다. 전체 저장소의 기존 번역 오류를 모두 고쳤다고 과장하지 않는다.

## 다른 검토 후보

- `/lunar-converter/`의 기념일 입력에 이름을 붙여 재사용하기. 현재 단일 변환/11개년 표가 있고 17차 ICS가 예정되어 있으므로, 달력 내보내기를 다시 만들지 않고 입력 저장이 필요한지 검토한다.
- 수능 성적표의 등급을 직접 넣는 흐름. 현재 도구는 원점수 기반 전년도 추정이므로 12월 성적 통지 뒤 실제 등급을 사용하는 입력 방식은 별도 후보가 될 수 있다. 16차 원점수 기록의 데이터 기준과 섞이지 않도록 먼저 계약을 설계한다.
