# 후속 후보 — 문서 비교와 마크다운 반출

2026-11-17 KST. root가 현재 코드를 읽고 확인한 후보이며 구현/브라우저 재현 완료를 뜻하지 않는다. 앞선 완료 목록에는 두 도구의 아래 기능이 없다. 18차 공용 번역 복원 체크포인트 이후 기존 도구 개선 범위에서 진행할 후보이다.

## 1. 텍스트 비교의 응답성과 결과 활용

`src/components/DiffViewer.tsx`는 LCS의 `(왼쪽 줄 수+1) × (오른쪽 줄 수+1)` 이중 배열을 메인 스레드에서 계산한다. 입력 길이/작업량 상한이 없고 한 번 비교하면 `showDiff=true`인 동안 매 입력마다 다시 계산한다. 큰 문서에서 화면을 막을 수 있는 경로이다. 실제 성능 수치나 브라우저 멈춤은 아직 측정하지 않았다.

다음 최소안:

- 비교 시점의 두 원문을 명시적으로 확정하고, 편집 중에는 결과가 이전 입력 기준임을 알려 재비교하게 한다. 비교 중 취소·새 입력·좌우 교체 후 늦게 도착한 결과를 무시한다.
- 계산을 별도 Worker로 옮기고 입력 크기·줄 수·LCS 작업량의 명시적 상한을 둔다. 공통 앞/뒤 구간 제거로 작은 수정이 있는 큰 문서를 줄인다. 상한 초과를 비교 성공/변경 없음으로 표시하지 않는다.
- 기존 전체 결과와 줄 번호를 유지하면서 ‘변경된 줄만’ 보기와 텍스트 파일 내보내기를 제공한다. 원문에 HTML이 있어도 텍스트로 표시한다.
- 기존 복사는 `execCommand` 반환값을 확인하지 않는 경로가 있다. 실패 시 선택 가능한 결과 텍스트를 제공하고 실제 성공만 성공으로 안내한다.
- 서버/계정/원문 자동저장은 추가하지 않는다. 실제 Worker·취소·큰 동일문서·상한초과·한글/줄바꿈·320px·다운로드 내용 검증으로 완료를 판단한다.

## 2. 마크다운 복사 실패 복구와 파일 읽기 경합

`src/components/MarkdownEditor.tsx`는 원고 자동저장, 서식/Markdown/HTML 복사, 파일 열기·이미지 붙여넣기, md/html 다운로드를 이미 제공한다. `copyText`와 `copyRich`는 Clipboard 예외 또는 `execCommand(false)` 뒤에도 `flash`를 호출한다. `FileReader` 기반 파일 로딩은 읽는 동안 입력이 바뀌거나 더 늦게 선택한 파일이 먼저 완료될 수 있는지 별도 검토가 필요하다.

다음 최소안:

- 복사 실패 시 거짓 성공을 없애고 현재 Markdown/HTML 텍스트를 수동으로 선택하는 복구 영역을 제공한다. 서식 복사는 성공한 형식과 plain-text 대안을 구분한다.
- 복사 요청 중 원고 변경/다른 복사/언마운트가 발생하면 이전 원고의 성공 안내나 복구 텍스트를 새 결과처럼 표시하지 않는다.
- 텍스트 파일 읽기 크기·오류·취소를 검증하고, 늦은 FileReader가 그동안 편집한 원고를 덮지 않도록 계약을 정한 뒤 적용한다. 기존 자동저장/다운로드/이미지 삽입은 유지한다.
- 서식 렌더러 교체, 실시간 협업, 문서 클라우드 저장, 새 경로는 이번 범위에 넣지 않는다.

두 후보의 우선순위는 확인한 코드 경로에 근거한 판단이며 실제 방문 통계 순위가 아니다. 구체 한도와 UI는 구현 전 별도 실행 계약에 기록한다.
