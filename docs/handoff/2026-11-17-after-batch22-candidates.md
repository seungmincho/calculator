# 22차 다음 기존 도구 후보

2026-11-17 KST. 읽기 전용 코드 조사에 따른 후속 후보이며 구현/실제 브라우저 검증은 아직 실행하지 않았다. 20·21·22차 확정 큐가 우선이다. 신규 경로나 서버는 필요하지 않다.

## 타자 연습 — 내가 고른 글로 연습

현재 `TypingTest.tsx`는 오늘의 문장·짧은 글·긴 글·시간제, KO/EN, 오타 자모 분석, 최근 기록과 일일 연속 기록을 제공한다. 지문은 `typingTest.ts`의 고정 목록만 사용한다. 사용자가 업무 문장이나 공부할 내용을 넣는 흐름은 없다.

권장 최소안은 명시적 ‘내 글 연습’이다. 지문 작성칸과 실제 타자 입력칸을 구분하고, 적용 전 정규화 미리보기와 길이 검사를 거친 확정 지문으로 연습한다. 작성 중 원문을 고쳐도 진행 중 지문/시간을 바꾸지 않고 ‘이 글로 시작’에서만 교체한다. 다른 모드로 이동·언어 전환 시 작성 초안은 보존한다. 지문은 해당 방문의 메모리만 사용하고 URL/공유/최근 기록에 원문을 넣지 않는다.

초기 제한안은 10~1,000 코드포인트다. 줄바꿈/탭은 공백으로 바꾸고 반복 공백 정리 여부를 적용 전에 보여 준다. 실제 타자 입력은 기존 줄바꿈 금지/붙여넣기 금지와 일치해야 한다. 조합문자/한글 IME는 기존 `diffTyped`의 코드포인트·두벌식 규칙을 따른다. 다양한 언어의 타수 정확성을 새로 보장하지 않는다.

사용자 지문 결과는 난도가 다르므로 기존 오늘의 문장·최고 기록·일일 횟수에 자동 합산하지 않는 별도 세션 연습으로 두는 안을 권한다. 기존 4모드/기록 형식을 변경하지 않는 자식 작업공간과, 기존 엔진을 공유하되 상태만 분리하는 대안을 착수 때 비교한다. 같은 화면에 결과 공유가 있다면 사용자 지문을 포함한 링크처럼 보이지 않게 구분하고, 복사는 실제 성공/실패를 판정한다.

검증은 지문 편집/적용/모드 왕복, KO 조합/영문·빈/과대/줄바꿈, 끝 글자 확정, 시작/재시작의 타이머 1개, 모바일 입력, 원문 무전송·URL/기록 불변, 기존 오늘의 문장과 계산 회귀다. `TypingTest.tsx`의 현재 copyText는 Clipboard 실패 뒤에도 copied를 설정하므로 새 흐름에 재사용하지 않는다.

## 화면 녹화 — 다시 찍기 중 이전 결과 보존

현재 `ScreenRecorder.tsx`에는 화면/시스템음/마이크 선택, 품질/FPS, 일시정지/계속, 미리보기와 WebM 다운로드가 있다. 짜르기나 오디오 편집을 새로 만드는 것보다 현재 결과를 잃지 않는 다시 찍기와 명확한 실패 처리가 우선이다.

코드상 `newRecording`은 이전 object URL과 chunk를 즉시 없애고, `startRecording`도 기존 URL을 먼저 폐기한다. 그다음 화면 선택을 취소하거나 마이크/인코더가 실패했을 때 이전 결과로 돌아갈 흐름은 없다. 녹화 준비 상태도 없어 권한 대기 중 중복 클릭이 가능하다. 이것은 코드 경로 확인이며 실제 권한창을 조작해 재현한 것은 아니다.

권장안은 마지막 성공 결과 1개를 메모리에 유지하면서 새 녹화를 준비하고, 새 결과가 유효하게 완료됐을 때만 교체하는 것이다. 별도 ‘결과 지우기’는 명시적으로 제공한다. 준비 중 중복 시작·취소/다른 작업·언마운트 후 늦게 허용된 MediaStream을 정리하고 녹화를 시작하지 않는다. 실패 시 이전 결과를 계속 다운로드할 수 있고 선택한 마이크를 확보하지 못했다면 실제 포함된 오디오를 구분해 안내한다.

연관 자원 문제: 현재 mergeAudioStreams의 AudioContext는 ref로 보관·close하지 않고, unmount effect는 초기 recordedUrl을 캡처한다. 녹화·정지·실패·재시작·언마운트 경로에서 실제 활성 stream/합성 출력 트랙/context/URL/타이머 소유권을 정리하는 계약이 필요하다. 단순 UI 추가로 이 경로를 복제하지 않는다.

실제 OS 화면 선택/마이크 권한창을 자동으로 검증했다고 과장하지 않는다. 제어 가능한 media 포트로 늦은 허용/거부/중복/오류 경합을 검증하고, 실제 canvas captureStream→MediaRecorder→다운로드 재생으로 녹화 파일을 검증하는 방식을 우선 검토한다. 사용자 개인 화면/마이크를 임의로 캡처하지 않는다. 모바일에서 getDisplayMedia를 지원한다고 새로 약속하지 않으며 미지원 안내와 320px UI만 구분한다.

두 후보 모두 실제 수요 순위는 가설이다. 현재 실행 큐 완료 후 최소 계약과 소유 파일/검증을 확정한 항목만 착수한다.
