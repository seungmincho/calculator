# 도구 탐색의 불필요한 초기 미리 읽기 줄이기

## 근거와 변경

번역 데이터 분리 이후 HTML에 연결된 초기 JS는 줄었지만, 실제 브라우저에서는 카테고리로 가는 링크를 자동으로 미리 읽으며 기존 도구의 큰 번역 청크까지 요청했다. 유류비 화면의 PC 브라우저에서 16개, 모바일에서 8개의 미리 읽기 요청이 확인됐다. 요청한 JS 중에는 디코딩 크기 2,323,389바이트의 기존 도구 번역 청크가 포함됐다.

Header·Breadcrumb·HomePage의 Next 링크에 `prefetch={false}`를 적용했다. 링크 클릭 후 이동과 도구 코드 로드는 그대로 작동한다. PWA 캐시는 v4.31.3으로 갱신한다.

## 같은 조건의 브라우저 측정

이전 성능 커밋의 정적 export와 변경 후 export를 각각 빈 저장소의 Chromium으로 읽고, 유류비 페이지 최초 진입에서 실제로 요청한 JS 응답 본문을 합산했다. 두 빌드는 같은 브라우저·날짜·유류비 API 모의값을 사용했다. gzip은 받은 JS 본문을 로컬에서 개별 압축한 추정값이다. 브라우저 전송 바이트나 실제 사용자 지표는 측정하지 않았다.

| 조건 | JS 전 | JS 후 | gzip 추정 전 | gzip 추정 후 | 미리 읽기 전→후 |
| --- | ---: | ---: | ---: | ---: | ---: |
| PC 밝은 화면 | 3,779,154 | 1,410,314 | 1,123,424 | 396,385 | 16→0 |
| 390px 모바일 다크 화면 | 3,751,229 | 1,410,314 | 1,115,453 | 396,385 | 8→0 |
| 미리 읽기를 지원하지 않는 브라우저 대조군 | 1,410,170 | 1,410,314 | 396,364 | 396,385 | 0→0 |

일반 브라우저의 최초 요청 JS는 PC 62.68%, 모바일 62.40% 감소했다. 차트 두 개는 원래대로 첫 화면의 계산 결과에 표시되며, 250km로 변경한 뒤 원형 차트 비율과 27,586원 툴팁 값이 변경 전과 같다. 카테고리·홈 카드·PC 및 모바일 헤더를 실제 클릭했을 때 해당 경로로 이동했고, 선택한 카테고리의 도구 코드는 그때 요청됐다.

추가 확인: 6페이지 × PC/모바일의 제목·본문·언어 상태·검색 이동 12건, 번역 원본 대조 11,301건, 관련 계산·API·모의 수집기 테스트 7개가 통과했다. 타입 검사와 756페이지 정적 빌드도 통과했다. 변경 파일 lint는 기존 3 errors / 3 warnings와 같고 새 오류는 없다. 전체 lint에는 기존 오류 550개와 경고 457개가 남아 있다.

서비스워커 갱신과 운영 페이지의 실제 링크 이동은 운영 배포 후 별도로 확인한다.
